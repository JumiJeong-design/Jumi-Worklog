## 회고

- "최신으로 배포해줘"를 곧이곧대로 실행하지 않고 **두 개(피그마↔깃 정합 vs npm publish)로 갈라** 먼저 상태를 읽은 게 맞았다. 막힌 원인은 디자인 드리프트가 아니라 "안 하기로 해둔 방침"이었고, 되돌리기 어려운 npm publish를 임의로 안 건드린 채 git 브랜치로 우회해 개발자를 즉시 언블록했다. "된다"고 말하기 전에 임시 프로젝트에서 실제 설치까지 돌려 측정했다.
- 세션 한도로 멀티에이전트가 전부 튕겼지만 감사에 필요한 데이터(Figma variant 매트릭스)는 이미 로컬에 확보돼 있어서, 팬아웃을 고집하지 않고 **직접 순차 대조로 완주**했다. 도구가 막혔다고 작업이 막히는 건 아니었다.
- 도넛 리포트를 손으로 재현한 건 **중복이자 품질 저하**였다. 완성 룩은 Figma가 본이고 Storybook은 인터랙션·모션 검증이라는 우리 역할 분담을 어기니, 이미 잘 만든 Verdict Bar Motion을 두고 새로 대충 그리는 일이 벌어졌다. 지적을 받고 정교한 기존 컴포넌트를 도착지로 연결하는 쪽으로 되돌렸다.
- 로컬 dev(HMR)에서 멀쩡하던 스토리가 프로덕션 빌드에서 깨졌다. 원인은 **스토리 파일 간 import**였고, 공용 코드를 비-스토리 모듈로 빼서 풀었다. 이후엔 `pnpm build`로 dev/prod 차이를 미리 잡기로 하고, 커밋 누락(`verdictBarMotionEngine.ts` untracked)도 "깃=스토리북" 점검에서 잡아 CI가 깨지기 전에 복구했다.
- "스와이프가 안 먹는다"를 코드 탓으로 돌리지 않고 측정했더니 로직은 정상, **6초 데모값이 짧았던 것**이었다. 원인을 코드가 아닌 파라미터에서 찾아 18초로 고쳤다.
- 스펙을 처음 읽고 P0 블로커 3개를 올렸는데 셋 다 오진이었다. 특히 **29일 된 유즈케이스 메모("사실상 Claude 중심")를 최신 스펙 위에 올린 게 잘못** — 스펙이 우선이고 모델 수는 기획서 3모델이 캐논이다. 대기투표 정책 공백도 "블로커"가 아니라 디자인이 먼저 가고 기획이 따라오는, 지금 만드는 중인 영역이었다. 파생·오래된 메모로 캐논을 덮어쓰지 말 것.

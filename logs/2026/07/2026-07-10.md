### 함정 모음 / 인사이트

- **off-scale = "스타일은 있는데 변수가 없는" 드리프트** — `display/1`(56px)은 사이즈 램프 최대(48=7xl)를 넘어 붙을 변수가 없었다. 2026-07-02 fontSize 바인딩이 "값 정확매칭만" 규칙이라 이걸 남겨둔 건 그 작업 스코프상 맞지만, **상류의 스케일 구멍(변수 미신설)은 별개의 드리프트.** variable-first면 스타일 생성 시 8xl 변수가 있었어야 함(주미님 지적).
- **read-only 감사가 문서 이름 오차를 잡음** — 문서엔 `display/1`·`body/xs`로 적혀 있었으나 실제 스타일명은 `display/1-sb`·`display/1-r`·`body/xs-r`·`body/xs-m`. 라이브 감사 없이 이름으로 바인딩했으면 실패. (`display/2·3·4`는 이미 5xl/6xl/7xl에 바인딩됨을 확인.)
- **add-as-earned** — "12~20을 전부 채우자"와 "쓰는 것만 넣자"는 지금 결과가 같음(빠진 건 13 하나뿐이고 실제로 쓰임). 밀도 철학(dense vs sparse)은 미래의 투기적 스텝에서만 갈리므로 그때 결정. 진짜 가드레일은 primitive 밀도가 아니라 **역할 스타일 층**.
- **컬러도 동일 구조** — 70개 중 52개가 색을 primitive 직접 바인딩(semantic 층 빈약)이라 타이포 palette와 같은 병. **섞지 말고 별도 패스**로 분리(plan-17).

## 타이포 off-scale 제품 스타일 — 변수 신설·바인딩

Figma `Socra Design system test`(`DcYgJjGAfObOIM4IyrQjgj`) `typography` 컬렉션(`5:2`, 모드 KR/JP). read-only 감사 → write → 재검증 순서. 전부 **픽셀 변화 0**.

- **감사** — 사이즈 변수 램프는 `2xs 11 … 7xl 48`(15단), **56·13 둘 다 부재**. fontSize 미바인딩 15개 중 제품 스타일은 4개(`display/1-sb`·`display/1-r`=56, `body/xs-r`·`body/xs-m`=13), 나머지 11개는 `foundation/*` 문서용(9/10/13/21/25px).
- **write** — `font/size/8xl`(=56, `VariableID:3455:2`)·`font/size/13`(=13, `VariableID:3455:3`) 신설(scope=FONT_SIZE, KR/JP 동일값). `display/1-sb`·`display/1-r`→8xl, `body/xs-r`·`body/xs-m`→13 바인딩.
- **검증** — 미바인딩 15→11개, **비-foundation fontSize 미바인딩 0**(제품 타이포 전부 바인딩 완결), 4개 resolved 56/13 그대로.
- **foundation 11개 제외(주미님 결정)** — 제품 미노출 문서 라벨이라 제품 사이즈 스케일에 넣으면 "안 쓰는 9/10/25px"가 스케일을 오염 → 미바인딩 유지.
- **코드 미러** — `design-system/tokens/tokens.json` `font.size`에 `13`·`8xl` 추가. 단 이 파일은 **design-source 참조**(패키지 빌드 입력 `primitive.tokens.json` 아님) → 런타임/theme.css **무영향**. 패키지 승격은 plan-14 반응형과 조율 후 별건.
- **문서** — `docs/plans/15-typography-variable-binding-2026-07.md` 미결 항목("body/xs 13px 결정") 해결로 갱신. 롤백 = 4스타일 `setBoundVariable('fontSize', null)` + 변수 2개 삭제 + tokens.json 2줄 제거.

## 컬러 semantic 정합 — 별도 바운디드 패스로 분리 (plan-17 신설)

타이포 palette 밀도와 **동일 구조의 병**(primitive 직접 바인딩 만연 vs semantic 층 빈약)이지만 섞으면 둘 다 커져 별도 작업으로 분리(주미님 "따로 기록").

- **`docs/plans/17-color-semantic-token-consolidation-2026-07.md` 신설(백로그·미착수 스코핑)** — 근거는 2026-07-02 전수 스캔(메모리 `project_semantic_token_drift`).
- **진단 요약** — 70개 계약 컴포넌트 중 52개가 색을 primitive 램프에 직접 바인딩. 역할 불일치: 흰 표면 `neutral/white`×85(→다크에서 검정, 치명적)·본문 `neutral/900·black` 혼용·에러/반전/보더 semantic 미사용. 공백 토큰 = status **success/info/warning**, `surface-inverse`.
- **단계** — Phase 1 공백 토큰 신설 → Phase 2 역할별 primitive→semantic 재바인딩(다크 치명적 흰표면·본문텍스트 우선) → Phase 3 컴포넌트 통합.
- **원칙** — foundation-first · add-as-earned · 자동 일괄치환 금지 · write 게이트 준수. 착수 전 스캔값(6일+ 경과) 라이브 재확인.

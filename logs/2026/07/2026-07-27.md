## 한 일

**전송 시각·날짜 구분선 — 기획서에 답이 있었다.** 버블에 전송 시각을 노출할지, 날짜 구분선을 둘지 논의로 시작했다. 처음엔 "AI 챗은 타임스탬프를 안 다는 게 관습"이라 봤는데, 기획서 v1.0.3에 이미 결정이 박혀 있었다 — 사용자 질문 버블에만 시각 표시, AI 답변엔 없음, 날짜 구분선은 두지 않음(각 메시지가 자기 날짜를 달아 자정 걸침 문제를 없앰). 그대로 채택했다. DS `Message Bubble`(247:183) Human 3개 variant에 숨어 있던 Footer를 노출하고, "오후 3:45"(12시간제) → "5분 전" 상대시간으로 바꾸고, 기획서에 없는 "전송됨"은 뺐다. AI variant는 손대지 않았다. 노출하는 순간 인스턴스의 옛 FILL override와 일본어 잔재("午後3時45分") 때문에 레이아웃이 무너져서 그것부터 잡았다.

**질문 버블 확장 — 긴 텍스트 접힘 + 시각을 버블 밖으로.** 5줄 초과 접힘(더보기)과 파일 첨부 variant를 추가했다. 처음엔 시각을 버블 안, 접힘을 `…` 말줄임으로 잡았는데 주미님이 둘 다 뒤집었다 — 시각은 버블 밖(메타 정보라 위계가 섞이면 안 됨), 접힘은 페이드 그래디언트(아래로 이어진다는 신호라 더보기와 짝). 시각을 버블 형제로 빼고, 접힘은 래퍼를 고정 높이로 잡아 클리핑 + 그래디언트로 다시 만들었다. 페이드 색은 변수 바인딩이 안 돼서(스톱에 변수를 걸면 알파가 1로 죽음) 버블 색상값을 직접 박았다.

**첨부 표현을 세 번 갈아엎음.** 이날의 본체. 이미지를 어떻게 보여줄지를 놓고 방향이 계속 바뀌었다. ① 버블 안 카드 → ② full-bleed(버블 패딩을 자식으로 옮겨 사진이 가장자리까지, WhatsApp식) + `Attachment/Media` 그리드(1·2·3·4+, 4장↑ 2×2에 `+N`) → ③ 최종적으로 "메신저 관습 폐기, 이미지·문서 모두 같은 칩(높이 56)으로 버블 밖, 한 줄 wrap". 마지막 전환의 근거가 이날 가장 중요한 판단이었다 — Socra의 도메인(투자·커리어·부동산·대인관계)에서 첨부 사진은 대부분 '사진으로 찍은 문서'(오퍼레터·급여명세서·계약서)라 감상 대상이 아니라 참고 자료이고, 그걸 읽는 주체도 사용자가 아니라 AI다. 그래서 크게 볼 이유가 없고, 답변이 긴 제품 특성상 240 이미지 블록은 대화를 계속 밀어낸다. 기획서가 이미지를 10장까지 허용한 것도 감상용이 아니라 "여러 페이지를 찍으니까"로 다시 읽었다. 전환 과정에서 `Attachment/Media` 그리드·`+N` 오버레이·이미지 뷰어 진입 규칙 고민이 통째로 사라졌고, 첨부 순서도 텍스트 위(Claude·ChatGPT·WhatsApp 관례)로 뒤집었다.

**첨부 컴포넌트 패밀리 재편.** 결과물로 컴포넌트가 여러 개 갈렸다. `Attachment/File`(3575:1480) 문서 6종 Type(PDF·DOC·HWP·TXT·XLS·PPT, 기획서 §182 그대로), `Attachment/Chip`(3578:1732) 입력창용 Type(Image/File)×State(default/processing/error) — 에러 칩은 스크림+경고 아이콘으로 재디자인하고 사유는 `Error reason` 텍스트 프로퍼티·다시 시도는 불리언으로. 전송 후용 `Attachment/Sent`(3613:1578), 버블용 첨부 행 `Attachment/Group`(3623:1569, Image 01~10 + File 불리언), 입력창용 `Attachment/ComposerGroup`(3625:1657, 한 줄 가로 스크롤)을 새로 만들고, 폐기된 `Attachment/Media`(3593:1731)는 지웠다. 첨부 아이콘 18개는 `stroke/width/icon-thin` 토큰으로 바인딩했다.

**Chat Input Bar 상태 + Mode Toggle 비활성.** `Chat Input Bar`(29:2) 2line에 `max`(5줄 내부 스크롤)·`limit-near`(2,400자~ 카운터 빨강)·`limit-over`(2,500자 초과 전송 비활성)를 추가했다(기획서 §181). 첨부만 있는 `Content=Image`(첨부만 전송) variant는 기획서가 텍스트 2글자 필수(§181·§562, 빈 입력 포함 비활성)라 도달 불가라서 삭제하고, `image-attached` 상태를 `attached`로 바꿔 이미지·파일·혼합을 한 상태에서 다루게 했다. `Mode Toggle`엔 `State` 축을 추가해 Deep Off/On의 disabled variant를 넣었다(기획서 §190: 생성 중엔 전송과 모드 토글 비활성).

**Product 파일에 케이스 화면 조립 + 라이브러리 퍼블리시 씨름.** 기준 화면(6196:117614) 옆으로 첨부 조합 5종·접힘·입력창 글자수 3종·입력창 첨부 3종·입력창 상태값 7종·첨부 처리 중/실패(6262:47021·47029)를 실제 DS 인스턴스로 깔았다. 여기서 반나절 발목을 잡은 게 라이브러리 문제였다 — PageUI의 `Message Bubble`이 DS 라이브러리가 아니라 이름만 같고 키가 다른 로컬 복사본(로컬 `083bc73a…` vs DS `d4e2a91b…`)이라 새 variant가 안 잡혔다. 퍼블리시는 주미님만 할 수 있어 여러 번 왕복했고, 결국 DS 키로 컴포넌트를 직접 임포트해 새 케이스를 붙이는 우회로 진행했다.

## 남은 것

세션 마지막 기준(자정 넘겨 이어감), 다음 날로 넘긴 것:

- 첨부 바텀시트(`+` 눌렀을 때 사진/파일 선택)와 미지원 형식 토스트 — 컴포넌트는 있는데 화면이 비어 있음.
- `loading`(전송 중) 상태에서도 Mode Toggle을 죽일지 — 지금은 `disabled`만 막힘.
- 이날 DS에서 마지막에 바꾼 것들(Mode Toggle 비활성, `ComposerGroup` 한 줄 처리, `loading` 토글)이 아직 Product로 퍼블리시 안 됨 → 정합 필요.
- 기존 PageUI 화면들은 여전히 로컬 복사본 `Message Bubble`을 봄 → 라이브러리 인스턴스로 교체 정리(기존 화면 건드리는 일이라 미착수).
- 남은 결함/부채: 접힘 variant는 디태치본이라 `_TextBubble` 업데이트를 안 따라옴, 페이드 그래디언트 변수 바인딩 불가, HWP·TXT 아이콘이 `lucide:file`로 동일.

## 회고

- 기획서(문서)와 주미님이 Figma에 직접 써둔 화면 Description을 섞어 읽어 두 번 헛짚었다. "기획 내용대로"를 문서로 읽고 뒤졌는데 실제로는 Figma 가이드였고, 주미님이 작업 중인 화면을 완성품으로 단정해 "다 있다"고 보고했다. 둘 다 원본을 잘못 지목한 실수였다.
- 이미지 표현에서 메신저 관습(full-bleed)을 먼저 이식했다가 제품 맥락에 안 맞아 되돌렸다. 대가가 컸다 — 이미지가 버블 폭을 정하니 min/max·반응형 그리드를 만들어야 했고, 같은 사진 3장이 질문 길이에 따라 240~330으로 변하는 이상한 상태까지 갔다. "첨부는 텍스트에 종속되지 않는 참고 자료"라는 성격을 먼저 못 박았으면 왕복이 줄었을 것이다.
- 접힘을 근거로 "첨부는 버블 안 소속"이라고 논증했는데, 그 규칙("접으면 첨부 숨김")이 요구하는 건 같은 메시지 소속이지 같은 버블 배경이 아니었다. 내 근거가 틀린 걸 스스로 짚어 첨부를 버블 밖으로 뺐다.
- 라이브러리 퍼블리시/로컬 복사본 키 충돌로 시간을 많이 썼다. 퍼블리시는 사용자만 할 수 있고, 로컬 복사본은 이름이 같아도 다른 컴포넌트라 자동으로 안 풀린다는 걸 확인한 뒤 DS 키 직접 임포트로 우회했다.
- 기획서와 어긋나는 결정 세 개(접힘 5줄→10줄, 접혀도 첨부 유지, 첨부만 전송 허용 여부)는 Notion 정본을 건드리지 않고 Figma 가이드에만 변경 제안으로 남겨 PM 판단 몫으로 넘겼다. "기획서 원문은 절대 건들지 말라"는 지시대로, 마크다운 미러도 손대지 않았다.

- **공유 워킹트리에서 생성 토큰 파일은 남의 변경을 같이 물고 온다.** `component.tokens.json`·`theme.css`·`public.manifest.json`에 내 토스트 gap 추가와 옆 세션의 `attachment-scrim-error` 제거가 섞여 있었다. 격리 worktree(main 기준)에서 **소스 편집만 다시 하고 거기서 `token:build`로 재생성**하니 diff가 내 두 줄로 떨어졌다. 생성물은 patch로 옮기지 말고 재생성한다.
- **파일을 통째로 복사해 격리 브랜치에 옮기면 남의 커밋 내용이 딸려 온다 — 그리고 `git diff`로는 안 보인다.** 공유 워킹트리에서 `packages/prism/src/index.ts`가 "내 변경만"인 걸 `git diff`로 확인하고 격리 worktree(main 기준)로 복사했는데, **CI가 `Cannot find module './components/EdgeBand.tsx'`로 깨졌다.** `EdgeBand` export는 옆 세션 브랜치에 **이미 커밋돼 있어서** 공유 쪽 `git diff`에 안 잡혔고, 파일을 통째로 옮기니 main에 없는 파일을 가리키는 export가 따라왔다. **검증 기준을 `git diff`(작업 브랜치 대비)가 아니라 `git diff main`(옮겨갈 base 대비)으로 잡아야 한다.** 정정 후 `git diff main --stat`이 내 11파일로 떨어지는 걸 확인.
- **로컬 통과가 CI 통과가 아니다 — 특히 공유 워킹트리에서는.** 로컬 `typecheck`·`build`·`storybook:build`가 전부 통과했는데 CI에서 `check`·`storybook` 둘 다 실패했다. 로컬은 옆 세션 파일(`EdgeBand.tsx`)이 워킹트리에 **있어서** 통과한 것이었다. 격리 worktree에서 같은 명령을 돌려야 진짜 판정이 나온다(`pnpm`은 심링크 node_modules에서 deps status check로 거부하므로 `node_modules/.bin/*`를 직접 호출).
- **`git worktree add`를 HEAD에서 따면 남의 브랜치 위에 얹힌다.** 격리했다고 안심했는데 base가 `feat/edge-scrim-exploration`이라 내 브랜치에 남의 커밋 9개가 딸려 있었다 — 그대로 PR 올렸으면 옆 세션 PR 내용이 내 PR로 갔다. `git rebase --onto main <base>`로 떼고 `git rev-list --count main..HEAD`로 1인지 확인한다. **worktree는 HEAD가 아니라 `main`에서 딴다.**

- **게시 스냅샷을 마스터로 착각하면 "안 고쳐졌다"는 오진이 나온다.** `importComponentByKeyAsync(key)`는 같은 파일에서 불러도 로컬 마스터가 아니라 **게시 스냅샷 프록시**(노드 ID가 다르다)를 돌려준다. 게시 전에 이걸로 재면 옛 사진·스크림이 그대로 나와서, 이미 끝난 마스터 수정을 "미반영"으로 문서에 적게 된다(옆 세션이 그렇게 적은 것을 실측으로 정정). 마스터 확인은 `✅ Components` 페이지의 실제 노드 ID로 한다.

- **(밤) 워크로그의 "완료"가 파일 상태와 달랐다.** 8/11 밤 기록에 「설정 §4.12: 스펙 외 제거 + 3행 추가 + 신규 4시트(탈퇴 인증·탈퇴 확인·언어 설정·비로그인)」가 완료로 적혀 있었는데, 오늘 `🛠️ settings` 페이지를 열어보니 **4시트가 없고 웹 3탭·태블릿은 구독·알림·로그아웃이 그대로**였다(반영된 건 모바일 2컷뿐). 정합 메모의 절 번호도 `§4.12`로 남아 있었다 — plan-26이 "settings 3곳 정정 완료"라고 적은 것과도 어긋난다. **다른 세션이 완료로 적은 항목은 파일에서 다시 확인하고 시작한다.**
- **(밤) 컴포넌트 속성이 문자열 변수에 지면 화면이 안 바뀐다.** 설정 라벨은 텍스트가 `settings/*` 변수에 바인딩돼 있어 `setProperties({Label})`이 **속성값만 바꾸고 렌더는 그대로**다. 스크립트 리포트는 성공으로 나오는데 스크린샷은 옛 문구라, 라벨 하나를 세 번 어긋나게 만들었다. 바꾸려면 `setBoundVariable('characters', null)`로 풀거나 맞는 변수로 재바인딩한다.
- **(밤) `Position` variant를 바꿔도 코너 반경은 안 따라온다.** 인스턴스 `row` 프레임에 반경이 override로 박혀 있으면 마스터 값을 덮는다. 오픈소스 라이선스 행이 `middle`인데 하단 28이 남아 **거기서 카드가 닫히고** 다음 행이 별도 카드처럼 떨어져 보였다(주미님이 "라운드 때문에 일직선 메뉴 같지 않다"고 지적). 마스터 값과 대조해 되돌린다. 단독 행 그룹은 `bottom`이 아니라 `single`이고, variant를 갈면 색 override(`semantic/text-error`)가 풀리니 다시 건다.
- **(밤) `findOne`은 이름이 같으면 위쪽을 먼저 잡는다.** 언어 화면에서 `findOne(n => n.name === 'Frame 15')`이 **Header Nav Bar 안의 동명 프레임**을 잡아, 선택 변경이 빈 배열에 적용되고도 성공으로 보고됐다. 컨테이너는 `children.find`로 경로를 명시해 잡는다.
- **(밤) `skipInvisibleInstanceChildren`은 양쪽으로 문다.** 켜져 있으면 숨긴 `_SettingsTrailing` 내부에 접근이 안 돼 체크 아이콘을 못 바꾸고, 끄면 이번엔 **숨은 섹션 타이틀 텍스트가 `label`로 먼저 잡혀** 라벨이 엉뚱한 노드에 들어간다. 끄고 쓰되 `visible` 필터를 같이 건다.

- **(밤) blur는 디테일을 지우지 위계를 낮추지 않는다 — 가장자리 처리에서 이게 갈랐다.** progressive blur를 상·하단 후보로 놓고 비교하다 탈락시켰다. ① 부분 블러(2~3px)가 15px 한글 글리프에 얹히면 재질이 아니라 **렌더 결함**으로 읽힌다 ② 제품 컷 상단 VoteBar 파란 막대가 blur를 먹여도 화면 끝에서 **그대로 쨍하다** — 색의 무게가 안 빠진다. **가장자리 처리의 일은 "덜 보이게"가 아니라 "덜 중요해 보이게"다.** 중간에 세웠던 "매끄러운 콘텐츠(사진·그래픽)에서는 blur가 이긴다" 가설도 ②로 폐기. 코드는 지우지 않고 탈락 기록으로 남겼다(왜 뺐는지가 없으면 같은 논의가 반복된다).
- **(밤) 이름이 이미 다른 뜻으로 쓰이고 있으면 그 이름을 쓰면 안 된다.** 새 토큰을 `edge.scrim.*`로 잡으려다 `color.overlay.scrim`이 **모달 뒤 검정 dim**임을 발견하고 `surface-fade-*`로 갈았다. 레포 어휘도 이미 전부 "페이드"였다(`fade-height`·`InputTopFade`·접힘 페이드). 토큰 이름은 값이 아니라 **기존 어휘와의 충돌**부터 본다.
- **(밤) 비활성 전달은 색 단계 + 인터랙션 층(스피너·not-allowed·툴팁 후보)으로** — 아이콘 배지 추가는 밀도·오독('권한 없음') 비용이 이득보다 크다. "왜 안 되는지"는 어차피 아이콘이 못 말한다.
- **(밤) 하드코딩 제거가 드리프트를 같이 잡았다.** `bottom-bar.scrim.*` 라이트가 `#F3F4F6`로 굳어 있었는데 실제 표면(`surface-muted`=`neutral.50`)은 `#F2F4F8`이라, 라이트에서 하단 페이드가 페이지로 **완전히 수렴하지 않고** 있었다. 값을 표면 토큰 참조로 바꾸니 자동 교정. 다크는 원래 맞았다 — 6/19 "옛 warm 그레이" 정리 때 다크만 잡히고 라이트가 남은 것으로 보인다. 8/10 ModelProfile 링, 오늘 낮 text-* 매핑과 같은 계열: **값이 한쪽만 어긋나면 사용처가 아니라 정의 층을 본다.**
- **(밤) 감사표의 숫자는 배치해 보기 전까지 가설이다.** 겹침 45건 → 오검출 3종 제거 후 4건 → **배치해 보고 2건**. 마지막 2건은 DnD 드롭존 힌트 필이었는데 감사 출력에 문구가 그대로 찍혀 있었는데도 못 읽었다. 낮 세션의 "위반 N건은 판정 전 숫자다"가 같은 날 밤에 한 겹 더 확인된 셈 — **판정은 실물에 얹어 봐야 끝난다.**
- **(밤) 겹침은 정적 컷에 거의 없다 — 그래서 컴포넌트의 값은 소급 적용이 아니라 구현 계약에 있다.** 피그마 컷은 대부분 스크롤 안 된 상태로 그려져 있어 콘텐츠가 헤더 아래에서 시작한다. "전수 일괄 배치" 전제를 접고, `EdgeBand`를 패키지로 포팅해 **스크롤 시 동작(`scrollTop > 0`)을 계약으로 박는 쪽**으로 방향을 틀었다.
- **(밤) 규칙이 세로에서만 어긋나면 규칙을 뒤집지 말고 기준면을 다듬는다.** 라이트박스 캡션 겹침을 "캡션을 이미지 기준으로 되돌리기"로 풀면 오늘 확정한 '하단 고정'이 세로에서만 뒤집혀 정본이 둘로 갈린다. 대신 "최대 뷰포트 90%"의 기준면을 카운터·캡션을 뺀 안전영역으로 정의해, 위(카운터)·아래(캡션) 겹침을 한 번에 해소했다. 가로 사진은 안전영역에 안 닿아 변화 없다.
- **(밤) 보드 분산의 신호는 상호 참조다.** 첨부 보드 3곳이 서로 "인터랙션 보드 ④ 참조"를 적고 있었던 게 같은 규칙이 네 번 복제됐다는 뜻이었다. 정리 규칙은 "정본 한 곳 + 나머지는 참조 한 줄"로 잡았다.

- **(밤) 대체 형태만 맞추고 정보량을 깎으면 대체가 아니다.** 모바일 첨부 시트는 행마다 아이콘 + 라벨 + 제약(형식·장수·용량)을 주는데 PC 팝오버는 라벨 두 줄뿐이었다. 형태(시트→팝오버)는 `LAYOUT 05` 규칙대로였지만 **고르기 전에 알아야 할 것이 PC에서만 없었다.** 규칙표가 대체 *형태*만 적고 있어서 생긴 구멍이라, 폭 240→320과 함께 규칙표에 근거 문장을 같이 박았다.
- **(밤) 폭은 취향이 아니라 문구가 정했다.** 제약 문구 실측 249 + 아이콘 24 + gap 12 + 패딩 32 = 317 → 320. 결과적으로 Desktop 앵커드 오버레이가 첨부·모델 리스트 둘 다 320이 되면서 폭 체계가 2단(240/320)에서 1단으로 줄었다.
- **(밤) 소비처가 0이 됐다고 토큰을 지우지 않았다.** `--layout-overlay-popover`(240)는 첨부가 320으로 옮겨가며 쓰는 곳이 없어졌지만 공개 manifest에 실린 값이라 변경·삭제 둘 다 브레이킹이다. **값은 그대로 두고 비고를 사실에 맞게 고친 뒤 "소비처 없음"을 명시**했다 — 다음 사람이 240을 근거로 뭔가를 정하지 않도록.

- **(밤·시트) 조합 축은 쓰지도 않을 변형을 만든다.** 헤더를 leading/trailing/title 3축으로 잡았다가 주미님이 2벌로 줄였고 그게 맞았다. 3축이면 `back + title + description` 같은 조합이 생기는데 실제 화면에는 없다. 축은 "표현 가능한 것"이 아니라 **"실제로 쓰는 것"의 수만큼** 둔다. 설명 줄을 축이 아니라 BOOLEAN으로 뺀 것도 같은 판단이다.
- **(밤·시트) 컴포넌트 값의 다수결은 그 컴포넌트가 올라앉는 화면에서 센다.** 시트끼리만 세면 좌우 20이 다수여서 20 통일을 추천했는데, 화면 거터를 실측하니 전부 16이었다. 시트는 화면을 반만 덮고 뒤가 계속 보이는 표면이라 어긋남이 그대로 드러난다. **비교 대상을 컴포넌트 안으로 한정한 게 오답의 원인**이었다.
- **(밤·시트) 정렬은 박스가 아니라 잉크로 맞춘다 — 단, 면이 있으면 박스가 잉크다.** 종료 버튼은 44 탭 타깃 안 24 아이콘이라 패딩 6 + 안쪽 10으로 시각 끝을 16선에 세웠고, 뒤로가기는 면이 채워진 칩이라 반대로 박스 모서리를 16에 뒀다. 같은 헤더 안에서 두 규칙이 갈리는 이유가 "채워진 면인가"다.
- **(밤·시트) 컴포넌트를 못 만드는 화면이 있으면 그게 감사의 결론이다.** 종료와 뒤로가기가 다른 컴포넌트에 갇혀 있던 건 수치 드리프트 목록의 한 줄이 아니라 **조립 불가**였고, 실제로 리스트 경유 전문 시트엔 닫는 방법이 없었다. 드리프트 표는 픽셀 차이를 세지만 진짜 신호는 "이 조합이 안 만들어진다"에 있다.
- **(밤·딤) 값을 정하기 전에 이미 그려진 것을 센다.** dim 2단 분리는 새 결정이 아니라 화면이 이미 시트 30 / 모달 40으로 그려져 있던 걸 토큰으로 승격한 것이다. plan-22가 "실사례 생기면 재검토"로 열어둔 조건이 파일 안에 이미 충족돼 있었다. **add-as-earned는 미래를 기다리는 게 아니라 현재를 세는 규칙이다.**
- **(밤·딤) 임시 적용 → 스크린샷 → 같은 스크립트에서 원복으로 시각 탐색을 했다.** 블러 4/8/16과 딤 20%를 실제 화면에 걸어 보고 전부 되돌렸다. `use_figma`가 원자적이라 스크립트가 실패하면 아무것도 안 남고, 성공하면 원복까지 끝나 있다. 말로 갈리지 않는 값(블러 반경, 딤 알파)은 이 방식이 논쟁보다 빠르다.
- **(밤·딤) 효과의 값은 그 표면이 움직이는지부터 본다.** 블러 4는 시각적으로 가장 좋았지만 시트가 드래그되는 표면이라 매 프레임 재합성된다. **정지 화면에서 고른 값이 인터랙션에서 비용이 되는 자리**라, 분리를 이미 만들고 있던 흰 표면·radius·그림자를 근거로 뺐다.

- **(밤) 기획서 버전이 바뀌면 예전에 맞았던 디자인이 조용히 틀린다.** 비로그인 소진 후 입력창을 평소대로 두는 건 v1.0.3(소진 후에도 Chat 무제한)에선 맞는 설계였다. v1.0.6이 "소진 뒤엔 Chat 포함 전부 게이트"로 뒤집으면서 같은 화면이 **거짓 약속**이 됐는데, 화면은 그대로 남아 있었다. 레포 미러가 두 버전 공존이라 v1.0.3만 보고 답할 뻔했다 — **정합의 근거는 항상 최신 절 원문**이고, 버전이 오른 절은 "이 규칙에 기대던 화면이 뭐였나"를 역으로 훑어야 한다.
- **(밤) 금지 규칙의 적용 범위를 좁히면 막혀 있던 자리가 열린다.** "‘2회 다 썼어요’ 문구 금지"는 자발 진입에서 같은 모달을 재사용하기 때문에 생긴 제약인데, 화면까지 금지로 읽으면 **왜 막혔는지 말할 자리가 사라진다.** 제약을 모달로 한정하고 진실은 소진 상태에서만 존재하는 화면에 두니 두 요구가 동시에 만족됐다 — **진실은 화면에, 모달은 중립.**
- **(밤) 갈리는 축이 매체가 아니라 종류였다.** 토스트를 "모바일은 상단, PC는 하단"으로 정리했다가 실측이 뒤집었다. PC와 S9-1·S9-3이 **똑같이 컴포저 상단 −18**이었다 — mo/PC를 가로질러 같은 값이 나온 게 근거다. 실제 기준은 **토스트가 무슨 말을 하는가**였다: 시스템 오류는 재시도가 컴포저 근처라 아래, 행동 확인은 이어질 행동이 없어 조작을 안 가리게 위. **분기를 발견하면 "무엇이 다른가"보다 "왜 다른가"를 맞춰야 규칙이 다음 화면에도 선다.**
- **(밤) 좌표를 계약에 넣지 않았다.** `ToastViewport`는 절대 y가 없고 앵커 요소에 상대적으로 뜬다. 이유가 둘 다 실물에서 나왔다 — 컴포저 높이가 134~208로 가변이라 S9-2·S9-2N이 컴포저가 낮아졌는데 토스트가 안 따라가 Bottom Bar를 4px 침범한 채 남아 있었고, 피그마 y=127에는 웹에 없는 iOS StatusBar가 들어 있었다. **가변인 것을 기준으로 삼으면 규칙이 스스로 깨진다.**
- **(밤) 규칙이 자기 산식을 자기가 안 지키고 있었다.** `layout.md`가 "zone = width + gutter×2"를 사이드바에만 적어둬서 Side Panel 산식이 좌우 16px씩 낙관적이었다. 정정하니 1280·요약 400에서 컬럼이 508로 **하한 520을 12px 깬다** — 문서엔 524로 지킨다고 적혀 있었다. "패널이 열리면 폭과 무관하게 사이드바를 rail로 접는다"로 통일해 해소했고, 덤으로 패널 열림 셸이 한 종류로 줄었다. **규칙을 쓸 때 자기 산식을 전 케이스에 대입해 봐야 한다.**
- **(밤) 떠 있는 것은 크롬뿐이다.** LNB·Side Panel은 gutter 8 + 라운드로 뜨고 Main은 flush 캔버스다. 비대칭으로 보인다고 Main까지 카드로 만들면 gutter가 그리드로 읽혀 패널이 "또 하나의 콘텐츠 열"이 되고, **가린 게 아니라 밀었다는 신호가 사라진다** — Side Panel을 Dialog 대신 고른 이유가 그거라 이 구분이 기능이다. 채택 근거도 취향이 아니라 비대칭 비용이었다: 이미 웹 20장이 쓰고 `--layout-sidebar-gutter`가 공개 토큰이라, 걷어내는 건 미채택이 아니라 철회다.
- **(밤) `disabled`와 `잠금`은 다르다.** 잠금 입력창은 눌러야 한다(탭 = 게이트 재노출). 기존 결정 노트의 "입력창 disabled 금지"도 실은 "탭이 죽으면 안 된다"는 뜻이었지 "평소처럼 보여야 한다"가 아니었는데, 문구만 남아 있어 화면이 평소 모습으로 복귀하고 있었다. **규칙은 결론만 적지 말고 이유를 같이 적는다** — 이유가 없으면 다음 사람이 범위를 잘못 잡는다.

- **(밤) 실패 상태는 성공 상태에 딱지를 붙인 게 아니다.** 이미지 첨부 실패 칩이 사진 위에 검정 40% 스크림 + 흰 ⚠였는데, 개발이 "첨부가 실패하면 프리뷰를 못 만든다"고 해서 그림 자체가 구현 불가였다. 사진을 걷어내자 스크림도 흰 아이콘도 근거를 잃었다 — 가릴 게 없고, 흰색은 검정 스크림 위에서만 성립한다. **실패는 성공 화면에서 뭘 빼는 게 아니라 다른 재료로 다시 짜야 한다.** 다시 짜고 보니 File 에러 칩이 이미 쓰던 규칙(타입별 기본 면은 유지, 빨강은 테두리·아이콘에만)으로 두 타입이 한 규칙에 모였다.

#### AI 도구 활용

- **(밤) 스크립트가 "성공"이라 말해도 렌더는 다를 수 있다.** 설정 정합에서 세 번 — 라벨 변수 바인딩, 리스트 참조 오조준, 숨은 텍스트 오조준 — 모두 반환 리포트는 정상이었고 **스크린샷에서만 틀린 게 보였다.** 노드 조작은 리포트가 아니라 렌더로 검증한다.

#### 설계 결정

- **(밤) 파괴적 액션은 주 버튼 자리를 주지 않는다.** 탈퇴 확인 모달에서 `취소`를 solid로 두고 `탈퇴하기`는 outline + `semantic/text-error`로 강조를 낮췄다. Button 세트에 danger variant가 없다는 사정도 있었지만, **되돌릴 수 없는 액션에 강조를 얹지 않는 쪽이 맞다**고 봤다.
- **(밤) 언어 목록은 각 언어 표기로 둔다.** 스펙은 "한국어·영어·일본어"지만 화면은 한국어 · English · 日本語다. UI가 한국어인 상태에서도 JP 사용자가 자기 언어를 찾을 수 있어야 한다 — JP가 주 타겟이라 더 그렇다.
- **(밤) 남는 게 없는 탭은 감춘다.** 웹 비로그인 설정은 계정 탭에 프로필·비밀번호 변경·회원 탈퇴가 전부 빠져 빈 탭이 된다. 빈 탭을 남기는 대신 탭 자체를 숨기고 앱·정보 2탭으로 뒀다.

## 비로그인 게이트 — 닫은 뒤 화면(SA-1a) 신설 + 섹션 재편 (제품 파일, 8/11 밤 세션)

```
https://www.figma.com/design/VHdwVCvG0YG7wucLtOWmOg/...?node-id=7980-18973

여기 내용좀 정리하려는데 도와주라. 
특히
SA-1 비로그인 게이트 — 2회 소진 후 입력창 탭
이 내용보면 끄면 질문횟수 소진되었으니 채팅창에 다른게 노출되어야하나? 어케해야하는지도 봐주라
```

### 무엇이 문제였나

`비로그인 유도 flow` 섹션(`7980:18973`)의 SA-1은 **모달이 열린 상태 한 장뿐**이었다. 게이트는 닫을 수 있는데(§3.2) 닫은 뒤 화면이 파일에 없었고, 그 상태의 입력창을 어떻게 보여줄지는 기획서에도 없다.

기획서 v1.0.6 §3.2 원문을 확인하니 판단 근거가 나왔다 — "2회를 소진한 뒤에는 Chat·Quick·Deep 어떤 답변도 받을 수 없다". v1.0.3까지는 소진 후에도 Chat·factual이 무제한이라 입력창을 살려두는 게 맞았지만, v1.0.6에서는 **소진 상태의 입력창이 더 이상 쓸 수 있는 입력창이 아니다.** 그런데 화면은 평소와 똑같이 생긴 입력창으로 복귀하고 있었다. 방치하면 ① 왜 막혔는지 화면에 없어 탭→모달→닫기 루프 ② 모바일에서 탭=포커스라 키보드와 시트가 동시에 올라옴(구현은 `readOnly`로 막아야 함) ③ 초안을 못 쓰는데 커서가 깜빡이는 거짓 약속.

### 결정 — 잠금 상태 + 이유는 화면에

- 입력창을 평소 모습으로 되돌리지 않고 **잠금**으로 남긴다. 시각은 `Chat Input Bar State=disabled`를 빌려 쓰고 placeholder를 "로그인하면 이어서 질문할 수 있어요"로 교체.
- 기존 "입력창 disabled 금지"는 유지 — 그 뜻이 "탭이 죽으면 안 된다"임을 결정 노트에 명시했다.
- 입력창 위 `Callout`(Type5 = action)에 이유와 행동: "무료 체험 2회를 모두 사용했어요" / "로그인하면 대화 그대로 이어서 질문할 수 있어요" / [로그인하고 계속하기]. 아이콘은 실패가 아니므로 `triangle-alert` → `info`.
- **"2회 다 썼어요 금지"와 충돌하지 않는다** — 그 제약은 모달 문구 대상(자발 진입에서 같은 모달 재사용). SA-1a는 소진 상태에서만 존재하는 화면이라 거짓이 될 수 없다.
- 웹 Callout은 DS 마스터 `maxWidth 400`을 존중해 늘리지 않고 입력 컬럼 중앙 정렬.

검토 후 탈락: **최소안**(입력창 그대로 + 안내만) = 커서·키보드 거짓 약속이 남는다 / **강한 안**(입력창을 CTA 버튼으로 치환) = §3.2 "닫으면 직전 화면으로 복귀"와 시각 차이가 너무 크고 로그인 후 복귀 전환도 커진다.

### 반영

- 신규 `SA-1a 게이트 닫은 뒤 — 입력창 잠금` 모바일(`8282:18920`)·웹(`8283:101403`). SA-1 복제 → Dim·Login Sheet(Modal) 제거 → 입력창 잠금 → Callout(`8283:18131`·`8283:101615`).
- 결정 노트 `비로그인 게이트`(`7541:15715`) 갱신 — 규칙에 v1.0.6 변경분 명시, 디자인 결정 3줄, 주미님 확인 4건 추가(528 → 919 높이).
- **섹션 재편**: 화면 7장이 한 줄에 뒤섞여 있고(주제 2개) 결정 노트 열이 폭 1440 웹 프레임에 밀려 어긋나 있었다. 밴드 3줄로 분리 — ① 비로그인 전환(SA-1·SA-1a·history 2장) ② 네트워크·서버 오류(S9-1·S9-2·S9-2N·S9-3) ③ 웹 Desktop 1440. 노트를 각 화면 열 x에 스냅, 섹션 `6885×4150` → `3450×7800`, 자식 겹침 0 실측.
- 캡션·설명 6건 추가(`8286:18293`~`8286:18298`), 밴드 라벨 3건(`8282:18917`~`8282:18919`).
- ②의 4장은 **다른 섹션으로 옮기지 않았다** — PC Layout 오류 가이드 섹션이 이 화면들을 사본으로 참조 중이라(`error-section-layout-2026-08-10.json`의 `copies[5].src = 7539:15491`) 여기가 원본이어야 한다. 밴드 라벨로 찾기 문제만 해소.

### 승인 대기로 남긴 것

read-only로 판정만 하고 write는 안 했다. `Chat Input Bar` `State=locked` 신설과 `disabled`의 중첩 `Mode Toggle` 비활성화 2건은 **제안서(변경안·영향 범위·rollback)까지 써서 plan-25에 뒀다.** 후자는 실측으로 실재 확인 — `disabled` 변형이 `Mode Toggle State=default`를 물고 있고 세트(`7759:199323`)엔 `disabled` 축이 이미 있다. 픽셀 변화가 있는 시각 변경이라 게시 전 대상 조회가 선행이다. 문구 4건도 KR 확정 전이라 JP/EN 초안까지만.

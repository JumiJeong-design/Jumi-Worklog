- **오토레이아웃 프레임 위 오버레이는 `layoutPositioning='ABSOLUTE'` 선행** — 모바일 홈/히스토리 프레임이 수직 스택이라 스피너·딤·메뉴의 x/y 지정이 무시되고 스택 끝에 붙는다(빠르게 시작하기 블록이 인디케이터 뒤로 간 사고 포함). appendChild → ABSOLUTE → 좌표 순서로.
- **중첩 인스턴스 검색은 `findAllWithCriteria`로만 잡힌다** — 클론 직후 `findAll(술어)`·`findOne`은 인스턴스 내부를 못 본다(0건). 패널 인스턴스를 먼저 잡고 그 안에서 `findAllWithCriteria` → 텍스트 매칭으로 행을 특정해야 했다.
- **컴포넌트 TEXT 속성이 걸린 라벨은 `characters` 쓰면 마스터 기본값으로 리셋** — RetryButton 라벨을 '확인'으로 바꿨더니 '다시 시도하기 1/3'로 되돌아옴. `setProperties({'label#…': '확인', 'count#…': ''})`로 속성 단위로 써야 한다.
- **"신설"이라고 판단하기 전에 DS 전수 검색** — ContextMenu를 새로 만들 뻔했는데 DS에 `Context Menu`(194:38)+`ContextMenu/Item`(destructive까지)이 이미 게시돼 있었다. 제품 파일 임시 메뉴는 게시본 인스턴스로 교체 완료.

- 노션 기획서를 66k 문자 통으로 읽지 않고 헤딩 오프셋 → 키워드 위치 → 절 단위 슬라이스로 읽으니 §4.1·§4.2만으로 홈 정합 근거가 다 나왔다. "칩 누르면 뭐 뜨나" 같은 질문은 기획서 → 태스크 페이지 → Slack 스레드로 출처를 끝까지 추적해야 "데이터 없음"을 확정할 수 있었다.
- 변수 바인딩이 잘 된 블록(빠르게 시작하기)은 다크 프레임에 넣기만 하면 모드 상속으로 다크가 공짜로 나온다 — 다크 동기화 비용이 라이트 정합 품질에 달려 있다는 것을 체감.

#### 설계 결정

- **웹 빠르게 시작하기 = 키워드 칩(기획서 §4.1 명문 채택, 주미님 확정)** — "문장형 예시 질문이 아니라 러프한 고민 키워드"가 원문. 문장 예시의 교육 역할은 placeholder("예: 이직 제안을…")와 모더레이터 유도 질문 대화가 담당하는 설계라, 문장 필 유지(UXUI 우선) 대안과 비교 끝에 스펙을 따랐다. 탭+문장 필 판은 참고용 보존.
- **모드 토글 결정 종결** — v1.0.6이 'Deep On/Off 스위치 하나(나란히 선택 아님)'를 명문화. 현행 Deep 칩이 정답, Quick|Deep 세그먼트 탐색 폐기 확정.
- **사업자 정보 푸터는 홈이 아니라 설정 화면 하단 소관**(기획서) — 홈 백로그에서 제거.
- **칩 탭 = Chat 즉시 전환** — 칩은 Quick/Deep 트리거가 아니라 Chat 대화의 시동(변환 문장 전송 → 모더레이터 유도 질문). 칩별 변환 문장·유도 질문 데이터셋은 기획서에 없음을 확인(예시 1쌍뿐) → 기획 요청 항목.

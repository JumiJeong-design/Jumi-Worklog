### 함정 모음

- **미게시 컴포넌트는 import 불가** — DS에 새로 만든 컴포넌트는 라이브러리 게시 전엔 제품 파일에서 `importComponentByKeyAsync`가 실패한다. 신설→게시→제품 치환 순서를 계획에 미리 넣을 것.
- **라이브러리 아이콘 재인스턴스화 시 검정 fill 부활** — 제품 화면의 lucide 아이콘이 깨끗해 보여도 그건 인스턴스 override(fill 제거) 덕분. DS에서 새로 인스턴스를 뜨면 마스터의 검정 fill이 살아난다. 같은 fill 제거 override를 다시 걸어야 정합.
- **"스펙이 없다"고 단정하기 전에 탐색 프레임부터** — 시트 피드백 선택 상태가 없다고 보고했는데 `피드백 · 도움 됐어요 선택` 프레임에 이미 있었다(Button `State=engaged`). 상태 스펙은 상태명 프레임 검색 먼저.
- **"전수 스캔" 오보 — 페인트 타입 커버리지 명시** — 색 감사에서 SOLID만 보고 "미바인딩 소진"이라 단정했다가 Deep 그라데이션·그림자 누락을 주미님이 지적. 전수라 말하려면 SOLID+GRADIENT 스톱+EFFECT 색을 다 돌리고 보고에 범위를 명시할 것.
- **인스턴스 swap은 텍스트 오버라이드를 초기화한다** — Attachment 치환 때 에러 칩 문구("5페이지 초과" 등)가 기본값으로 덮였다. swap 전 텍스트 스냅샷→swap→복원 + 전후 스크린샷 대조를 게이트로. 오후 chat/chart 치환은 이 절차로 4건 보존.
- **변수는 컬렉션 이름만 보고 못 찾는다** — 13px이 `font-size` 컬렉션엔 없어 "스케일 부재"로 판단했는데 `typography` 컬렉션 `font/size/13`에 있었다. 값 검색은 전 컬렉션 FLOAT 전수로.
- **스테일 라이브러리 스냅샷** — 제품 파일 인스턴스는 게시 시점별 remote 스냅샷을 참조한다. `History` 세트가 폐기 전(7656:26405)·현행(7669:35766) 두 remote로 공존했고 variantProperties는 둘 다 `login=off`라 이름으론 구분 불가. 판별은 `mainComponent.parent.id`, 수정은 `swapComponent`(오버라이드 보존). 전수 스캔으로 잔여 0건 확인.
- **파일 간 이동 = 노드 ID 전면 변경** — 인터랙션 보드가 DS→제품 파일로 옮겨지자 옛 ID가 전 페이지에서 0건이라 "보드 소멸"로 오판할 뻔했다. ID 조회 실패 시 삭제 단정 전에 다른 파일로의 이동 가능성을 먼저 묻는다. 반대로 라이브러리 변수 바인딩은 이동에도 유지된다(이동 후 감사: 필 37건 중 33건 바인딩 생존, 나머지 4건은 아이콘 숨김 필 비이슈).

#### 설계 결정

- **피드백 선택 문법 통일** — engaged = 면 `neutral/100` + 안쪽 1px 선. 선 강도는 주미님이 `neutral/300`으로 직접 튜닝해 확정. `Report/Feedback`·`Button/ActionBar`·`Answer/Feedback` 3곳 공유.
- **`Answer/Feedback`은 별도 컴포넌트** — 리포트 피드백(👍👎 아이콘 칩)과 UI 문법이 달라(텍스트 라벨 outline Button 2개) 한 세트에 축으로 우겨넣지 않음.
- **추론 텍스트는 Message Bubble 아님**(주미님 판정) — "답변을 요약해서 리포트를 만들었다!"류는 현행 유지.
- **행간 촘촘 계층 = 140% 확정**(주미님) — 130%는 멀티라인·JP 글리프 클리핑 위험. `body/xs-r-tight`·`body/sm-m-tight`·`caption/2-tight` 신설.
- **Deep 링 색은 램프 편입 아닌 브랜드 그룹** — `#4DD959`·`#3D80FF`는 green/blue 램프 어디에도 없는 링 전용 값이라 `brand/deep-ring/*`으로 신설(램프에 끼우면 이름이 거짓말).
- **브랜드색 토큰 신설 기준 = 재사용**(주미님 "과해") — 카카오/라인 로그인 색은 로그인 화면 한정이라 하드코딩 동결, add-as-earned. 그림자 스냅은 정확 일치분만.
- **이미지 미리보기 = 풀스크린 라이트박스**(주미님 "팝오버 밤티") — 어중간한 카드 팝오버는 확대인지 툴팁인지 애매. 스크림은 90%→60%+blur→**60% 단색**으로 두 번 깎아 확정, 닫기도 스크림·Esc·× 3종으로 최소화(블러·스와이프 다운 "굳이" 폐기). 장식 층을 하나씩 빼며 확정하는 패턴.
- **유일한 경로인 것과 눈에 띄어야 하는 것은 다른 문제다**(주미님 "설정이 그 정도로 중요할까") — 비로그인 하단의 [설정]이 언어·약관·개인정보·문의로 가는 유일한 문이라는 사실에서 "라벨을 줘야 한다"로 건너뛴 게 오판이었다. 전부 저빈도 항목이라 전환 목표인 [로그인하기]와 동등한 무게를 주면 화면 목적만 흐려진다. 아이콘 단독 유지, 대신 `aria-label`은 필수.
- **축 이름은 겉모습이 아니라 의미로 짓는다** — TextDivider 선 축을 `line = solid | wave`로 만들었다가 `type = default | loading`으로 고쳤다. 이 레포는 `state="collapsed"`·`auth="logged-out"`처럼 의미 기준을 쓴다. 겉모습 이름은 그 스타일이 다른 의미로 재사용될 때 바로 거짓말이 된다.
- **물결은 로딩 신호를 혼자 지지 못한다** — 손그림 선은 "부드러움"으로 읽히지 "진행 중"으로 읽히지 않는다. 신호가 성립하는 건 스피너와 바뀌는 문구가 옆에 있기 때문이고, 물결은 거드는 역할이다. 그래서 `type`은 선 모양만 결정하고 스피너는 `leading` 슬롯으로 분리했다.
- **리포트는 섹션 단위로 도착하지 않는다**(기획서 §4.3 "응답이 모인 뒤 한 번에") — "출처 섹션은 아직 물결, 위쪽은 이미 직선" 같은 그림은 성립하지 않는다. 도착 순서대로 오는 건 개별 모델 말풍선이지 리포트 섹션이 아니다. 대신 **화면 단위**로 갈렸다 — 대기 화면은 통째로 로딩 맥락, 리포트는 통째로 완료 맥락.
- **바깥 여백은 컴포넌트가 아니라 그 화면이 정할 일** — 분리본(패딩 12/16)과 마스터(8/0)가 어긋났을 때 마스터를 올리면 리포트 섹션 마커 19개가 같이 두꺼워진다. 마스터 패딩을 지키고 여백은 감싸는 프레임에 맡겼다(결과적으로 393×49로 원본과 일치).

## TextDivider `type=loading` — 물결선 규명부터 코드까지

"로딩 중엔 구불구불, 다 되면 일직선"(주미님)에서 시작해 Figma 축 신설 → 분리본 재연결 → 패키지 포팅까지 갔다.

**물결의 정체.** 벡터 경로는 직선인데 `strokeGeometry`가 38,237자에 진폭 ±1.9px다. Figma가 직선 경로를 손그림 스트로크로 렌더하는 것이고, **그 속성은 Plugin API로 못 찾았다.** 그래서 물결본을 먼저 복제해 보존한 뒤 원본 벡터를 새로 만든 직선으로 갈아끼웠다(새 벡터는 `strokeGeometry` 58자).

**축과 슬롯.** `line = solid | wave`로 만들었다가 `type = default | loading`으로 고쳤다. 분리본 11개가 마스터에 없는 `익명` 뱃지를 물고 있어 그냥 치환하면 뱃지가 사라지는 구조라, `trailing` 슬롯(BOOLEAN + INSTANCE_SWAP, 기본 `Badge/Label surface/sm`)을 먼저 만들고 `label`과 `labelGroup`(간격 4)으로 묶었다. 복제 과정에서 끊긴 `type=loading`의 `leading` 바인딩도 복구했다.

**재연결.** 하나로 파일럿을 돌려 원본과 같은 393×49·뱃지 35×25가 나오는 걸 확인한 뒤 그 인스턴스를 복제해 나머지 10개를 채웠다. 결과 인스턴스 **34개**(`default` 23 · `loading` 11), 분리본 **0개**, `type`↔선 모양 불일치 **0건**. 주미님 퍼블리시 후 34개 전부 새 축(`type`·`trailing`)을 보는 것까지 확인했다.

**코드.** 물결 지오메트리 38KB를 그대로 실을 수 없어 **중심선을 2px 간격 79점으로 샘플링**했다(941자, 진폭 2.66px, 양 끝 y 일치로 `repeat-x` 이음매 0). data URI에 CSS 변수를 못 넣으므로 **모양만 마스크로 내고 색은 `border-control` 토큰이 칠한다** — 다크가 그대로 따라온다. 검증은 test-runner 9개 + 헤드리스 픽셀 실측.

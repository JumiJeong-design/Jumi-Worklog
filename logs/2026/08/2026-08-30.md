### 함정 모음

- **⚠️ 숨긴 노드의 x좌표는 허수다** — `TrailingIcon`은 기본 `visible=false`라 오토레이아웃 흐름 밖에 있고 x가 마지막 계산값에 멈춰 있다. 세트를 훑으면 오른쪽 여백이 0·16·95·111·139·155로 흩어져 보이는데 전부 가짜. **판정은 `InputContainer.paddingRight`로 한다.**
- **캔버스에 남아 있다 ≠ 살아 있다** — 「계약 문서가 사용처 0이라 적었는데 실물 16곳이 있으니 문서가 낡았다」고 봤다가 거꾸로였다. 그 화면들은 `plan-41`이 폐기 대상으로 잡아 둔 것. **실측 수치로 문서를 반박하기 전에 폐기 목록부터 대조한다.**
- **INSTANCE_SWAP 기본값은 이 파일에서 노드 ID다** — `addComponentProperty`에 컴포넌트 key(40자)를 주면 `Property value is incompatible`. preferred values는 반대로 key를 받는다.
- **`origin/main`이 내 워킹트리 base보다 앞서 있었다** — 다른 세션의 #320이 `plan-10`을 4곳 고쳐 놓아서, 파일을 통째로 새 브랜치에 옮겼으면 그 4건을 되돌릴 뻔했다. **추가한 절만 잘라 얹어 삭제 0으로 만들었다.**
- **43-2 옛 프록시는 값어치를 재고 방치했다** — 프로퍼티가 안 내려온 4곳은 `Login Modal` 2단 중첩의 옛 세대 프록시. 눈이 꺼진 딤 뒤 필드라 고쳐서 얻는 게 없고, `swapComponent`는 override 유출 위험(룰 42)이 있어 안 했다.
- **「A를 B랑 안 맞췄다」는 채우라는 뜻이다** — 「웹 스텝퍼를 모바일이랑 안 맞췄다」를 web의 `4/4`를 떼는 쪽으로 반대로 읽었다가 「여전히 스테퍼 없는데?」로 되돌아왔다. 비교 요청은 어느 화면을 보고 계신지부터 확인한다.

- **createAutoLayout 기본 흰 fills가 정본에 스민다** — 시안을 정본으로 승격하면 컨테이너 흰 fills·근사색이 그대로 따라온다. 승격 직후 미바인딩 SOLID 전수(이번엔 55건)를 돌린다.

### 회고 및 인사이트

#### AI 도구 활용

- **관례가 갈리는 자리는 말 대신 비교 컷** — 눈 매핑(동작 표시 vs 상태 표시)을 말로 설명하다가, `eye-off`/`eye-closed`를 실물 필드에 얹은 비교 컷을 만들어 바로 결정받았다. 임시 인스턴스 렌더 후 삭제 패턴이 이럴 때 싸게 먹힌다.
- **룰 43-1 두 번 적중** — 「게시했어」 직후 상태값 대신 소비 파일 인스턴스로 쟀다. 패딩(값)은 게시 없이 이미 내려와 있었고, 프로퍼티(구조)는 게시 후 50/54, 기본값 변경은 재게시 후 16/16. **값·구조·기본값이 각각 다르게 전파된다.**
- **취향 결정은 비교 컷 반복으로 수렴** — A(모달)/B(투뎁스) → 카드/리스트 행(V1/V2)까지 두 번의 2벌 비교로 「끔찍한 화면」이 넉 턴 만에 확정안으로. 말로 설득한 구간은 전부 헛돌았다.
- **병행 편집 세션과의 겹침 가드** — 같은 파일을 옆 세션이 실시간으로 고치고 있었다(약관 제목 블록·스테퍼). 쓰기 직전 「같은 문구 존재 확인 후 SKIP」 가드와 재조회가 두 번 사고를 막았다.

#### 설계 결정

- **Text Field 눈 매핑 확정: 가림 = `eye-closed`(상태 표시) · 보임 = `eye`** — 주미님 "눈을 감고 있어야 맞지 않나". Material·MUI 계열(동작 표시)이 아니라 Ant 계열(상태 표시)을 따른다. 글리프는 사선(`eye-off`)이 아닌 눈꺼풀(`eye-closed`).
- **제품 화면에 토글 예시를 안 그렸다** — 비밀번호 화면 전부가 `[v1.0.8 폐기]` 구역이라 그리면 폐기 때 같이 지워진다. DS 예시 4컷만으로 종결.
- **모바일 약관 4장: 전면 화면 → 딤+시트** — §3.1 「로그인은 오버레이」 정합 · web과 구조 일치 · 대화 복귀 감각. 게이트의 배경 3층과 시트 껍데기를 복사해 콘텐츠만 이동(시트 535 · 화면의 63%).

```
웹 쪽 화면을 보면 가이드 텍스트가 많은데 모바일에 거의 많이 써있고. 웹 쪽은 거의 없거든
```

- 라이브 4페이지 419장 전수 검토 — 총량은 웹이 적지 않았고(로그인·채팅은 웹이 더 많음), 짝 대조로 진짜 어긋남 4건을 추출. 이 검토에서 두 트랙이 갈라짐

```
아니 그렇게 축약한게 더 불친절해 ㅡㅡ
```

- 확장자 19개 나열 제거 — 문장은 유지하고 괄호만. 시트·팝오버·바텀시트 열림·보드2 등 5컨테이너 10줄, 재독 검산 allClean. 마스터는 DS 범용 `Bottom Sheet`/`Context Menu`라 기본값 오염 없음(같은 마스터의 모델 선택 시트에 문구 부재로 검증)
- 사유 툴팁: 종류별 목록 분리(SVG→이미지 10종 / ZIP→문서 9종), 앵커=칩(터치 좌표 아님) · 칩 위 4px · 화살표=칩 중앙 · 16px 클램프. 계약의 「3초」에 목록형 예외(A안 — 바깥 탭·스크롤·입력·Esc까지 유지) 신설, `attachment-chip.md` 개정
- 닫기(X) 툴팁 신설은 기각 — 44px 터치 타깃·role=tooltip 충돌·Popover 계약 중복(규칙 41)
- 검토에서 나온 웹↔모바일 어긋남 4건 종결 — 웹 약관 제목(옆 세션 기해결) · 탈퇴 갈래 설명(삽입→이후 재구성으로 발전) · `인증번호` 용어(전부 [v1.0.8 폐기] 화면이라 스킵) · DnD 토스트(기획서 §166 그대로라 결함 아님 · 첫 보고 정정)

## 웹 탈퇴 흐름 재구성 트랙 — 「끔찍한 화면」 → 투뎁스 (prism · Figma)

```
이런 끔찍한 화면은 어디서 나온거냐?
```

- 출처 확정: 8/28 plan-41 신설분이 모바일 3장 흐름을 설정 패널에 간격 0으로 이식한 것 + 이날 내가 캡션 한 줄을 같은 방식으로 얹어 악화

```
웹에 애초에 스텝디자인이나 플로우가 저렇게 들어가는게 맞아!?
내부에 이런식으로 투뎁스가 될수도있자나
```

- 설정 웹 스테퍼 7곳 제거 → 흐름 재검토 → A(모달 체인)/B(패널 투뎁스 · 튜터 웹 패턴) 비교 컷 → B 확정 → 카드/리스트 행(V1/V2) 비교 → **V2(헤어라인 행) 확정.** 타이포 22→16/13 · back 헤더는 기준선 12, 콘텐츠는 32(그리드 실측 12/32/64)

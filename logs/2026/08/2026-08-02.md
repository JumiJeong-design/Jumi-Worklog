- **축 기준은 `design-system/rules.md` #5** — 웹이라 모바일·PC를 함께 대응해야 하므로 hover와 pressed를 나누지 않고 `engaged` 하나로 통합. 값 이름은 rules #5의 `enabled`, 표기는 파일 관례인 `State=`.
- **`engaged` 배경은 알파 시맨틱 토큰 `semantic/pressed/surface`** (rules #23). 불투명 `surface/Inset`이 아니라서 어떤 배경 위에서도, 다크모드에서도 성립한다.
- **새로 만든 변수 0개.** 전부 기존 로컬 변수 바인딩이다. raw `neutral/black`·`neutral/900`·`neutral/600` → `semantic/text-primary`·`semantic/text-secondary`로 교체(부제가 `#30323b` → `#53555c`로 밝아지는 시각 변경이 `enabled`에도 적용된다).

### 곁다리로 정리한 것

- **`Menu Item`(`3352:1374`)** — 6종(`default`/`hover`/`pressed`/…)으로 rules #5를 정면으로 어기고 있었다. `default`→`enabled`, `hover` 삭제, `pressed`→`engaged`로 5종화. 삭제 전 인스턴스 6개의 State를 조회해 `hover`/`pressed` 사용이 0건임을 확인하고 지웠고, 사후 재조회에서 전부 정상 승계됐다.
- **`Type=selection`(`192:38`)** — 선택 시트인데 행 3개가 전부 체크였다. CheckIcon을 `selected` 전용으로 만든 김에 첫 행만 `selected`, 나머지는 `enabled`로 정정.
- **마크다운 링크 칩(`3490:1485`)** — `size=M, state=focus`가 비어 매트릭스가 불완전했다(rules #7 위반). 빠진 조합을 채워 2×2 완성, 속성명을 `Size`/`State`로, 값을 `enabled`/`engaged`로 정규화. `focus`는 포커스 링이 아니라 배경이 진해지는 눌림 처리라 `engaged`가 맞았다.
- **`Markdown Block / Link Preview1`(`3806:1995`)** — State 2종(`enabled`/`engaged`) 추가.

### 함정

- **`combineAsVariants`는 currentPage 컨텍스트를 탄다** — `Grouped nodes must be in the same page as the parent`. 대상이 `✅ Components`(0:1)인데 currentPage가 `thumbnail`이었다. 스크립트가 원자적이라 파일은 무변경이었고, `setCurrentPageAsync`를 앞에 붙여 해결. 이후 모든 write 스크립트에 선행 호출을 넣었다.
- **`loadAllPagesAsync` 미지원** — 인스턴스 사용처를 전 파일에서 찾으려다 막혔다. 페이지별 `findAllWithCriteria`로 대체(`✅ Components` 1062개 조회, 링크 칩 인스턴스 0건 확인).
- **Dev Mode MCP 서버가 꺼져 있었다** — `mcp__Figma__*`가 전부 안내문만 반환. 플러그인 쪽 `mcp__plugin_figma_figma__*`로 우회했다.
- **세트 위치가 저 혼자 밀렸다** — `BottomSheet/ActionRow`를 x=715로 뒀는데 나중에 보니 813. 원인 미상이고 겹침은 없었지만 정렬이 깨져 사후 보정했다. **섹션 안 세트는 생성 후 bbox를 다시 검사하는 게 맞다.**
- **감사에서 걸러낸 것** — `ContextMenu/Item`·`Row/Item`이 고아였다. `Context Menu`(194:38)와 `Dropdown Menu`(194:50)는 이미 `Menu Item` 인스턴스로 갈아탄 뒤였다. 지시가 "다 해줘"였으니 State는 붙였지만, 이 사실을 먼저 보고하지 않았으면 안 쓰는 컴포넌트에 조용히 공수를 넣을 뻔했다.

## 회고

#### 설계 결정

- **`engaged` 통합은 문서가 이미 정해 둔 답이었다.** 피그마 실물(`Menu Item` 6종)이 rules #5를 어기고 있어서 "실물이 1차 기준"과 "문서 규칙"이 충돌했는데, 결론은 실물을 규칙에 맞추는 쪽이었다. 피그마 우선 원칙은 *디자인 의도*에 대한 것이지, 규칙 위반까지 승계하라는 뜻이 아니다.
- **`engaged` 색은 불투명이 아니라 알파로.** `Menu Item`의 hover가 쓰던 `surface/Inset`은 불투명이라 배경이 다른 곳에 얹으면 깨진다. `semantic/pressed/surface`(알파)로 통일해 시트·메뉴·칩 어디에 얹어도, 다크에서도 성립하게 했다.

#### AI 도구 활용

- **한 개 먼저 만들고 스크린샷으로 검증한 뒤 나머지를 돌린 게 맞았다.** `BottomSheet/ActionRow` 하나로 바인딩 헬퍼와 레이아웃 계산을 검증하고 나머지 3개는 같은 틀로 찍어냈다. 4개를 한 번에 돌렸으면 `combineAsVariants` 페이지 오류를 4배로 만났을 것이다.
- **`use_figma` 스크립트가 원자적이라는 점이 안전망이다.** 실패해도 파일은 무변경이라, 에러 메시지를 읽고 고쳐 재시도하는 루프가 파괴적이지 않다.
- **파괴적 작업 전에 역참조를 먼저 세었다.** `hover` variant를 지우기 전에 인스턴스 6개의 State를 조회해 0건임을 확인했다. 셌으니 지운 것이고, 안 셌으면 인스턴스가 깨졌을 것이다.

### 시안과 다르게 둔 것 3가지

1. **파란 primary 버튼 → DS Button `solid`(neutral)** — 브랜드 액센트 미확정이라 plan-19의 "새 화면은 semantic 토큰만" 원칙을 따랐다
2. **`!` 글리프 → `circle-alert`** — 맨 느낌표 아이콘이 세트에 없다. DS는 네트워크 전용 아이콘으로 `wifi-off`를 쓴다(Toast `Type=warning`)
3. **마스터 인스턴스가 아니라 파생 케이스** — `Modal / Dialog` 세트에 아이콘 슬롯도 center 정렬 축도 없다

### 함정

- **기획 시안을 먼저 확보하지 않았다.** "기획서에 네트워크 에러 팝업 있다"는 말만 듣고 기획서 텍스트(5.1·5.3)만 읽어 토스트/모달 3안을 제안했고, 모달 확정 뒤에도 텍스트 전용 DS 모달을 먼저 만들었다. 실제 시안은 아이콘 배지 + 가운데 정렬 + 재시도 횟수별 2케이스여서 만든 걸 지우고 다시 그렸다. **문서에 시안 이미지가 없는 항목은 시안 위치(Product 파일 노드 또는 이미지)를 먼저 물어보는 게 맞다.**
- **승인받은 마스터 축 추가를 중간에 멈췄다.** `Icon`·`Align` 축 추가를 승인받아 영향 범위 실측까지 갔다가(4개 페이지 인스턴스 0건) "기록만 해줘" 지시로 write 없이 종료. 오늘 첫 세션의 "패키지 계약 동기화 기록만" 과 같은 패턴이다 — 지금은 시안 확정이 먼저라는 판단.

- 마스터 속성을 복제(fills·effectStyleId·padding)하고 텍스트는 마스터 노드를 clone하면, 새로 그린 프레임도 텍스트 스타일·변수 바인딩을 유지해 다크 모드까지 자동으로 성립한다. 빈 프레임부터 그리는 것보다 정합 비용이 훨씬 싸다.

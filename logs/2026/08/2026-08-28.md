### 함정 모음

- **판정 코드가 틀리면 교차 검산도 같이 틀린다** — 제품 파일에 복사 버튼이 내려왔는지 세면서 `findAll(n => n.name === "Footer")[0]`을 썼다. Human 버블에는 Footer가 **두 개**(BubbleBox 안 숨김 · variant 직계 보임)인데 `[0]`이 숨은 쪽을 잡아 **224개가 전부 「없음」**으로 나왔다. 실제로는 224개 전부 정상 도달해 있었다. 더 나쁜 건 `importComponentByKeyAsync`로 게시본을 직접 가져와 「교차 검산」한 것도 **같은 `[0]` 로직**이라 같은 오답을 냈다는 점이다. 그 결과 「게시본 자체에 복사 버튼이 없다」는 결론까지 갔고 **주미님께 재게시를 두 번 요청**했다. 주미님이 「이미 반영되어 있는데」라고 짚어서야 잡혔다. **경로를 바꾸는 게 검산이 아니라 로직을 바꾸는 게 검산이다.**
- **`getPublishStatusAsync`는 양방향 모두 신뢰 불가다** — description을 실제로 바꾼 뒤에도 계속 `CURRENT`를 돌려줬다. 규칙 43-1이 「CHANGED여도 이미 내려와 있다」는 방향만 적고 있었는데 반대 방향도 성립한다. 다만 이번 사고의 뿌리는 이게 아니라 위 판정 코드였다.
- **정본·계약·주석이 셋 다 같은 말을 해도 낡았을 수 있다** — 「접히면 첨부도 숨긴다」가 기획서 §4.2·계약 md·캔버스 주석에 다 있어서 확정 결함으로 올렸는데, 첨부를 말풍선 밖으로 뺀 뒤로는 숨길 수 없다는 디자인 판단이 이미 내려져 있었다. 특히 주석의 「구 …는 폐기했습니다」 같은 문장은 **그 시점 기록**이지 현재 상태가 아니다.
- **인스턴스 이름·variant만 보고 대상을 고르면 입력창 칩과 스트림 칩이 안 갈린다** — 둘 다 `Attachment {Type=PDF}`다. 10MB 초과 컷을 만들다가 **이미 보낸 메시지의 첨부를 에러로 바꾸는 사고**가 났다. 부모 체인(`1342:732` = 메시지 버블 / `1925:5206;3625:1693` = ComposerGroup)으로 판별해야 한다. 원복 후 원본과 전수 대조해 확인했다.
- **게시 직전에 원본이 바뀔 수 있다** — 복사 버튼을 16×16 인스턴스로 넣었는데 주미님이 게시 전에 `copy` 32×32 프레임으로 감싸고 간격을 `size/8` → `size/4`로 줄이셨다. 이름도 `lucide:copy` → `copy`로 바뀌어서, 이름으로만 찾았으면 「사라졌다」로 오판할 자리였다. **게시 확인은 내가 쓴 값이 아니라 그 시점 실물로 다시 읽는다.**
- **캡션은 폭을 안 재고 놓으면 옆 캡션과 겹친다** — 컷 간격이 493인데 캡션을 880으로 만들어 옆 캡션과 물렸다. 컷마다 캡션을 달 때는 **컷 간격 안에 들어가는 폭**으로 잡는다.
- **경로 지정 커밋도 «같은 파일»이면 못 막는다** — `git add <파일 하나>`만 했는데도 옆 세션 변경이 딸려 갔다. 커밋 전 `git diff --stat`이 12/1이었는데 커밋 결과는 16/3이었다. 새는 구간은 「diff를 읽은 시점 → `add`가 실행되는 시점」이고, `add`는 내가 본 diff가 아니라 그 순간의 파일 전체를 담는다. **커밋 직후 `git show --stat`을 직전 `git diff --stat`과 대조**하면 잡힌다. 이 로그 파일 자체도 같은 이유로 한 번 덮어썼다가 `git checkout HEAD --`로 되살려 병합했다 — 옆 세션이 먼저 쓴 파일에 `cat >`를 쓴 것이다.
- **중첩 부품의 마스터 변경은 그것을 품은 세트의 「변경됨」으로 승격되지 않는다** — 게시 창과 제품 파일 양쪽에 「업데이트할 것 없음」이 떴다. DS 안에서는 `Bottom Sheet`의 헤더가 이미 새 값인데 세트 상태가 `CURRENT`라 게시 목록에 안 뜨고, 소비 파일은 옛 스냅샷에 묶인다. 세트 description을 갱신해도 `CHANGED`가 되지 않았다.
- **count만 보고 일괄 적용하면 안 된다** — Setting의 「20px 69곳」 중 진짜 제목은 모달 9개였다. 나머지 60곳은 OTP 숫자 42 · 아바타 이니셜 11 · 워드마크 7이었다. 부모 인스턴스 이름으로 묶으면 한 번에 갈린다.
- **「스타일 미적용」이 DS 잘못이라고 단정하지 말 것** — 이번엔 DS가 멀쩡하고 화면이 덮어쓴 경우였다. 마스터를 먼저 읽어서 DS 수정·게시라는 큰 경로를 피했다.
- **게시 후 슬롯 이름이 바뀐다** — 판정 코드가 `name === 'Header'`로 찾다가 「헤더 없음」을 냈다. 수락되면서 슬롯 이름이 마스터 이름(`Sheet/Header`)으로 갱신된 것이었다.
- **스타일 id는 접미를 떼고 비교한다** — 제품 파일의 원격 스타일 id는 `S:d6b9…,5349:1`처럼 인스턴스 접미가 붙는다. DS에서 읽은 id(`S:d6b9…,`)와 문자열 그대로 비교했더니 「스타일이 다르다」로 SKIP돼 첫 시도가 통째로 막혔다. `String(id).split(',')[0]`으로 가른다. **적용할 때도 DS의 id를 쓰지 말고 같은 파일에서 그 스타일을 이미 쓰는 노드의 id를 재사용**하면 import 없이 붙는다.
- **「web은 28」 같은 값을 카드 폭 안 보고 옮기면 깨진다** — DS `Modal Shell`이 28을 쓰는 근거는 **폭 400 카드**였는데, 게이트의 제목 상자는 344라 28에서 잉크가 360이 되어 두 줄로 접힌다. 26도 여유 10px뿐이라 한 글자만 늘면 접힌다. **「web이니까 28」이 아니라 「이 카드 폭에서 몇 줄인가」로 판정한다.**
- **규격 보드를 못 찾으면 같은 내용을 두 벌로 쓰게 된다** — 오버레이 폭을 판단하면서 DS `➡️ Guidelines`의 레이아웃 규격 보드를 몰라 컴포넌트 설명만으로 답했다. 하필 `rules.md`에 같은 규격을 새로 쓰던 중이라 두 벌이 될 뻔했다. 주미님이 「레이아웃 룰 없니?」로 링크를 주고서야 알았다. 규칙 51을 **값 없이 포인터로만** 세우고 `AGENTS.md` 색인에 넣었다.
- **보드에 적혀 있다고 맞는 건 아니다** — `LAYOUT 04_Overlay`가 「Modal 400 · Dialog 660」 2단으로 적고 있었는데, 실측하니 확인 팝업 320이 **30곳** 있는데도 표에 없었고 `Dialog 660`은 **실물 0개**였다. **보드의 `Dialog`는 「웹에서 결정을 막는 오버레이」라는 형태 분류이고 컴포넌트 `Modal / Dialog`와 단어만 같다** — 이름으로 이어 붙이면 오판한다.
- **⚠ 규칙이 있는데도 같은 게이트에서 이틀 만에 반복했다 — 「감사」로만 읽고 「고치기」에 안 걸었다.** web 게이트 제목을 `✅ chat/report`에서 한 곳 고치고 **「대상은 이 1곳」이라고 보고**했는데, `➡️ Login`의 v1.0.9 수단 판(`10906:13126`)이 28로 남아 **두 줄로 접혀 있었다.** 주미님이 화면을 보고 잡으셨다. 규칙 **44-5(페이지를 범위 경계로 삼지 않는다)**에 **8/26 사례로 같은 게이트가 이미 적혀 있었다.** 안 걸린 이유는 그 항이 「문구·컴포넌트 **감사**는」으로 끝나서다 — 나는 감사 중이 아니라 「판정된 결함 하나를 고치는 중」이라고 생각했다. **결함을 고치는 것도 그 결함의 전수를 세는 일이다** — 하나만 고치면 나머지는 「안 고친 것」이 아니라 **「고친 것과 어긋난 것」**이 되어 드리프트가 는다. **순서를 뒤집어 고치기 전에 센다**(44-5-1 신설 · 색인 추가 · PR #306). 뒤늦게 세니 `Modal Shell` 제목은 Login 75곳 · chat/report 4곳이고 접힌 것은 1곳뿐이었다 — **세고 나서야 「1곳」이 사실이 됐다.**

#### 설계 결정

- **접힘에서 첨부를 숨기지 않는다** — 첨부를 말풍선 밖으로 뺀 이상 함께 숨길 수가 없다(주미님). 정본 §4.2와 갈리므로 정본은 고치지 않고 계약 md·캔버스 주석에 ※로 적어 PM 통보 대상으로 남겼다.
- **질문 버블 복사는 시각 줄 오른쪽에 둔다** — AI 답변은 액션바가 버블 아래 왼쪽에 있고 사용자 버블은 오른쪽 정렬이라 대칭이 맞는다. 터치 영역은 코드가 아니라 **피그마에서 32×32로 잡는다**(주미님 조정). 아이콘만 16으로 두면 여백이 없어 액션바와 어긋난다.
- **안전 안내 컷은 문구가 아니라 화면 구성을 정한다** — 답변 정책은 시스템 프롬프트의 근거이고 실제 문장은 AI가 쓴다(주미님 「어차피 AI가 답변하는 거구나」). 그래서 이 컷이 말하는 것은 「액션바와 주의 문구는 일반 답변과 같고 출처 칩만 빠진다」로 좁혔다.
- **홈 투자 칩만 DS 기본값을 쓰고 있었다** — 커리어·대인관계는 제품 파일 override로 라벨을 넣어 뒀는데 투자만 마스터 기본값이 내려와 v1.0.6 예시에 멈춰 있었다. 같은 방식(override)으로 맞춰 DS write와 게시를 피했다. **DS 마스터 기본값은 아직 옛 예시라, 새 `QuickStart/Group`을 놓으면 「목돈 고민」이 다시 나온다.**
- **네트워크 모달은 web 컷이 필요 없다고 판단했다** — SA-1 게이트가 web 컷을 가진 이유는 모바일 바텀시트 → web 센터 모달로 **표면이 갈리기 때문**인데, 네트워크 모달은 모바일에서 이미 센터 모달이다. 남은 건 폭 결정뿐이다.
- **시트의 닫기는 헤더 층이 담당한다** — DS 마스터 설명에 이미 적혀 있던 계약을 화면이 안 따르고 있었다. 본문에 얹은 44 히트영역을 걷고 `Sheet/Shell`의 `header=on`을 켰다.
- **아이콘 정렬선은 16이 아니라 24다** — 같은 16인데 토스트는 안 답답하고 시트는 답답한 이유가 컨테이너 폭이었다. 토스트는 폭 344 카드라 화면 끝에서 41px 떨어지고, 시트는 화면 폭을 다 써서 잉크 16이 곧 화면 끝 16이 된다.

## 오버레이 폭을 정하다가 규격 보드를 찾았다

오늘 마지막 미해결이던 「네트워크 모달 web 폭 결정」에서 시작해, 모달 타이포 세 건과 규칙 하나로 번진 트랙이다.

### DS `Modal / Dialog` 제목 22 통일 — 승인받아 실행했다가 철회했다

plan-44에 이관돼 있던 항목이다. 착수 전 전수 실측에서 범위가 달라졌다 — **plan-44는 「Setting 9곳」이라 적었지만 실제로는 4페이지 30곳**(Setting 13 · Login 9 · chat/report 6 · home/history 2, 다크 목업 +3)이었고, 30곳 전부 제목이 `heading/2` 정상 바인딩에 **override가 0**이라 마스터 수정 + 게시 한 번이면 따라올 상태였다. 제목 15종을 22px로 재보니 박스 280 안에서 전부 한 줄이었다(최장 254px).

승인받아 마스터 6개 variant를 `heading/1`로 올렸고 검증(한 줄 유지 · 카드 +3px · 변수 바인딩 생존)까지 통과했다.

```
아.. 근데 미안 얘네랑 걔는 역할이 달라서 ㅠㅠ 얘는 내가 시각보정 해둔건데..
페이지,바텀시트에서의 타이틀 디스크립션이랑 팝업에서의 역할은 다른거자나 ㅠㅠ
```

**게시 전이라 전수 복원했다.** 제품 파일 영향 0이다. 착수 전 실측은 버리지 않고 plan-44에 남겼고, 「제목 22 · 부연 16」 기준 불릿에 **적용 층위는 화면·시트**라고 명시해 다음 세션이 같은 제안을 반복하지 않게 했다. DS 마스터 description에도 근거를 한 줄 넣었다.

### `Modal Shell` 게시 판정 — 28이 아니라 24였다

게시 후 web 게이트 제목이 28로 내려왔는지 쟀다. **안 내려왔는데 원인이 게시가 아니었다** — DS 마스터는 variant 둘 다 28로 정상인데 소비 인스턴스가 스타일을 덮어쓰고 있었다. 게시를 반복해도 안 바뀌는 자리다.

**그런데 28을 그대로 내리면 두 줄로 접힌다.** 제목 상자가 344인데 28px 잉크가 360이다. 크기별로 22→283 · 24→308 · 26→334 · 28→360이라 26조차 여유가 10px뿐이다.

```
28로 너무 커지는건 아냐?
```

주미님이 24를 골라 `heading/web-2`를 적용했다. 부연도 이 web 판만 자동 줄바꿈이라 `있어요`가 셋째 줄로 떨어져 있어서, 모바일 기준 판과 같은 위치(`전문가들에게 \n제한`)로 고정했다. 세 줄이 두 줄이 됐고 카드 높이는 372 그대로다.

같은 문구를 쓰는 나머지 4곳은 대상이 아니다 — 잠금 안내 3곳은 14px 한 줄이고, 사본 1장은 별개 화면이다.

### `Chat Input Bar/1line/filled` — 고아 해소

주미님 게시 후 확인하니 `✅ Components`의 `계약 제외` 섹션에 정상으로 붙어 있다. **DS 고아 0건**이다.

### 「코드 잔무」로 적혀 있던 둘은 아니었다

- **`Callout` action 정렬은 코드 버그가 아니다.** 마스터 3종을 재니 제목 x=40 · 보조 설명 x=12로 **피그마가 그렇게 그려져 있고 코드가 그대로 옮긴 것**이었다. 코드만 고치면 오히려 어긋난다 — **DS write + 게시 + 수락**이 따라오는 디자인 결정 묶음이다.
- **리포트 히어로 360 대응은 상수 한 줄이 아니다.** `CONTENT_W`가 막대 폭·버블 좌표·컨테이너 셋에서 쓰이고, 321은 **393에서 역산한 값**이라(361 − 40) 동적으로 바꾸려면 런타임 폭 측정과 모션 엔진 좌표계까지 걸린다. **모션이 바뀌므로 시각 QA가 필요하다.**

### 함정 모음

- **web 설정 2depth는 설정 모달 안에 그려진다 — 모바일 전체 화면과 값을 직접 비교하면 오진한다** — 해지 안내 화면에서 머리 문장이 모바일 22 Medium, web 16 Medium인 것을 「같은 역할인데 위계가 없다」고 봤고, 모바일 불릿을 감싸는 흰 카드가 web에 없는 것을 결함으로 봤다. **둘 다 틀렸다.** web은 1440 캔버스 한가운데 뜬 설정 모달 안이라 폭이 좁고, 모달이 이미 흰 면이라 안에 카드를 또 넣으면 면이 두 겹이 된다. 주미님이 「애초에 둘이 UI가 다르잖아」라고 짚어 주셔서 알았다. 컷 이름에 `web /`가 붙어 있어도 렌더를 한 장 보고, 텍스트 실측에 **화면에 없는 1depth 문구가 섞여 잡히면** 모달 뒤에 가려진 화면이 있다는 신호다. 메모리 `reference_web_settings_2depth_lives_inside_a_modal`.

### 회고 및 인사이트

#### 설계 결정

- **숫자만 적은 보고가 오해를 만들었다.** 어제 「web 16 Medium, 모바일 22 Medium」만 적어서 같은 자리인데 값만 다른 것처럼 읽혔다. 주미님이 「왜 사이즈가 다르냐」고 물어 재보니 web 사다리 전체가 한 단 작았고, 「시각물 보여 달라」는 요구에 렌더를 띄우니 그제야 카드 유무라는 더 큰 차이가 보였다. **값을 적을 때는 그 값이 속한 사다리를 같이 적고, 시각 판정은 렌더를 먼저 띄운다.**
- **비교 대상을 플랫폼 건너로 잡으면 안 된다.** 판단 근거는 같은 플랫폼·같은 층 화면에서 나온다. web 설정 2depth 세 화면(「내 정보」 `11169:47189` · 「정보」 `11183:13664` · 해지 안내 `13828:6671`)을 재니 그룹 제목 14 SemiBold · 목록 행 16 Regular로 일치했고, **안내 문장이 놓이는 자리는 해지 안내 화면 말고 없다**는 것도 그때 알았다. 기존 값이 없으니 「어긋났다」고 말할 근거 자체가 없었다.

## web 해지 안내의 머리 문장은 16 Medium 그대로 두기로 했다 (prism PR #1078)

어제 web 안내 화면 두 컷(`13828:6671`·`13842:6671`)에 머리 문장을 넣으면서, 시각 값을 임의로 정하지 않으려고 아래 질문 노드를 `clone()`해 문자열만 바꿨다. 그래서 머리 문장이 질문과 같은 16 Medium이 됐고, 모바일(22 Medium)과 달라서 「플랫폼 사이 위계 차이가 남아 있다」고 주미님 판단으로 올렸다.

오늘 그 판단이 닫혔다. **web 설정 2depth는 설정 모달 안이고 모바일은 전체 화면이라, 값을 직접 비교할 수 없다.** 모달 폭이 좁고 내용이 짧아 22를 쓸 자리가 아니고, 렌더로 보면 16 Medium이 본문 14 Regular와 크기·굵기로 갈려서 맨 위 안내로 읽힌다.

- 실측: web 설정 2depth 세 화면 모두 그룹 제목 14 SemiBold · 목록 행 16 Regular. 안내 문장 자리는 해지 안내 화면에만 있다.
- 렌더 확인: `13828:6671` 한 장. 텍스트 실측에 잡혔던 「약관 동의 관리」·「마케팅 정보·메일 수신」은 모달 뒤 1depth라 화면에 없다.
- **피그마는 건드리지 않았다.** `docs/plans/87` K절 문서만 고쳤고 PR #1078로 머지했다.

해지 계열 여섯 컷은 이제 열린 항목이 없다.

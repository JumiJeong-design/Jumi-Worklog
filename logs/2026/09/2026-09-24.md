### 회고 및 인사이트

#### 설계 결정

- **숫자만 적은 보고가 오해를 만들었다.** 어제 「web 16 Medium, 모바일 22 Medium」만 적어서 같은 자리인데 값만 다른 것처럼 읽혔다. 주미님이 「왜 사이즈가 다르냐」고 물어 재보니 web 사다리 전체가 한 단 작았고, 「시각물 보여 달라」는 요구에 렌더를 띄우니 그제야 카드 유무라는 더 큰 차이가 보였다. **값을 적을 때는 그 값이 속한 사다리를 같이 적고, 시각 판정은 렌더를 먼저 띄운다.**
- **비교 대상을 플랫폼 건너로 잡으면 안 된다.** 판단 근거는 같은 플랫폼·같은 층 화면에서 나온다. web 설정 2depth 세 화면(「내 정보」 `11169:47189` · 「정보」 `11183:13664` · 해지 안내 `13828:6671`)을 재니 그룹 제목 14 SemiBold · 목록 행 16 Regular로 일치했고, **안내 문장이 놓이는 자리는 해지 안내 화면 말고 없다**는 것도 그때 알았다. 기존 값이 없으니 「어긋났다」고 말할 근거 자체가 없었다.
- **「전부 지워 달라」는 요청에서 남길 것을 갈랐다.** QA는 「서비스 전반 툴팁 제거」였지만 툴팁은 두 종류였다. 컨트롤 이름(`label`)은 키보드 접근성용이라 hover·클릭에 뜰 이유가 없었고, 설명(`bubble`: 첨부 오류 사유·삭제 불가 안내)은 그 자리 말고 읽을 곳이 없다. 앞쪽만 끄고 뒤쪽은 남기되, 답글에 「이것도 없애길 원하면 말해 달라」를 적어 되물을 자리를 열어 두었다.
- **레일 넷은 예외를 두지 않았다.** 접힌 레일은 보이는 글자가 없어 hover 툴팁이 마우스 사용자에게 유일한 이름이었지만, 넷 다 관용 아이콘이고 한 규칙에 예외를 두면 다음 사람이 규칙을 못 읽는다. 이름이 필요해지면 툴팁을 되살리는 게 아니라 그 컨트롤을 다시 본다.

## 툴팁 「서비스 전반 삭제 검토」 — 역할 툴팁을 키보드 포커스에서만 열도록 고쳤다 (board #111 · prism 3.5.0)

`docs/plans/108-tooltip-label-keyboard-only-2026-09.md`가 정본이다.

QA 이슈 board #111(김근영)이 「패널 hover·모바일 탭에 툴팁이 뜬다, 전반 제거」를 올렸다. 첨부 두 장은 PC 사이드바의 「히스토리 패널 접기」와 행 「더보기」였다.

주미님 판단: 「툴팁을 넣었던 이유가 키보드로 동작했을 때 접근성을 위해서였는데, 마우스를 쓰는 사람에게도 과하게 다 뜨는 것 같다.」 → 「가장 나은 판단을 해줘봐」.

**원인은 둘이었다.** `Tooltip.tsx`의 focus 경로가 `:focus-visible`이 아니라 그냥 `focus`라 마우스 클릭에도 떠서 포커스가 빠질 때까지 남았고, plan-75(9/10)가 아이콘 버튼 23곳에 `Type=label` 역할 툴팁을 붙일 때 hover 경로를 그대로 두었다. 「모바일 탭」은 board #59에서 `riiid/prism#940`(2.4.0)으로 이미 막았고 프론트가 3.3.0을 쓰고 있어 들어가 있었다.

**`type="label"`(컨트롤 이름)은 키보드 포커스에서만 연다.** `isKeyboardFocus()`가 focus 대상의 `matches(":focus-visible")`로 가르고, `label`은 hover로 열지 않는다. inline이어도 `data-open`을 늘 내려 CSS `:hover`·`:focus-within` 규칙에서 빠진다. `bubble`과 controlled 경로는 그대로다. 계약·DS 문서(tooltip · button · accessibility)·스토리 설명·changeset(minor)까지 같이 갔다.

**실물은 크로미움으로 잰다.** 스토리북 정적 빌드를 Playwright로 열어 계산된 `display`를 셌다. `LabelType` hover 0 · 클릭 0 · Tab 1 · Esc 0, `Default`(bubble) hover 1, `ChatHistoryPanel` 접기 hover 0 · 클릭 0 · 레일 hover 0 · Tab 1. 스크립트는 prism `.claude/scratch/tooltip-label-keyboard-check.mjs`.

PR #1086 머지 → 릴리스 PR #1066 `chore: 3.5.0` 머지 → `publish-latest`·`request-stable-update` 성공. 3.5.0에는 다른 세션의 브랜드 띠 색·ModeToggle 띠·`action.primary` 다크 두 칸도 함께 실렸다. board #111에 답글(comment 5807710755)을 달았고, plan-108을 종결했다(PR #1088).

보드도 맞췄다. 주미님 승인 뒤 DS `➡️ Guidelines` Accessibility 보드 F 절(`7118:4`)에 「이 역할 툴팁은 키보드 포커스(:focus-visible)에서만 뜨고 hover·마우스 클릭에는 뜨지 않는다」 문장을 넣었다(높이 51→68, 렌더로 겹침 없음 확인). plan-108 열린 항목 0(PR #1090).

## 탈퇴 흐름 Stepper는 양쪽 갈래 다 2단계였다 (prism PR #1083)

`plan-86`의 남은 세 항목을 닫았다. 기획서 v1.0.11 §3.1.6(회원 탈퇴)을 피그마 컷·계약 문서와 맞대는 일이었다.

**계약이 적던 「튜터 이력이 있으면 3단계」가 낡은 서술이었다.** `packages/prism/component-contracts/stepper.md`는 갈래에 따라 3단계(갈래 선택 → 본인 인증 → 확인)와 2단계로 갈린다고 적고 있었다. 두 축으로 재니 둘 다 아니었다.

- 기획서 v1.0.11 §3.1.6이 「갈래 선택 팝업은 두지 않는다. 사용자가 고르는 것이 아니라 상태에 따라 결정되므로, 무엇이 일어나는지만 정확히 알리면 된다」로 못박고 있다.
- 제품 파일 10페이지 INSTANCE 45,561개 전수에서 `Stepper` 인스턴스는 11건이고 **전부 `Steps=2`**다. `Steps=3`과 `Steps=4`는 0건이다. 서브에이전트 집계라 샘플 셋(`11111:104`·`13772:6701`·`11539:140143`)을 REST로 직접 열어 교차검증했고 값이 일치했다.

화면 수는 갈래마다 다르지만(① 탈퇴 4장 · ② 해지 5장) Stepper가 세는 단계는 양쪽 다 둘이다. 덤으로 계약에 없던 사실을 하나 찾았다. ② 해지의 인증 전 화면(`13772:6725`)과 안내 팝업(`13772:26139`)은 Stepper 인스턴스가 스스로 `visible=false`다.

## 로고 모델 링을 agent와 합치고, stroke override 47건을 실측해 plan-100을 닫았다 (prism PR #1084 · #1085 · #1089)

`plan-100`에 「주미님 판단 대기」로 걸려 있던 셋을 전부 닫았다. 오늘 열린 항목은 0이다.

**다크에서 링이 안 보이던 이유는 색이 배경과 같아서였다.** `Model Profile`의 로고 모델(Claude·GPT·Gemini·Grok·Perplexity) 30 variant가 `neutral/100`을 물고 있었는데, 그 다크 값 `#27282B`가 시트 배경색과 정확히 같았다. 라이트에서는 `#EAEDF2`로 보이니까 값만 읽어서는 못 잡고, 다크 실물을 렌더해야 드러난다. `agent` 아홉이 이미 쓰던 `semantic/border-default`로 옮겼다. 라이트는 `#D9DCE2`로 한 칸 진해지고 다크는 `#46474A`가 된다. 코드 토큰 `model-profile/ring`도 `{color.border.control}`로 같이 옮겼다(PR #1084).

**「47건이 옛 그라디언트로 남는다」는 서술이 틀렸다.** `plan-100`은 「stroke를 덮어쓴 47건은 마스터를 고쳐도 옛 그라디언트로 남습니다」를 판단 대기로 걸어 두고 있었다. Plugin API로 표본 여섯을 되읽으니 **47건 전부 현재 마스터와 같은 값**이었다. `Deep=On` 32건은 `GRADIENT_ANGULAR` 스타일 그대로이고, `Deep=Off` 15건은 이미 `semantic/border-default`로 옮겨져 있었다. 다크에서도 `#46474A`로 모드를 따라간다.

원인은 **스캔 json이 스냅샷이라는 점**이다. 09-23 스캔이 `styleName: gradient/brand`를 적었는데, 같은 날 저녁 「띠를 가르는 축」 작업이 마스터와 인스턴스를 함께 회색으로 옮겼다. `overriddenFields`는 그대로 남지만 값은 따라 움직였다. 걷어내지 않고 그대로 두기로 했고, 「다음에 `Mode Toggle` 마스터 stroke를 고치면 47건도 같은 턴에」라는 조건만 절로 남겼다(PR #1089).

### 함정 모음 (링 트랙)

- **`overriddenFields`는 「덮어썼다」는 이력이지 「지금 다르다」는 뜻이 아니다.** override가 걸려 있으면서 값이 마스터와 같은 상태가 정상적으로 존재한다. 감사표의 count를 결함 수로 옮겨 적기 전에, 표본 몇 건의 실제 paint와 마스터 variant의 paint를 나란히 읽는다.
- **`fields`가 `fills`인 건은 stroke 얘기가 아니다.** 같은 문서가 stroke override 47건에 fill override 24건을 더해 「71건」으로 세고 있었다. 성격이 다른 둘을 합산한 수다.
- **Chromatic 쿼터 소진은 `pending`으로만 보인다.** `gh pr checks`로는 구분이 안 되고, `gh api repos/<owner>/<repo>/commits/<sha>/status`의 `description`에 "Update your plan to resume testing"이 뜬다. 기다려도 영원히 안 끝나니 백그라운드 대기를 멈춰야 한다. 스토리북 게시는 따로 성공하므로 육안 확인 경로는 살아 있다.
- **서브에이전트가 「`instance.overrides`가 빈 배열을 준다」고 보고했는데 사실이 아니었다.** 표본 전부에서 `overriddenFields: ["strokeStyleId","strokes"]`가 정상으로 나온다. 그 보고는 판정 기준을 바꿔 7건이라는 수를 냈고, 어제 수치와 비교할 수 없는 값이었다.

## 커밋 게이트를 머지 인식형으로 고치려다, 이미 끝나 있는 것을 확인하고 빈틈만 실측했다

앞 세션에서 「`scripts/check-unfounded-claims.sh`를 머지 인식형으로 고치자」는 항목을 넘겨받아 착수 승인까지 받았는데, **착수 전에 재 보니 2026-09-23에 이미 반영되어 있었다.** 스크립트 32행에 머지 상황을 감지해 검사를 건너뛰는 줄이 있고, 같은 성격의 `scripts/check-story-style.sh` 39행에도 동일한 처리가 들어가 있다. plan-55 §9가 이 작업을 완료로 서술하며 그 문서에 열린 항목은 하나도 없다. **코드는 건드리지 않았다.**

AGENTS.md가 경고하는 「낡은 항목은 착수 전에 다시 잰다」에 정확히 걸린 사례다. 승인을 받았다는 사실이 「할 일이 남아 있다」는 근거가 되지 못한다.

수정이 어디까지 유효한지는 임시 워크트리를 만들어 직접 시험했다. 검사에 걸리는 문장을 담은 파일로 네 경우를 돌렸다.

| 상황 | 검사 동작 | 판정 |
| --- | --- | --- |
| 평소 커밋 | 막음 | 의도대로 작동한다 |
| `git cherry-pick` | 검사가 실행되지 않음 | 빈틈이 아니다 |
| `git merge` 후 커밋 | 건너뜀 | 수정이 작동한다 |
| `git merge --squash` 후 커밋 | 막음 | 빈틈이지만 이 저장소 관례가 아니다 |

`git merge --squash`는 머지 상태를 나타내는 표식을 남기지 않아서 검사가 평소 커밋으로 본다. 다만 이 저장소는 깃헙의 squash 머지를 쓰기 때문에 로컬에서 그 명령을 쓸 일이 없어, 지금 막고 있는 것이 없다고 판단해 고치지 않았다.

**`git rebase`는 확인하지 못했다.** `shared-tree-guard.sh` 훅이 작업 폴더를 지정하는 `-C` 옵션을 읽지 못하고 현재 디렉터리만 보기 때문에, 격리한 워크트리를 대상으로 삼아도 공유 폴더 작업으로 오판해 막았다. 안전한 방향의 오탐이라 사고로는 이어지지 않지만, 워크트리 작업이 불필요하게 막힌다. 시험용 워크트리와 브랜치는 모두 지웠고 원격에는 아무것도 올리지 않았다.

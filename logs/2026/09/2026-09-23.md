| `socra-code-traps` 스킬 | 스토리북·CSS·헤드리스 렌더 판정 함정 | 25 |
| `MEMORY-archive.md` | 결론이 나서 다시 판단할 일이 없는 제품 결정 | 44 |

**무엇을 옮길지는 「트리거가 분명한가」로 갈랐다.** 피그마·스토리북·CSS는 그 일을 시작할 때 스킬 설명이 걸린다. 반대로 토큰·색·대비는 피그마 작업 중에도 코드 작업 중에도 걸려서 어느 쪽에도 확실히 속하지 않아 색인에 남겼다. 주미님 지시(`feedback_*`)와 커밋·워크로그·날짜처럼 어떤 일에든 걸리는 것도 남겼다.

**날짜로 고르려다 되돌린 것이 다섯 건이다.** 제품 원칙·웹 퍼스트·JP 출시 방침·유즈케이스는 적은 지 오래됐어도 매번 판단에 쓰인다. 아카이브 후보를 49개에서 44개로 줄였다.

**스킬은 사용자 레벨(`~/.claude/skills/`)에 뒀다.** 레포의 `.claude/skills`는 `../skills`로 가는 심볼릭 링크라 커밋 대상인데, 내용이 이 머신에만 있는 메모리 경로를 가리켜서 남에게는 깨진 링크가 된다. 같은 이유로 `.claude/rules/`의 경로 스코프도 안 썼다.

결과는 **25,590바이트 316줄에서 13,708바이트 89줄**이다. 25KB의 55%, 200줄의 45%로 여유가 생겼다. 기록은 한 건도 안 지웠고 파일 317개가 그대로 있다. 검산은 171+44+78+25=318에서 머리말의 아카이브 링크 1을 빼면 파일 수와 맞고, 중복 등재 0건·어느 색인에도 없는 파일 0건·깨진 링크 0건이다. 방법과 검산은 메모리 `reference_memory_index_25kb_byte_limit`에 적었다.

**남은 리스크는 스킬이 안 열릴 수 있다는 것이다.** 색인과 달리 스킬은 관련 있다고 판단될 때만 로드된다. 그래서 설명에 「피그마 파일을 읽거나 고치기 전에」처럼 상황을 구체적으로 적고 `MEMORY.md` 머리말에도 가는 길을 한 줄씩 남겼지만, 판단이 빗나가면 못 본다. 한동안 쓰면서 안 열리는 상황이 있는지 봐야 한다.

## 해지 화면 여섯 컷의 문구를 기획서 ② 열로 맞췄다 (prism PR #1070)

`plan-87` K절이 「본문이 기획서와 통째로 다른데 무엇이 어떻게 다른지는 아직 대조하지 않았다」로 열려 있었다. 대조를 끝내고, 주미님 승인을 받아 피그마까지 고쳤다.

**항목에 적힌 범위가 틀려 있었다.** 「web 두 장」으로 돼 있었는데 `0916 탈퇴 및 해지` 섹션(`13803:115810`)의 자식을 세어 보니 **여섯 장**이다. 모바일 세 장과 web 완료 팝업이 더 있었다. 규칙 44-5-1이 말하는 경우로, 둘만 고치면 나머지 넷이 어긋난 것이 된다.

**가장 무거운 어긋남은 「대화 그대로 돌아와요」였다.** 기획서 §3.1.4가 「재동의해도 해지 이전 세션은 복원하지 않는다 · 신규 가입자와 동일하게 빈 목록에서 시작한다」로 정하고, §3.1.6 표 아래가 「되살릴 수 있다고 오해하게 쓰지 않는다」로 못 박는다. 화면 문구가 정확히 그 오해를 만들고 있었다. 나머지는 완료 팝업 제목·본문, 안내 화면의 「30일 이내」(어제 #1068에서 ① 열만 7일로 고칠 때 ② 열이라 범위 밖이었던 자리), web 안내 화면의 순서였다.

**텍스트 노드 14개를 고쳤고, web 두 컷에는 머리 문장 노드를 새로 만들었다**(`14845:16092`·`14845:16093`). 여섯 컷을 모두 렌더해 육안으로 봤다. 본문이 48자에서 141자로 늘어난 팝업도 잘리거나 밀리지 않았고, web 두 컷의 순서는 모바일 `13772:6720`과 「머리 문장 → 불릿 셋 → 질문 → 버튼」으로 같아졌다. 되돌릴 옛 문구는 `.claude/scratch/figma-cancel-copy-rollback-2026-09-23.json`에 남겼다.

**막혔다가 풀린 자리가 하나 있다.** 기획서 ② 열 팝업이 「채팅 내역이 모두 삭제되며」인데 §3.1.4는 「해지해도 계정과 데이터는 그대로 보관한다」라 서로 어긋나 보였다. 「기획서가 틀렸다」고 보고할 뻔했는데, 표 바로 아래에서 기획서가 스스로 설명하고 있었다 — 「갈리는 것은 셋뿐이다」, 「겪는 결과가 다르지 않아 골격을 공유한다」. ② 열의 「삭제」는 내부 데이터가 지워진다는 뜻이 아니라 **사용자가 겪는 결과**를 말한다. 주미님 「너가 헷갈린 건 아닌지 다시 잘 검토해 봐」가 없었으면 그대로 올렸을 자리다.

**머리 문장의 시각 값은 내가 정하지 않았다.** web에 없던 노드를 새로 만들어야 했는데 크기·굵기·색을 고르는 대신 같은 화면의 질문 노드를 `clone()`해서 문자열만 바꿨다. 그래서 web 머리 문장은 16 Medium이고 모바일은 22 Medium이라 **플랫폼 사이의 위계 차이가 남아 있다.** 이 값을 맞출지는 주미님 판단으로 `plan-87`에 적어 두었다.

덤으로 안내 팝업의 `취소` 강조가 이미 맞아 있는 것을 렌더에서 확인해 미측정 항목 하나를 닫았다. `plan-87` K절에 열린 항목은 이제 없다.

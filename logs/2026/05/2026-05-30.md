## 회고 및 인사이트

### AI 도구 활용

- **컨텍스트 자동화는 협업 퀄리티를 바꾼다** — CONTEXT.md가 SessionStart에 자동 로드되면 새 세션도 이전 결정 맥락을 즉시 파악. "왜 이렇게 결정했나"가 없으면 매번 재설명 비용 발생.
- **MCP 도구의 한계를 알아야 우회책이 보인다** — "왜 2개만 보여?" → Plugin API 특성 → REST API 필요 → FIGMA_TOKEN → 네트워크 정책 순서로 추적해야 해결됨.
- **워크로그 기록 ≠ main 상태** — 워크로그에 "했다"고 적혀도 그 커밋이 main에 남아있다는 보장이 없음(orphaned 가능). 커밋 SHA는 반드시 도달 가능성을 검증해야 신뢰 가능. git은 orphaned 커밋도 한동안 보관하므로 SHA만 알면 복구 가능하다.

### 설계 결정

- **검증 루프 없는 빌드 트랙은 반쪽** — PMF는 빌드만으로 못 찾음. Build track + Learn track 동시 운영 필수.
- **Japan-First는 로컬라이제이션이 아니라 설계 기준** — 일본을 초기 설계 기준으로 삼아야 현지화 비용 최소화.
- **토큰 네이밍은 디자인-코드 간 계약** — `color-text-secondary` 같은 semantic 이름만 유효. 3레이어: Primitive → Semantic → Component.
- **일본어 폰트는 일관성 vs 친숙도 트레이드오프** — Pretendard JP(한국어와 같은 패밀리, 일관성↑) vs M PLUS 2(일본어 네이티브, 친숙도↑). Japan-First 원칙상 일본 사용자 체감을 1순위로 실제 렌더링 비교 후 결정.

## Figma↔코드 토큰 드리프트 감사 도구 (read-only 루프 1단계)

### 요청 범위

yozm 글("제가 정말 루프 엔지니어링까지 알아야 할까요?") 논의에서 출발. 우리 셋업(prism)에서 **루프화 가능한 게 있는지 검토** → 잘 가고 있는지 확인 → 후보 중 드리프트 감사를 read-only 루프로 1단계 구현.

### 검토 결론 (루프화 후보)

- prism은 검증·시각회귀가 이미 CI(`release.yml`)로 루프화돼 있고, 피그마 시각 변경은 승인 게이트로 사람이 잡는 구조 = 글이 말한 "잡기 싼 층은 자동, 비싼 taste 층은 사람"에 이미 부합.
- 빈틈은 **Figma↔코드 토큰 드리프트 감사**뿐 — 수동이라 드리프트가 조용히 쌓였다 뒤늦게 발견되던 지점(과거 4건). read-only라 승인 게이트와 안 부딪힘 → 여기만 루프화.

### 완료 (riiid/prism, 브랜치 `plan/parallel-codex`, 로컬 미커밋)

- **추가물** — `scripts/figma-token-drift.mjs`(감사), `design-system/sync/figma-variables.snapshot.json`(Figma side 실데이터), `design-system/sync/figma-token-drift.md`(루프 운영 문서), `pnpm token:drift` 진입점. 시각 변경/Figma write 0 → 리포트만.
- **방식 = 값 커버리지** — 코드에 `gray`/`neutral` 두 램프 공존 + Figma 이름 규칙(`neutral/*`·`semantic/*`·`palette/*`)이 코드 경로와 1:1 아님 → 이름 매칭은 거짓 드리프트(예: Figma `neutral/900 #0e0e17`은 `gray.900`이 아니라 `neutral.900`과 일치). 대신 "Figma 색이 코드 팔레트에 존재하는가"만 본다.
- **Figma side 수집** — REST `variables/local`은 토큰 스코프 403이라 공식 MCP `get_variable_defs`로 노드별 수집(노드 늘리면 커버리지↑). 현재 sync-map 노드 5개(Button/Toast/MessageBubble/Chip/Badge).
- **검증(측정)** — `pnpm token:drift` 감사 색상 21종 → 커버 19 / 드리프트 2 / 알파(수동) 1. exit 기본 `0`(게이트 안전), `--strict` `1`(CI 가드). 패키지 소스 무변경 → typecheck/test/build 영향 0, `validate-design-system.sh`에 새 에러 0건.
- **드리프트 2건 발견** — `neutral/600` Figma `#31313a` ↔ code `gray.600 #303235`, `neutral/800` Figma `#191922` ↔ code `gray.800 #191a1d`. **어느 쪽으로 맞출지는 디자인 판단**이라 자동 처리 안 함. 대표 기록 prism `docs/plans/10-design-system-followup-2026-06.md` 2026-06-25 섹션 + `### 주미님 확인`에 등재.

## neutral 그레이스케일 램프 재밸런싱 (Figma Light write + 코드 정렬)

### 요청 범위

드리프트 2건(neutral/600·800) 처리하려다 주미님이 Figma 그레이스케일(`639:10`)을 보고 "쿨-미들그레이로 적절히 가나? 150→200 건너뛸 때 이상"이라 지적 → 램프 전체 밸런스 검토.

### 완료 (Figma `Socra Design system test` + riiid/prism)

- **CIELAB 분석으로 진단** — Light 램프: 150이 100에 붙어 중간값 아님(ΔL 2.9 vs 9.0), 200 채도 꺼짐+azure outlier, 50 너무 회색, 다크(600–900)는 보라(네이비 회피 **의도**)지만 600에서 절벽. 메인스텝 명도는 주미님 OK라 유지.
- **Figma Light 7개 write(승인)** — `neutral/50→#F2F4F8`, `150→#D9DCE2`(중간값), `200→#C9CCD2`, `400→#84878F`, `500→#53555C`, `600→#30323B`, `700→#23242D`. read-back 7/7 ok. **모드-aware(Light/Dark) 발견** → Light만, Dark는 미변경.
- **Dark = 무변경 결정** — 분석상 명도 이미 균형(150이 이미 중간값), hue 정리는 1단위 sub-perceptual. 근거: 전경(Light 다크색=악센트→보라 OK) vs 배경(Dark surface→중립이 콘텐츠 안 건드림). 성숙 다크테마 공통.
- **문서 위생** — swatch 문서의 150/200 스위치가 변수 미바인딩 정적 fill이던 것 재바인딩(하드코딩 제거) + hex 라벨 7개 갱신.
- **코드 정렬** — semantic용 `neutral.{200,500,700}` light 값 3개 정렬. `pnpm token:build` 통과, `pnpm token:drift` 재실행. 대표 기록 prism `docs/plans/10-…` 2026-06-25 섹션.

### 함정 / 발견

- **`get_screenshot` 캐시(stale)** — 변경 직후 캡처가 옛 화면. 노드 fill 직접 읽어 실반영 확인(측정 우선).
- **코드 토큰 외부 원복** — 재적용한 `primitive.tokens.json`이 빌드 직후 HEAD로 콕 되돌려짐(theme.css엔 새 값 남음). 조사 결과 **떠 있던 `tsx build.ts --watch` 2개는 삭제된 옛 paseo 워크트리의 좀비**(소스 안 건드림, 출력만). 원복 원인은 에디터 "변경 취소" 추정으로 좁혀짐(Codex 활성 트랙 아님). 좀비 watch 정리 후 코드 3개 재적용 → 유지 확인.

## neutral 풀 램프 1단계 + gray 토큰 참조 1차 정리

### 요청 범위

앞선 neutral 재밸런싱 후 남은 foundation 미커밋 작업을 먼저 닫기. 목표는 Figma full neutral ramp를 코드에 mode-aware로 반영하고, drift known-orphan을 0으로 만든 뒤 gray 직접 참조를 neutral/semantic으로 1차 정리하는 것.

### 완료 (riiid/prism, 브랜치 `plan/parallel-codex`, 커밋 `15072c2`)

- **neutral 풀 램프 추가** — Figma `color` collection 기준으로 `neutral.{white,50,100,150,200,300,400,500,600,700,800,900,black}`을 Light/Dark mode-aware primitive로 정리. 기존 `neutral.{200,500,700}` sparse 구조에서 full ramp mirror로 확장.
- **드리프트 기준 정리** — `scripts/figma-token-drift.mjs`의 `KNOWN_ORPHANS`를 비움. `pnpm token:drift -- --strict` 결과: 감사 색상 21종 → 커버 21 / 새 드리프트 0 / known 0 / 알파 수동검토 1(`semantic/surface/glass #ffffffb2`).
- **gray 직접 참조 1차 이관** — surface, border, disabled state, badge neutral, checkbox, toggle, toast, history-item, model-profile, tooltip 계열을 neutral 또는 semantic 토큰으로 이동. component token의 직접 `gray.*` 참조는 0으로 정리.
- **남긴 예외** — `color.action.primary.{bg,hover}`와 `color.focus.ring`만 직접 `gray.*` 유지. action primary는 Figma semantic action 값이 rebalanced neutral step과 정확히 같지 않고, focus ring은 기존 결정(2026-06-18) 유지 범위.
- **문서 반영** — `packages/prism/token-contract.md`, `design-system/tokens/color.md`, `design-system/tokens/semantic-guide.md`, `design-system/sync/figma-token-drift.md`, `docs/plans/10-design-system-followup-2026-06.md` 갱신.

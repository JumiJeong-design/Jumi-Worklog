### 함정 모음

- **BottomNav/Tab vs Nav Item 혼동** — `Nav Item (243:93)`은 HORIZONTAL 레이아웃(icon 좌, text 우) — 사이드바/LMB용. Bottom Navigation은 VERTICAL(icon 위, text 아래)이 맞음. 기존 Nav Item을 Bottom Navigation에 그대로 쓰면 레이아웃이 깨짐. 전용 `BottomNav/Tab` 컴포넌트를 별도로 만들어 교체했다.
- **Chat History Panel FRAME vs COMPONENT** — 화면에서 "쓰던" 컴포넌트라도 `type === 'FRAME'`이면 clone = 단순 복사. 원본을 바꿔도 화면에 반영 안 됨. COMPONENT로 승격하고 인스턴스로 교체해야 진짜 재사용.
- **combineAsVariants() 후 좌표 초기화** — `combineAsVariants()`로 component set 생성 직후 자식들이 모두 (0, 0)으로 이동. 각 COMPONENT에 x/y를 수동으로 다시 설정해야 캔버스에서 겹치지 않음.
- **FRAME → COMPONENT 직접 변환 불가** — Figma Plugin API에는 FRAME을 COMPONENT로 in-place 전환하는 메서드가 없음. 새 COMPONENT를 만들고 속성을 복사한 뒤, 원본 FRAME 위치에 INSTANCE를 놓고 원본을 제거하는 4단계를 거쳐야 함.
- **토큰 미바인딩 → 다크 모드 파괴** — `use_figma` 스크립트에서 hex/RGB 직접 입력하면 변수 미연결 상태가 됨. 다크 모드 전환 시 해당 노드만 색이 안 바뀌고 튀어나옴. 생성 스크립트 상단에서 `figma.variables.getVariableByIdAsync()` 로 변수를 미리 로드하고 `setBoundVariableForPaint()` 로 즉시 바인딩해야 함. (Rule 28·29 추가)
- **neutral/white를 Surface에 쓰면 다크 모드 계층 역전** — `neutral/white` (Dark = #000000)를 다이얼로그 배경으로 쓰면 다크 모드에서 페이지(`neutral/50` Dark = #18181b)보다 더 어두워짐. elevation이 높을수록 밝아야 하는 원칙에 반함. 다이얼로그는 `surface/elevated`, 사이드바는 `surface/raised` 사용.
- **Pretendard JP 폰트 로드 누락** — 노드가 Pretendard JP로 생성된 상태에서 `textStyleId`를 설정하면 "unloaded font Pretendard JP" 오류 발생. `figma.loadFontAsync()` 에 `Pretendard JP` family + style도 반드시 포함해야 함.

### 회고 및 인사이트

#### AI 도구 활용

- Figma MCP `use_figma` 로 Plugin API JS를 실행할 때, 노드 조회 후 `type` 체크로 FRAME/COMPONENT/INSTANCE를 구분하는 것이 디버깅 핵심. `mainComponent` 존재 여부가 인스턴스 판별 기준.
- 폰트 변경 전 `figma.loadFontAsync({family, style})`를 **모든 family+style 조합**에 대해 실행해야 함. `Pretendard JP`와 `Pretendard` (non-JP) 모두 필요.
- **생성과 토큰 바인딩은 한 번에**: 레이아웃 먼저 잡고 색은 나중이라는 패턴이 문제의 원인. 스크립트 상단에 TOKEN_IDS + TS 상수 블록을 두고 모든 노드 생성 직후 즉시 바인딩하는 구조로 전환.

#### 설계 결정

- **원자 단위 설계 원칙(Rule 27)**: 반복되는 UI 요소는 처음부터 독립 COMPONENT로 만들고 상위 컴포넌트는 인스턴스로 조합. raw FRAME 복사 금지.
- **Surface elevation 토큰(Rule 29)**: 다크 모드에서 elevation이 높을수록 밝아야 함. `neutral/50`(페이지) → `surface/elevated`(카드/다이얼로그) → `surface/raised`(사이드바/섹션) 계층 확립.
- **ThinkingIndicator 아키텍처**: `_Dot` → `ThinkingIndicator` (공통 3점) → 나중에 모델별 고도화.
- **Message Context Menu (스틱 메뉴)**: 플로팅 pill 방식(A) 채택.
- **Settings 구조**: 모바일은 페이지 전환, Web은 Dialog. `Settings/Row` atom은 양쪽 공용.
- **타임스탬프/Footer 처리**: 삭제 대신 `visible=false`. 눌렀을 때 노출하는 interaction 가능성 유지.
- **Message Bubble Text+Image**: Image 위 + TextBubble 아래 VERTICAL 레이아웃. body lineHeight 1.75→1.6, timestamp 14→13px.

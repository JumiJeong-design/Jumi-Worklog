### 발견사항 분류

- Button icon 포함 text button의 min-width 기준이 Figma evidence와 package contract 사이에서 다르게 보임.
  - Figma evidence: icon on 상태에서 `s=85px`, `m=98px`, `l=120px`로 측정됨.
  - Package contract/token/implementation: text button min-width가 icon 여부와 무관하게 `s=80px`, `m=96px`, `l=120px`로 적용됨.
  - 회수 위치: `contract` / `token` / `story` 중 결정 필요.
  - 판단 옵션:
    - Package contract를 유지한다면 Figma evidence 문서에 해당 측정값을 historical evidence로 라벨링하고 현재 package contract가 우선임을 명시한다.
    - Figma 측정값을 반영한다면 icon text button 전용 min-width token/contract/story를 추가한다.
- Package-first로 판단하더라도 Figma는 반드시 동기화 대상이다.
  - Button min-width를 package contract 기준으로 유지한다면, Figma Button component도 `s=80px`, `m=96px`, `l=120px` 기준에 맞게 정렬해야 한다.
  - Figma evidence 문서는 과거 측정값과 현재 package contract 기준을 분리해서 기록한다.
  - 운영 루프는 `riiid/prism contract` -> `Figma component sync` -> `Storybook QA` -> `worklog 기록` 순서로 유지한다.
- Figma 실제 component 확인 결과:
  - Button node `17:184`의 실제 `minWidth`는 package contract와 이미 일치함.
  - `Icon=true` withText 기준: `s=80px`, `m=96px`, `l=120px`.
  - 현재 캔버스 렌더 width는 content hug 때문에 `s=84x32`, `m=101x40`, `l=120x48`로 보일 수 있지만, 최소 너비 계약은 package와 동일하다.
  - 따라서 Figma component 수정은 필요 없고, stale evidence 문서만 정리한다.
- Storybook coverage는 Button 상태/크기/variant/long text/iconOnly 확인이 가능함.
  - 회수 위치: `story` / `worklog`.
  - light/dark는 local static Storybook으로 확인 완료.
  - Chromatic visual upload는 외부 업로드 승인 여부를 먼저 결정한 뒤 진행한다.
- 사용자 피드백으로 Storybook Button 자체가 Figma 디자인과 달라 보이는 문제가 확인됨.
  - 회수 위치: `token` / `contract` / `implementation` / `worklog`.
  - 조치: Button 전용 radius/state color/icon-size token을 추가하고 실제 Button 구현을 Figma Button 디자인 기준으로 수정함.
- 이후 사용자 조건에 따라 package 변경은 revert함.
  - 회수 위치: `worklog` / `rules`.
  - 다음 판단: package 변경 금지 조건이 있으면 Storybook에서 보이는 실제 package component styling은 수정하지 않는다.

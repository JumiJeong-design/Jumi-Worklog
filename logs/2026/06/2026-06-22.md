## ChatPage 다크 색상 정합 + neutral 텍스트 램프 + Figma 역정합

ChatPage 다크가 Figma와 "색이 다르고 이상하다"는 피드백을 Figma read-only 대조로 근본 원인까지 잡았다. 직전 핸드오프의 "사이드바를 완전 flush(색 동일)로" 진단은 **오진**이었고, Figma 실측은 반대(패널이 본문보다 한 단계 밝은 raised 면)였다.

### 코드 정합 (패키지 = 실제 배포물)

- 히스토리 패널 배경 `bg-surface`(#0E0F12) → `bg-surface-raised`(#191A1D, Figma `surface/floating`). 항목 다크 토큰 off-by-one 정정(기본 순흑 #000 → #191A1D).
- **단일 ramp 드리프트 근본 해결:** 코드가 surface용 `gray` 램프 하나로 텍스트까지 칠해 다크에서 Figma `neutral` 텍스트 램프와 어긋났다. mode-aware `color.neutral.{500,700,900}`를 추가하고 텍스트 토큰을 재바인딩 → 본문 #F3F6F9·히스토리 #DADEE2·보조 #A0A3A7 등 Figma 정확값.
- 웹 chat 하단 본문 하드컷 → 모바일과 동일 scrim 페이드로 입력창 뒤로 자연스럽게 사라지게 함.
- 검증: `token:build`/`typecheck`/`test`(43) 통과, Playwright 픽셀 대조로 Figma 다크와 일치 확인.

### 인사이트 (드리프트 패턴)

- Figma는 텍스트용 `neutral`(모드 flip)과 표면용 surface 스케일이 분리돼 있는데, 코드 포팅 때 `gray` 하나로 합쳐서 라이트에선 안 보이다가 다크에서 갈라졌다. 다크 정합은 "단일 ramp로 두 스케일을 표현하려는 시도"를 깨야 풀린다.
- 채팅 내부 요소를 컴포넌트별로 대조하니 **Figma 쪽이 코드보다 덜 일관**했다(아바타 배경·모델명·카드 배경이 컴포넌트마다 제각각, 카드가 다크에서 순검정으로 떨어짐). 이런 경우 코드를 기준으로 두고 Figma를 맞추는 역방향 정합이 옳다.

### Figma 역정합 (승인 후 write)

`Socra Design system test`에서 Answer Card·Message Bubble을 코드에 맞춰 변수 rebind: 카드/아바타 배경 → `surface/Floating`, 모델명 → `neutral/900`(중립), 테두리/divider → `border-default`. 아이콘 주황은 "작은 컬러 포인트"로 유지(브랜드 흑백 원칙). 그룹 B 1단계 미세차는 보류.

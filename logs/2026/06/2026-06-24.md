- `npx skills add jakubkrehel/make-interfaces-feel-better`로 받은 스킬이 슬래시 목록에 안 잡히던 원인을 확인했다. `npx skills`는 여러 AI 툴 공유 경로 `~/.agents/skills/`에 설치하는데, Claude Code는 `~/.claude/skills/`(또는 프로젝트 `.claude/skills/`)만 스캔해서 파일은 다 있어도 인식되지 않았다.

- 이 스킬은 UI 폴리시 도우미로, 16개 원칙(press 촉감, 타이포 줄바꿈, 동심원 라운드, 터치영역, 등장/퇴장 애니메이션 등)을 코드 점검·적용한다. 다만 이미지 외곽선 등 "하드코딩 색 강제" 규칙은 Socra의 Variables-only 규칙과 충돌하므로 우리 규칙을 우선한다.

### 완료 (riiid/prism, 브랜치 `plan/parallel-codex`, 로컬 커밋 — push 보류)

- prism 컴포넌트 24종 + GlassSurface를 16원칙으로 전수 점검하고, 컴포넌트별 적용 가능 맵을 A(안전)/B(터치영역 판단필요)/C(토큰·구조 작업)/충돌(skip)으로 분류했다. 대표 작업 기록은 prism `docs/plans/10-design-system-followup-2026-06.md` 2026-06-24 섹션에 정리.
- 피그마 read-only 감사: Chip(`201:166`)은 default/active/removable 3상태뿐이고 pressed 변형이 없어, 코드 전용 press-scale 추가는 피그마와 충돌하지 않음(피그마 write 아님)을 캡처로 확인했다. 부수 확인으로 피그마가 Button에 pressed 색 토큰(`Button/*/Pressed`)을 정의하고 있어 press 피드백 자체는 의도된 것임을 봤다.
- press 촉감(#12) — `active:scale-[0.96]` + 트랜지션 속성 명시(`transition: all` 회피) + `motion-reduce` 존중을 Chip/TabItem/Button(`334bb2b`)과 compact 아이콘 버튼/FAB 7곳(ChatInputBar 첨부·전송, HeaderNavBar 아이콘 슬롯, BottomNavigation 탭, BottomBar scrollFab, AnswerCard 더보기, Toast 닫기, ChatHistoryPanel 접기)에 적용했다(`3605cd3`). 풀폭 행(홈/새채팅, HistoryItem, SettingsRow nav)은 scale이 부적절해 색 기반 C단계로 분리했다.
- 타이포(#10/#9) — 라이브러리에 안 쓰이던 줄바꿈 원칙을 적용했다. MessageBubble 제목 `text-balance`·유저 말풍선 `text-pretty`, AnswerCard 에러 `text-pretty`, Callout 본문/설명/inline `text-pretty`, TabItem count 배지 `tabular-nums`. AI 응답 본문(MessageBubble assistant·AnswerCard 답변)은 10줄+ 가능성으로 스킬 권고에 따라 제외했다(`3605cd3`).
- 모든 변경은 className 유틸 추가 수준으로 동작·DOM·ARIA·시각 토큰을 바꾸지 않았다. 검증은 매번 typecheck 3프로젝트 + test 44 통과. `transition: all`은 전 컴포넌트 0건 유지.

### 보류 / 결정

- 터치영역(#16, B단계)은 제품화 전이라 실사용 오탭 이슈가 없고, 실기기에서 손가락으로 눌러야 체감되는 항목이라 보류하기로 결정했다. 적용 시에도 보이는 크기는 그대로 두고 투명 가상요소로 클릭 영역만 넓히는 방식이라 "벙벙해지는" 일은 없음을 확인했다(겹침 회피로 세로만 확장 등 컴포넌트별 판단 필요).
- C단계(별도): Button/SettingsRow 색 기반 pressed/hover(`Button/*/Pressed` 토큰 theme 포팅), Toast 등장/퇴장 애니메이션(마운트 라이프사이클), HistoryItem bg 기반 press, 폰트 스무딩 root. 충돌로 skip: UserProfile 이미지 외곽선(#11, Variables-only 우선).

## Button solid engaged 색 = enabled 드리프트 정정 (Figma)

### 요청 범위

주미님 "solid의 engaged 버튼 컬러가 enabled랑 똑같다, 왜지?" → 원인 확인 후 수정.

### 완료 (Figma `Socra Design system test`, `Button` `17:184`)

- **read-only 픽셀 감사로 원인 확정**: solid의 enabled와 engaged가 픽셀 단위로 동일(둘 다 `neutral/black` #000000 바인딩, 이미지 diff bbox=None)했다. outline·ghost는 정상(engaged = `neutral/100` #EAEDF2 틴트로 enabled와 구분). 버그는 **solid 한정, xs·s·m·l 전 사이즈**.
- **근본 원인**: 이 버튼은 시맨틱 토큰이 아니라 raw `neutral/*` 램프에 직결돼 있고, solid engaged에 별도 색이 안 물려 enabled의 검정을 그대로 둔 상태였다. 코드(`theme.css`)엔 이미 `action.primary.bg`(#0E0F12/#F3F4F6)·`action.primary.hover`(#242528/#E1E5EC)가 있어, **Figma에 시맨틱 레이어가 누락된 드리프트**였다(라이브러리 `Primary/Hover·Pressed`는 SocraBlue 계열이라 무관).
- **결정(주미님 "지금하자")**: 임시 근사(neutral/700)가 아니라 **코드 기준값으로 Figma에 시맨틱 토큰을 신설하고 버튼을 재바인딩**(피그마=코드 구조). 코드 값은 이미 정답이라 코드 변경 없음.
- **Figma write(명시 승인 후)**: `color` 컬렉션에 `semantic/action-primary/bg`(#0E0F12/#F3F4F6 = neutral/50 모드-반전)·`semantic/action-primary/hover`(#242528/#E1E5EC = neutral/150 모드-반전) 2종 신설(fill scope). solid 30개 변형 재바인딩 — enabled(10)+loading(10)→`bg`, engaged(10)→`hover`. loading은 예전 별도 변수였으나 enabled와 동일 base로 통일. fg는 기존 `neutral/white`가 이미 일치라 미변경, disabled는 자체 토큰이라 미변경.
- **검증**: 라이트 라이브 픽셀 enabled #0e0f12 / engaged #242528 / loading #0e0f12 = 코드 목표 정확 일치. 다크값은 변수에 모드별 설정 완료. rollback=old 바인딩 기록 + Figma 버전 히스토리. 대표 기록은 prism `docs/plans/10-design-system-followup-2026-06.md` 2026-06-24 섹션.

### 보류 / 다음

- 토큰 파이프라인 동기화(Figma 신설 변수명 `semantic/action-primary/*`를 `token-contract.md`/토큰 export에 정식 반영)는 별도 결정. 값은 이미 일치라 시각 회귀 없음. 이 작업으로 base 드리프트(#000→#0E0F12)도 함께 해소됨.

## ChipGroup 내부 칩 → 진짜 ModelChip 인스턴스 전환 (Figma)

### 요청 범위

주미님 "ChipGroup 안에 ModelChip이 인스턴스로 들어가야 할 것 같은데" → read-only 감사로 확인 후 승인받아 전환.

### 완료 (Figma `Socra Design system test`, `ChipGroup` `2998:231`)

- **감사로 원인 확정**: ChipGroup 두 variant의 칩은 ModelChip 인스턴스가 아니라 "ModelChip" 이름만 가진 detached 프레임이었다. ModelChip 마스터(`2937:122`)를 참조하지 않아 마스터 스타일이 전파되지 않는 구조 — 6/23에 "nested 텍스트를 외부로 노출 못 한다"는 이유로 의도적으로 detach했던 상태(plan-11 §174 기록).
- **6/23 결론 정정**: Plugin API `isExposedInstance`가 실제로 지원됨을 probe로 확인. 다만 칩이 ModelChip 인스턴스 안으로 들어가면 노출 속성명은 master의 `Label`이 되어 기존 `Chip1~Chip10` 이름은 보존 불가 — nested 인스턴스 레이어명을 `Chip 1`…`More`로 지어 패널에 `Chip 1 · Label`로 읽히게 완화(Model A1).
- **전수 전환(주미님 "바로 전수 전환" 승인)**: Expanded 10칩(`3029:139`~`157`)·Collapsed 3칩+More(`3030:149`~`155`) 전부 ModelChip 인스턴스로 교체, `isExposedInstance=true`. `Chip*Visible`/`MoreVisible`/`State`는 새 인스턴스 `visible`에 재바인딩해 보존, 바인딩 풀린 `Chip1~Chip10`/`MoreLabel` TEXT 11개 삭제.
- **8개 카드 텍스트 복원**: TEXT 속성 삭제로 일본노후 hyp-card 8개(`2999:153`…`2999:285`)의 override가 리셋되므로, 전환 전 칩 텍스트/`+N`을 전량 캡처해 두고 nested override(`Chip 1/2/3/More`의 `Label`)로 32개 전부 복원(`+7` 7개, `+6` 1개, 30%/20% 그룹 포함).
- **검증**: component set 스크린샷(Collapsed/Expanded) 원본과 픽셀 동일, 카드 `2999:209`(`+6`)·`2999:228`(30%) 캡처값 그대로 렌더, 카드 nested 칩 4개 `mainComponent`=`2937:122` 확인(전파 회로 성립). 대표 기록은 prism `docs/plans/11-…-componentization.md` §8 "2026-06-24" 절 + `10-…` 체크리스트.

### 보류 / 다음

- 칩 텍스트 편집은 이제 ChipGroup 인스턴스 패널에서 nested 칩(`Chip 1 · Label`)을 펼쳐서 함(평면 `Chip1~Chip10` 필드 아님). 기능 동등, UX만 다름.

### 오늘의 작업 맥락

- Socra Figma design system을 계속 정리했다.
- 카테고리 컬러, 다크모드 shadow, Markdown rendering, component guide, responsive frame, opacity token 운영 방식이 한 세션 안에서 얽혀 있었다.
- 사용자는 "그럴듯한 임시 화면/가이드"가 아니라 실제 디자인 시스템 기준으로 쓸 수 있는 문서와 Figma 구조를 원했다.
- Codex가 자체 판단으로 만든 임시 component guide와 responsive screen은 잘못된 방향으로 확인되어 삭제되었다.
- 그 실수를 다시 반복하지 않도록 실제 프로젝트 문서에 규칙을 추가했다.

### Figma에서 완료한 정리

- `category/*` color variables/styles 제거.
  - 이유: 고민 카테고리 taxonomy가 확정되지 않았고, category semantic이 active foundation처럼 보이면 오히려 잘못된 선택지를 늘림.
  - 기존 Page design test의 category binding은 neutral scale로 되돌림.
- `Shadow`와 `Foundation / Dark Shadow Tokens`를 `Shadow / Elevation`으로 병합.
  - light/dark shadow를 따로 섹션화하지 않고 같은 elevation row에서 비교하도록 정리.
  - dark sample은 `color` 컬렉션의 Dark mode를 명시하고 `neutral/50`, `neutral/100`, `neutral/200`에 바인딩.
- Markdown 영역 정리.
  - `Markdown Guide`와 `Markdown Components` 중복을 `Markdown Rendering` 안으로 통합.
  - `Markdown Block / Table` component 추가.
  - 이후 table은 head, column, body cell 구조를 구분해야 한다는 기준을 추가로 반영.
- 잘못 만든 임시 component guide cards 삭제.
  - 이유: 실제 component별 docs wrapper가 아니라 흩어진 guide card라 사용자가 보기에도 중구난방.
- 자체 제작 responsive web/mobile frames 삭제.
  - 이유: 사용자가 이미 만들어둔 모바일 디자인을 기준으로 web 확장을 해야 하는데, 기존 source screen을 확인하지 않고 새 화면을 만들었음.

### 주요 판단

- category color는 지금 active foundation에 둘 단계가 아니다.
  - 고민 카테고리 자체가 아직 제품적으로 확정되지 않았기 때문.
  - 금융/법률/관계 같은 category 방향은 가능성이 있지만, 지금 token으로 고정하면 UI tone이 흔들릴 수 있음.
- dark mode opacity는 black/white alpha를 1:1로 뒤집으면 안 된다.
  - 다크모드에서 같은 alpha라도 surface, overlay, disabled, shadow의 의미가 다름.
  - `overlay/scrim`, `state/disabled`, `state/pressed`, `focus`, `shadow/dark/*`처럼 role semantic token으로 분리해야 함.
- dark shadow는 "잘 보이는 그림자"가 아니라 elevation context를 보여주는 구조로 봐야 한다.
  - surface/background 차이, subtle stroke, dark shadow, inner highlight를 함께 본다.
- component guide는 설명 카드가 아니라 docs wrapper 구조로 만든다.
  - 실제 component set/instance와 usage/variant/light-dark/token notes가 같은 wrapper 안에 있어야 한다.
- responsive design은 기존 source frame 확인이 먼저다.
  - iPhone 16 기준이라면 safe area/dead space까지 포함해야 함.
- Markdown table은 일반 block component와 다르게 구조가 중요하다.
  - header row, column, body cell이 같은 스타일로 뭉개지면 table로 읽히지 않는다.

### 실수 / 재발 방지

- 임시 Codex 작업 폴더에 룰을 써놓고 실제 프로젝트 문서에 반영하지 않는 판단은 잘못이다.
  - 재발 방지: `AGENTS.md`, `docs/agent-rules.md`, `design-system/rules.md`, 관련 foundation 문서를 먼저 찾는다.
- component guide를 component마다 붙였지만 실제로는 통짜이거나 흩어진 card 형태였다.
  - 재발 방지: component guide는 `Docs / ComponentName` wrapper 구조로 만든다.
- responsive web/mobile 화면을 기존 모바일 source frame 확인 없이 자체 제작했다.
  - 재발 방지: 기준 node를 먼저 찾고, 불명확하면 사용자에게 확인한다.
- Shadow와 Dark Shadow를 별도 섹션으로 두면 Foundation에서 같은 주제가 중복된다.
  - 재발 방지: 같은 token family는 하나의 top-level section에서 light/dark를 함께 보여준다.
- Markdown table은 table component를 만들었다는 사실만으로 충분하지 않다.
  - 재발 방지: head, column, body cell 역할이 실제 preview에서 구분되어야 한다.

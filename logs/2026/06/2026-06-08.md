## 함정 모음

- **컨셉 실험을 기존 코드에 바로 넣으면 부담이 커진다** — PrismSpirit는 아직 캐릭터 방향을 찾는 중이라 기존 design-system repo와 분리된 standalone Vite sandbox로 관리했다. 컨셉 검증이 끝나기 전까지는 product/package 코드와 결합하지 않는 편이 안전하다.
- **"불특정 요인이 합쳐지는 형태"를 blob 덩어리로 해석하면 징그러워진다** — 사용자가 원한 것은 여러 덩어리가 아니라 같은 크기의 작은 단위가 모여 형상을 만드는 pixel/text-art 계열이었다. 시각 피드백이 빠르게 바뀌는 컨셉 작업에서는 레퍼런스의 조형 원리를 먼저 읽어야 한다.
- **옵션이 많으면 컨셉 패널이 산만해진다** — pixel weight/radius 조절은 초반 탐색에는 유용했지만, 방향이 잡힌 뒤에는 고정값(W 1.15, R 1.25)으로 잠그고 표정·장식·variant 같은 핵심 선택지만 남겼다.
- **worklog 뷰어 구조가 중간 리팩터 상태일 수 있다** — `site/worklog.html`은 inline entry block을 제거하고 raw markdown fetch로 전환 중이었는데, ENTRIES가 DOM script block만 스캔하면 날짜가 비게 된다. 날짜 source를 `ENTRY_META` 키에서도 읽도록 보정했다.

## 회고 및 인사이트

### AI 도구 활용

- 로컬 Vite sandbox + in-app browser는 빠른 캐릭터 방향 탐색에 잘 맞았다. 사용자가 "징그러움", "안 귀여움", "중앙정렬", "한 칸 위로"처럼 즉각 피드백을 주면 바로 SVG pixel grid를 수정해 확인할 수 있었다.
- 공유 단계에서는 localhost가 한계가 있으므로 Vercel production URL을 바로 만들어야 한다. 오늘은 `https://prism-spirit-concept.vercel.app`로 공개 확인 환경을 열었다.

### 설계 결정

- PrismSpirit는 임시로 **기존 repo와 분리된 standalone concept folder**에서 관리한다. 디자인 방향이 확정되면 design-system component로 이관한다.
- body는 blob/cloud가 아니라 **동일 크기 pixel unit + opacity/색상 차이**로 형상을 만든다.
- 귀와 악세사리는 분리하지 않고 **Adornment** 한 축으로 합친다. `auto`, `round`, `cat`, `fox`, `pigtails`, `headphones`, `glasses`, `alien`, `bunny`를 한 컨트롤에서 비교한다.
- `soft` variant는 default와 구분되도록 외곽에 blurred aura layer를 추가한다. `mono`는 유지하고 `aqua`, `berry`, `sunrise` 컬러 variant를 추가했다.
- 발은 기본 구조에 고정하지 않고 `showFeet` 옵션으로 켜고 끌 수 있게 한다.

### 4. Adornment 컨트롤 정리 + 자동 순환

```
ear 랑 Accessory 합쳐서 auto로 하면어때?
대신 헤드폰도 가로로 더 넓게 해서 ear 영역에 있으면 좋을듯 얼굴 옆쪽에 붙도록 
그래서 글래스, dog(이건 근데 도그가 아니고 양갈래 머리로 표현하는게 나을듯), 헤드폰, 외계인 귀 (위로 솟은 모양 뭔지알지), 위로 긴 토끼귀 이정도?
```

**Codex 작업:**
- `ear`와 `accessory`를 새 `adornment` API로 합쳤다.
- `auto`는 round, cat, fox, pigtails, alien, bunny, headphones, glasses를 순환한다.
- dog/raccoon 계열은 제거하고 pigtails 형태로 대체했다.
- headphones는 얼굴 옆 ear 영역에 붙도록 더 넓은 side-mounted pixel 형태로 수정했다.
- `adornmentY` 기본값을 `2`로 두고, `adornmentFloat`를 켜면 Y 0~4 사이를 반복하도록 만들었다.

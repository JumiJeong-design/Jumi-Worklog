## 🧭 전체 흐름

```text
1  왜 "Figma → 바로 코드"가 안 됐나
      · 토큰 과다  · 완성본이 탐색을 좁힘  · 코드가 너무 빨리 기준이 됨
        ↓ FE 패키지 도착 = 전환점

2  그래서 만든 운영 루프
      Figma 승인 → Git 언어화 → Package 반영 → Storybook QA → Worklog/Wiki
        ↓

3  AI가 움직일 경계를 정한 기준 설계
      Figma Foundation(시각) + Git Rules(행동)
        ↓

4  작업이 흩어지지 않게 한 운영 설계
      Worklog · Wiki · 문서 레벨 · 모바일/데스크톱 분업
        ↓

5  그래도 사람이 끝까지 잡아야 하는 것
      B2C 브랜드 품질의 마지막 디테일 = 디자이너의 몫
```

## 🗺️ 5채널 역할 맵

| 채널 | 역할 | 한 마디 |
| --- | --- | --- |
| Figma | 시각 기준 승인 | source of truth |
| Git | Figma를 언어화 | contract · rules (두 번째 디자인 시스템) |
| Package | FE 구현 경계 | 임의 수정 금지, 승인 후 변경 |
| Storybook | 구현 QA 표면 | 원본 아님, 검수용 |
| Worklog / Wiki | 기록 → 운영 지식 | 다음 세션이 이어받는 곳 |

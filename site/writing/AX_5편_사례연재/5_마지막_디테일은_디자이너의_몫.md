# 5편. 마지막 디테일은 디자이너의 몫

## 한 줄 요약

AI는 구조를 빠르게 만들고, 누락을 찾고, 기준을 문서화하는 데 강했다. 하지만 B2C 브랜드 품질의 마지막 디테일은 디자이너가 직접 잡아야 했다. 이번 실험의 결론은 "AI가 디자이너를 대체한다"가 아니라, "AI가 들어와도 디자인 시스템이 안 무너지게 운영 기준을 설계한다"였다.

---

## 디자이너가 끝까지 잡아야 하는 것

AI는 구조를 빠르게 만들고, 누락을 찾고, 기준을 문서화하는 데 강했다. 하지만 B2C 제품의 마지막 품질까지 대신 살려주지는 못했다.

특히 이런 디테일은 디자이너가 직접 보고 조정해야 했다.

- disabled, pressed, loading, error 상태의 미묘한 강도
- dark mode에서 shadow와 surface가 보이는 정도
- icon stroke의 두께와 optical balance
- 긴 텍스트나 일본어가 들어왔을 때의 여백과 줄바꿈
- table head, column, body cell이 실제로 읽히는지
- 브랜드 컬러가 한 화면에서 너무 많이 쓰이지 않는지
- 캐릭터나 모델 아이콘이 제품 톤을 해치지 않는지

AI가 이런 값을 제안할 수는 있다. 하지만 "이게 우리 제품답다"는 최종 판단은 디자이너가 해야 한다.

특히 Socra처럼 B2C 제품이고, 일본 사용자에게 신뢰감을 줘야 하는 화면에서는 작은 어색함이 바로 품질 저하로 느껴질 수 있다.

---

## AI가 잘하는 일 vs 디자이너가 해야 하는 일

| AI가 잘한 일 | 디자이너가 해야 하는 일 |
| --- | --- |
| 문서와 코드 비교 | 브랜드 톤 판단 |
| 누락된 기준 찾기 | 시각 우선순위 결정 |
| 체크리스트화 | 최종 승인 |
| Storybook 상태 확인 | 미묘한 상태값 조정 |
| worklog 정리 | 제품다움 판단 |
| 다음 액션 계산 | 탐색 방향 선택 |

이번 실험의 결론은 AI가 디자이너를 대체한다는 것이 아니었다. AI가 반복 확인과 문서화를 도와주는 동안, 디자이너는 더 중요한 시각 판단과 마지막 품질 조정에 시간을 써야 한다는 쪽에 가까웠다.

---

## 시리즈 전체 결론

AI를 디자인 시스템에 넣는 일은 단순 자동화가 아니었다. 필요했던 것은 좋은 프롬프트 하나가 아니라, 여러 개의 안전장치였다.

```text
Figma Foundation
-> Git Rules
-> Worklog Planning
-> Document Levels
-> Mobile / Desktop Split
-> Designer Final Detail
```

이 구조가 있어야 AI가 빠르게 움직여도 디자인 시스템과 브랜드 품질이 흔들리지 않는다.

이번 AX 실험의 핵심은 "AI로 디자인을 빨리 만들었다"가 아니라, "AI가 들어와도 디자인 시스템이 무너지지 않도록 운영 기준을 설계했다"에 더 가깝다.

> AI가 줄여준 시간은 디자인 판단 자체가 아니라, **판단 이후의 정리·검증·전달·재사용 비용**이었다.

> AI를 디자인 시스템에 넣는 일은 자동화가 아니라 **운영 설계**에 가까웠다.

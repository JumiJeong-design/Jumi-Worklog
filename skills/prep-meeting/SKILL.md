# prep-meeting

최근 worklog를 읽어 업무 요약 + 미팅 아젠다를 빠르게 정리한다.
사용자가 미팅 직전에 "이번 주 뭐 했지?"를 떠올리지 않아도 되게 한다.

---

## Step 1 — 미팅 컨텍스트 파악  [Confirm]

**Do:**
1. 사용자에게 묻는다:
   - 미팅 상대 (기획, 프론트, 디자인팀, 전체 등)
   - 미팅 주요 주제 (없으면 "자유롭게 구성" 으로 진행)
   - 기간 (기본값: 최근 7일)

질문은 한 번에 묶어서 한다. 짧게.

---

## Step 2 — worklog 읽기  [Research]

**Do:**
1. `mcp__github__get_file_contents`로 `JumiJeong-design/Jumi-Worklog`의 `logs/YYYY/MM/` 경로를 읽어 파일 목록 확인.
2. Step 1에서 지정한 기간의 worklog 파일을 전부 읽는다 (기본 최근 7일 = 최대 7개 파일).
3. 각 파일에서 아래 항목을 추출한다:

| 추출 대상 | 어디서 |
|-----------|--------|
| 완료한 주요 작업 | `## YYYY-MM-DD` 섹션의 작업 제목들 |
| 미완료 항목 | `### 미해결 항목`의 `- [ ]` 항목 |
| 설계 결정 | `### 회고 및 인사이트 > 설계 결정` |
| 함정/이슈 | `### 함정 모음` |

---

## Step 3 — 미팅 자료 생성  [Write to chat]

추출한 내용을 아래 형식으로 채팅에 출력한다. 파일 저장하지 않음.

```
## 미팅 준비 — YYYY-MM-DD

### 이번 주 완료한 것
- ...
- ...

### 진행 중 / 미완료
- ...

### 논의할 것 (아젠다 제안)
1. ...
2. ...
3. ...

### 참고: 이번 주 설계 결정
- ...
```

**아젠다 선정 기준:**
- 미완료 항목 중 상대방 결정이 필요한 것 우선
- 미팅 상대가 기획/프론트면 → 프로세스·협업 이슈 우선
- 미팅 상대가 팀 전체면 → 완료 항목 공유 + 다음 스프린트 우선

---

## Step 4 — 피드백  [Confirm]

"아젠다 수정하거나 추가할 것 있어?" 라고 묻는다.
수정 요청 시 반영 후 재출력.

파일로 저장이 필요하면 사용자가 요청할 때만 `write-worklog` 스킬과 연동해서 처리.

---

## 운영 규칙

- 파일 저장은 기본 안 함 — 채팅 출력만
- worklog가 없는 날은 해당 날짜 건너뜀
- 내용이 많으면 요점만 불릿으로, 길게 쓰지 않는다
- 아젠다는 최대 5개로 압축

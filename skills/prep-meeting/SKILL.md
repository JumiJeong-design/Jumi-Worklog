# prep-meeting

최근 worklog를 읽어 업무 요약 + 미팅 아젠다를 빠르게 정리한다.
사용자가 미팅 직전에 "이번 주 뭐 했지?"를 떠올리지 않아도 되게 한다.

---

## Step 1 — 미팅 컨텍스트 파악  [Confirm]

**Do:**
1. 사용자에게 묻는다:
   - 미팅 상대 (기획, 프론트, 디자인팀, 전체 등)
   - 미팅 주요 주제 (없으면 "자유롭게 구성" 으로 진행)
   - 기간 (기본값: 최근 7일)

질문은 한 번에 묶어서 한다. 짧게.

---

## Step 2 — worklog 읽기  [Research]

**Do:**
1. 로컬 `~/Desktop/jumi-worklog/logs/YYYY/MM/`의 파일 목록을 확인한다
   (`ls ~/Desktop/jumi-worklog/logs/$(date +%Y/%m)/`).
2. Step 1에서 지정한 기간의 worklog 파일을 전부 읽는다 (기본 최근 7일 = 최대 7개 파일).
3. 각 파일에서 아래 항목을 추출한다:

| 추출 대상 | 어디서 |
|-----------|--------|
| 완료한 주요 작업 | `## YYYY-MM-DD` 섹션의 작업 제목들 |
| 미완료 항목 | `### 미해결 항목`의 `- [ ]` 항목 |
| 설계 결정 | `### 회고 및 인사이트 > 설계 결정` |
| 함정/이슈 | `### 함정 모음` |

---

## Step 3 — 미팅 자료 생성  [Write to chat]

추출한 내용을 아래 형식으로 채팅에 출력한다. 파일 저장하지 않음.

```
## 미팅 준비 — YYYY-MM-DD

### 이번 주 완료한 것
- ...
- ...

### 진행 중 / 미완료
- ...

### 논의할 것 (아젠다 제안)
1. ...
2. ...
3. ...

### 참고: 이번 주 설계 결정
- ...
```

**아젠다 선정 기준:**
- 미완료 항목 중 상대방 결정이 필요한 것 우선
- 미팅 상대가 기획/프론트면 → 프로세스·협업 이슈 우선
- 미팅 상대가 팀 전체면 → 완료 항목 공유 + 다음 스프린트 우선

---

## Step 4 — 피드백  [Confirm]

"아젠다 수정하거나 추가할 것 있어?" 라고 묻는다.
수정 요청 시 반영 후 재출력.

파일로 저장이 필요하면 사용자가 요청할 때만 `write-worklog` 스킬과 연동해서 처리.

## 위클리 모드 — '위클리 작성', '주간 위클리' 요청 시 (2026-08-11 도입)

Step 1의 미팅 컨텍스트 질문 대신 이 절차로 간다. 목표는 화요일 PD 위클리 미팅노트의 배포 표 + Product Design Timeline을 한 번에 최신화하는 것.

**소스 3개 — worklog만 믿지 않는다:**

1. 로컬 worklog (기간 전체) — 에이전트 세션 기록. **주미님이 직접 한 피그마 작업·리뷰·미팅은 여기 없다.** worklog 없는 날은 `git log --all`과 메모리로 보강.
2. 주미님 수기 계획 목록 — 붙여주시면 worklog와 대조해 빠진 항목(직접 작업·리뷰류)을 보충. 없으면 요청.
3. Notion (notion MCP):
   - Product Design Timeline: `collection://bc826f04-7476-4000-9b10-4067a524072e` — `프로덕트='Socra AI'` 필터로 조회
   - 위클리 미팅노트 DB: `collection://35f5bc5f-6307-80e6-a5d2-000b11213eb6` — 해당 주차 페이지(이름 = YYMMDD)
   - **MVP 디자인 일정**: `39d5bc5f6307803b98f1d057d9b90fc7` — 주차별 계획의 정본. 여러 번 재조정됐고 최신 표가 상단, 이전 안은 「아카이빙」 토글. 예정 작업의 날짜·우선순위(P0~P5)는 여기서 가져온다.
   - 문서 허브: `35e5bc5f630780f6a393ef8dd5f851e6` — PD 위클리 / 디자이너 TODO / 기획 문서 / PD·미팅 로그 DB
   - 주미님 user ID: `225d872b-594c-81b7-8251-00022b786cb3`
4. 개발 협업 문서 — 프론트 개발자와의 논의(예: [PRISM 패키지 싱크](https://app.notion.com/p/3b25bc5f6307805e813bf995ebb5f21a))는 워크로그에 안 남는다. 해당 주에 미팅이 있었으면 결정 사항을 표에 반영.

**절차:**

1. worklog 기간 전체 읽기 + 수기 계획 대조
2. **타임라인 먼저 갱신** — 진행 중 행 상태·기간 갱신, 새 트랙은 행 신설(담당자 주미님, 채팅 관련 에픽 `SA-채팅창`), 다음 주 예정 작업은 `시작 전` 행으로. 상세의 정본은 타임라인 페이지.
   - 행 본문은 **팀 템플릿 「2026 태스크 생성 템플릿」 구조**를 따른다: `## 1. 기획`(기획문서 링크 + 업무 배경) → `## 2. 작업 히스토리`(날짜별 `<details>` 토글 + 요약 태그) → `## 3. 디자인`(최종 전달 Link) → `## 4. 데이터`. 헤딩은 `{color="gray_bg"}`.
   - **행 이름 기준(2026-08-11 확정)**: 화면·영역 이름으로 짓고 **우선순위(P0~P5)는 이름에 박지 않는다** — P는 구축 단계 한정이라 운영 전환 때 거짓말이 된다. 우선순위는 MVP 일정 문서가 정본, 구축→운영 구분은 `유형` 필드(`신규` ↔ `운영개선`)가 담당.
   - **아이콘 기준(2026-08-11 확정) = 진행 상태**: ✅ 완료(design 완료·prod 완료) / ➡️ 진행 중 / ➖ 아직 안 함(시작 전·보류·홀딩). 팀 기존 관례이자 **위클리에서 타임라인 행을 mention으로 걸면 아이콘+제목만 보이기 때문** — 그 자리에서 필요한 건 "끝났나 남았나"다. 성격은 `업무타입` 컬럼이 담당하므로 아이콘으로 중복하지 않는다. 최상위 우산 3행(MVP 구축·DAX 구축·일정/커뮤니케이션)은 팀 커스텀 이모지라 **건드리지 않는다**.
   - **최상위 우산 행은 상태 아이콘을 쓰지 않는다** — 늘 진행 중이라 ➡️가 정보를 안 준다. 토픽 이모지를 쓴다(MVP 구축·DAX 구축·일정/커뮤니케이션은 팀 커스텀 이모지, 브랜드는 🏷️).
   - **실제로 배포된 건은 `prod 완료` + `Prod.date`를 채운다**(스테이징·카나리는 `stg`). 이 DB가 그 컬럼을 가진 이유이고, 위클리 표의 「배포일 / 배포 ✅」 칸과 같은 개념으로 이어진다. 상태 옵션(칩)을 새로 만들지 않는다 — `상태`는 팀 공용 필드라 Notion UI 수동 작업 + 타 제품 뷰에 노출되는데, `Prod.date` 유무로 이미 갈린다.
   - ⚠️ **상태를 바꾸면 아이콘도 같은 턴에 바꾼다.** 안 그러면 거짓말이 된다 — 실제로 「리서치」 행이 완료인데 ➡️로 남아 있었고, 팀 다른 제품 행에도 `시작 전`인데 ✅인 사례가 있다. 위클리 모드에서 상태를 갱신할 때마다 아이콘 동기화를 체크한다.
   - **상태 기준**: `시작 전` = 지금 착수 가능 / `보류·홀딩` = 선행(기획·타인 작업) 대기 / `진행 중` 중 트랙(우산) 행은 상시 열려 있으므로 본문 상단에 트랙 콜아웃을 둔다.
   - 겹치는 영역이 생기면 행을 늘리지 말고 **소속 규칙을 본문에 명문화**한다(예: PC 반응형=공통 기준만, 화면별 웹 작업은 각 화면 행 / 첨부 에러=파일 첨부 행 소유).
   - 기획서 최신본은 Notion 검색으로 확인(현재 v1.0.6 = `3885bc5f630780da8b48c9fe235a1f44`, **페이지 ID는 버전마다 재사용되니 검색으로 재확인**).
3. 해당 주차 위클리 페이지의 배포 표를 채운다 — 형식은 전주 표 참고: `[카테고리 : 작업명]` 태그 + green `작업 진행` / red `진행 필요`, 배포 완료 행은 배포일+✅. 리뷰·미팅류는 "리뷰 진행 후 확정" 수준 한 줄로만.
4. 표의 각 행에 대응 타임라인 행을 mention-page로 링크 — 표는 요약+링크, 중복 서술 최소화.

**함정:**

- 배포 표는 **synced block** — 원본 공유 페이지에도 전파된다. 표 밖 페이지 본문에 긴 위클리 덤프를 넣지 않는다(표가 정본).
- Notion 자동 링크화 — `w.AI`, `CLAUDE.md` 같은 점 포함 텍스트는 백틱으로 감싼다(안 그러면 깨진 http 링크로 변환).
- 주미님이 표를 동시에 편집 중이면 old_str 매칭이 깨진다 — **update_content 직전에 fetch로 최신 상태를 다시 읽는다.**
- 타임라인 상태 옵션: 요청 / 보류·홀딩 / 시작 전 / 진행 중 / design 완료 / prod 완료.
- 불참·소급 주차 페이지엔 synced 표가 아예 없을 수 있다(표 복사가 수동 절차라서). synced block은 API로 못 만드니 **같은 5열 일반 표**로 채우고, 표 위에 "소급 기록 (작성일)" 회색 캡션을 단다. (2026-08-11 첫 실행에서 확인)
- **제품 트랙만 세면 AX·운영성 작업이 통째로 빠진다.** AX 사례글·스킬 정비·워크로그 체계는 워크로그에 있어도 "제품 화면"이 아니라서 표에서 누락되기 쉽다. 매주 AX 행이 있는지 확인한다.
- **개발 협업·프로세스 결정도 한 줄 넣는다** — 패키지 수정 주체, 핸드오프 방식 같은 건 화면이 아니어서 놓치지만 위클리에서 팀이 알아야 할 정보다.

## 운영 규칙

- 파일 저장은 기본 안 함 — 채팅 출력만 (위클리 모드는 예외: Notion 타임라인·위클리 표에 write)
- worklog가 없는 날은 해당 날짜 건너뜀 (위클리 모드에선 git log·메모리로 보강)
- 내용이 많으면 요점만 불릿으로, 길게 쓰지 않는다
- 아젠다는 최대 5개로 압축

# save-ideation

현재 대화에서 **결정 사항·탈락 항목·생존 후보·인사이트·다음 스텝**을 추출해
FigJam 보드에 **날짜 스탬프 카드**로 자동 저장한다.
매 아이데이션 세션 끝에 부를 수 있는 루틴이다.

---

## 자동 감지 — Claude가 먼저 제안하는 타이밍

사용자가 트리거를 말하지 않아도 아래 패턴이 감지되면
응답 끝에 **"아이데이션 저장할까요?"** 한 줄을 붙인다.
(길게 설명하지 않고 딱 한 줄만)

| 감지 패턴 | 예시 표현 |
|---------|---------|
| 방향/후보를 줄이는 결정 | "~빼자", "~제끼자", "~로 가자", "~탈락" |
| 로드맵·계획이 확정됐을 때 | Phase 정의, 순서 확정, "이 순서로 하자" |
| 대화가 아이데이션 → 실행으로 전환될 때 | "그럼 이제 만들어보자", "다음 단계는" |
| 후보가 1~2개로 수렴됐을 때 | 여러 후보에서 최종 2개 이하로 좁혀짐 |
| 긴 탐색 후 한동안 새 아이디어가 없을 때 | 10턴 이상 아이데이션이 이어진 후 대화가 마무리 분위기 |

**제안 형식 (응답 끝에 딱 한 줄):**
> 아이데이션 저장할까요?

사용자가 "응", "저장해줘", "그래" 등으로 승인하면 Step 1부터 실행한다.
"아니", "나중에", "괜찮아" 등이면 건너뛴다.

---

## Mandatory prerequisites

- Figma MCP (`mcp__figma__use_figma`, `mcp__figma__get_figjam`) 연결 필요
- 대화 컨텍스트 — 이번 세션 아이데이션 내용
- FigJam 파일 키 — 사용자가 세션에서 공유한 URL에서 추출, 없으면 물어본다

---

## Step 1 — 대화에서 추출  [Research]

대화 컨텍스트를 보고 아래 항목을 뽑는다.

| 항목 | 추출 방법 |
|------|---------|
| 결정 사항 | "확정", "~로 간다", "A로 가자" 같은 확정 표현 |
| 탈락 항목 | "빼자", "별로", "탈락", "제끼자" 같은 제거 표현 + 이유 |
| 생존 후보 | 탈락하지 않고 남은 선택지 |
| 핵심 인사이트 | 방향 전환, 새로 발견한 관점, 중요한 깨달음 |
| 다음 스텝 | 다음 세션에서 해야 할 것, 미결 항목 |
| 현재 Phase | 로드맵이 있으면 현재 위치 |

항목이 하나도 없으면 사용자에게 "이번 세션에서 결정된 게 있으면 말해줘" 라고 묻는다.

---

## Step 2 — FigJam 현재 상태 파악  [Research]

`mcp__figma__get_figjam`으로 파일 구조를 읽어 **카드를 놓을 빈 위치**를 파악한다.

- 기존 "결정 사항" 카드가 있으면 그 아래에 이어서 배치
- 없으면 기존 콘텐츠 오른쪽 여백에 배치
- 좌표는 기존 노드의 최대 x/y 값 기준으로 겹치지 않게 결정

---

## Step 3 — FigJam에 카드 작성  [Write]

`mcp__figma__use_figma`로 아래 구조의 카드를 생성한다.

### 카드 구조 (코드 템플릿)

```javascript
await figma.loadFontAsync({ family: "Inter", style: "Regular" });
await figma.loadFontAsync({ family: "Inter", style: "Bold" });

// 날짜 스탬프 헤더 (어두운 배경)
// 탈락 항목 (빨간 배경, ✕ 접두)
// 생존 후보 (초록 배경, ✓ 접두)
// 결정 사항 (파란 배경, → 접두)
// 핵심 인사이트 (노란 배경, 💡 접두) — 있을 때만
// 다음 스텝 (보라 배경, ▶ 접두) — 있을 때만
```

### 카드 색상 규칙

| 섹션 | 배경 | 텍스트 |
|------|------|------|
| 헤더 (날짜) | `#0F172A` | `#FFFFFF` |
| 탈락 | `#FEE2E2` | `#991B1B` |
| 생존 후보 | `#DCFCE7` | `#166534` |
| 결정 사항 | `#DBEAFE` | `#1E3A8A` |
| 인사이트 | `#FEF9C3` | `#854D0E` |
| 다음 스텝 | `#EDE9FE` | `#5B21B6` |

### 카드 배치 규칙

- 카드 너비: 500px
- 섹션 간 간격: 8px
- 빈 섹션(내용 없음)은 렌더하지 않는다
- 같은 날짜 카드가 이미 있으면 **옆에 새 카드 추가** (덮어쓰지 않음)

## Step 4 — 완료 보고  [Confirm]

저장 완료 후 채팅에 아래 형식으로 보고한다.

```
FigJam 저장 완료 (YYYY-MM-DD)
├── 탈락: N개
├── 생존: N개
├── 결정: N개
└── 다음 스텝: N개
```

---

## 운영 규칙

- FigJam 기존 콘텐츠는 **절대 삭제하지 않는다**
- 날짜 카드는 누적 저장 (같은 날도 덮어쓰지 않고 옆에 추가)
- 항목이 비어 있는 섹션은 렌더하지 않는다
- 탈락 이유가 있으면 이유도 같이 기록한다
- 로드맵/Phase 정보가 있으면 "결정 사항"에 현재 위치를 포함한다

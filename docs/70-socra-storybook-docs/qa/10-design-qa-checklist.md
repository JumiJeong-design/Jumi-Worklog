# 10. Design QA Checklist

## 1. 문서 목적

이 문서는 Socra AI의 UX/UI 완성도를 검수하기 위한 체크리스트다.

기준은 단순히 “구현됐는가”가 아니라, 경쟁 서비스와 비교했을 때 부족하지 않은가, 사용자가 답변 비교 구조를 쉽게 이해할 수 있는가, 모바일/다크모드/다국어/긴 텍스트에서도 완성도가 유지되는가이다.

---

## 2. UX 구조 검수

| 체크 | 질문 |
|---|---|
| 목적이 명확한가 | 이 화면에서 사용자가 무엇을 판단해야 하는지 즉시 보이는가 |
| 정보 위계가 적절한가 | Summary → Stance → Detail → Source/Chart 순서가 자연스러운가 |
| 비교가 쉬운가 | 여러 모델/에이전트 답변의 차이가 빠르게 보이는가 |
| 종합 판단이 있는가 | 단순 나열이 아니라 Socra가 정리해주는가 |
| 긴 텍스트가 피로하지 않은가 | 접기/펼치기, 요약, 원문 보기 구조가 적절한가 |
| 모바일에서 자연스러운가 | 좁은 화면에서 핵심만 먼저 보이는가 |
| PC에서 공간 활용이 좋은가 | 병렬 비교와 요약 고정이 자연스러운가 |

---

## 3. UI 완성도 검수

| 체크 | 질문 |
|---|---|
| 간격이 안정적인가 | 카드/텍스트/섹션 간 spacing이 일관적인가 |
| 타이포 위계가 선명한가 | 제목/요약/본문/메타가 구분되는가 |
| 카드 구조가 명확한가 | AgentAnswerCard, SourceCard, ChartContainer의 역할이 구분되는가 |
| 색상 사용이 과하지 않은가 | 의미 없는 컬러가 많지 않은가 |
| 다크모드가 어색하지 않은가 | 대비, surface, border가 안정적인가 |
| 아이콘/배지가 과하지 않은가 | 스캔을 돕되 장식적이지 않은가 |
| 모션이 상태를 설명하는가 | 예쁘지만 산만하지 않은가 |

---

## 4. Multi-agent UX 검수

| 체크 | 질문 |
|---|---|
| Agent와 Model이 구분되는가 | 사용자가 누가 말하는지 이해하는가 |
| Agent character가 과하지 않은가 | 신뢰를 해치지 않는 수준인가 |
| 모델별 입장이 한눈에 보이는가 | StanceRow가 충분히 명확한가 |
| 결론이 갈릴 때 이해되는가 | DisagreementBlock이 도움이 되는가 |
| 결론이 같을 때 납득되는가 | ConsensusBlock이 반복을 줄이는가 |
| 일부 실패해도 UX가 유지되는가 | 실패 카드가 전체 경험을 망치지 않는가 |

---

## 5. Source / Trust 검수

| 체크 | 질문 |
|---|---|
| 출처가 답변과 연결되는가 | Citation과 SourceCard가 매핑되는가 |
| 출처 타입이 보이는가 | web/file/history/model 구분 |
| 출처 없는 답변이 정직하게 보이는가 | 추론/확인 필요 상태가 보이는가 |
| 출처 카드가 너무 무겁지 않은가 | 답변을 압도하지 않는가 |
| 모바일에서 출처 접근이 쉬운가 | sheet/expand 구조가 자연스러운가 |

---

## 6. Chart 검수

| 체크 | 질문 |
|---|---|
| 차트가 판단을 돕는가 | 장식이 아니라 비교/판단에 기여하는가 |
| 차트 제목/설명이 충분한가 | 무엇을 보여주는지 즉시 알 수 있는가 |
| 수치 출처/산식이 있는가 | 숫자가 어디서 왔는지 알 수 있는가 |
| 모바일에서 라벨이 깨지지 않는가 | 긴 라벨 처리 |
| 다크모드에서 축/tooltip이 보이는가 | 대비 확인 |
| 데이터 없을 때 fallback이 있는가 | empty/error state |

---

## 7. 다국어 검수

| 체크 | 질문 |
|---|---|
| 한국어 | 기준 화면이 자연스러운가 |
| 영어 | 긴 단어/문장이 깨지지 않는가 |
| 일본어 | 줄바꿈과 문장 밀도가 어색하지 않은가 |
| 버튼 라벨 | 작은 공간에서 overflow되지 않는가 |
| Agent role | 번역 후 캐릭터성이 유지되는가 |
| Chart labels | 축/범례/tooltip이 깨지지 않는가 |

---

## 8. Interaction / Motion 검수

| 체크 | 질문 |
|---|---|
| Thinking motion | 현재 상태를 이해시키는가 |
| 답변 등장 | 여러 agent 답변이 자연스럽게 등장하는가 |
| 펼침/접힘 | 위치를 잃지 않고 자연스럽게 동작하는가 |
| Source preview | citation에서 source로 이동이 명확한가 |
| Chart tooltip | desktop/mobile 모두 조작 가능한가 |
| Copy/feedback | 조작 후 피드백이 즉시 보이는가 |
| Reduce motion | 모션 최소화 모드를 고려했는가 |

---

## 9. 레퍼런스/경쟁사 비교 검수

비교 대상 후보:

- ChatGPT
- Claude
- Perplexity
- Poe
- Gemini
- Consensus / Elicit 계열 research UI
- Notion AI
- Linear / Raycast 등 polished SaaS UI

### 비교 항목

| 항목 | 질문 |
|---|---|
| 답변 가독성 | 긴 답변이 읽기 좋은가 |
| 출처 표현 | Perplexity 대비 신뢰감이 충분한가 |
| 모델 구분 | Poe처럼 모델 구분이 명확한가 |
| 비교 UX | Socra만의 차별점이 보이는가 |
| UI 밀도 | 너무 빽빽하거나 허전하지 않은가 |
| 모바일 완성도 | 모바일에서 자연스럽게 쓸 수 있는가 |
| 다크모드 | 경쟁 서비스 수준으로 안정적인가 |
| 모션 | AI 서비스다운 생동감이 있는가 |

---

## 10. 최종 리뷰 기준

| 점수 | 기준 |
|---|---|
| 1 | 구현은 됐지만 UX/UI 품질이 낮음 |
| 2 | 기본 사용 가능하지만 edge case에서 깨짐 |
| 3 | MVP 수준으로 충분함 |
| 4 | 경쟁 서비스와 비교해도 부족하지 않음 |
| 5 | Socra만의 차별화와 완성도가 느껴짐 |

6월 목표는 주요 P0 화면에서 평균 3 이상, 핵심 비교 UX에서는 4에 가까운 상태를 목표로 한다.

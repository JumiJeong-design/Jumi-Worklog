## 1. 프로젝트 개요

### 한 줄 정의
일본 유저 타겟 AI 멀티 모델 기반 고민 상담 서비스.

### 제품 목표
AI 기술을 활용하여 복합적인 문제에 대한 다각적 관점을 제시하되, 단일한 '정답'을 내리는 것이 아니라 사용자가 고민의 '방향'을 잡도록 돕는다. 사용자의 상황에 맞춰 'Quick'·'Deep'(사용자가 선택)과 'Chat'(자동 개입)으로 답변 형태를 제공하고, 그 답변 안에서 질문 주제에 맞는 **전문가 수준의 에이전트 의견까지 함께 제시**함으로써 새로운 상담 경험과 사용자의 신중한 의사결정을 돕는다.

### 배경과 사용자 문제
현대 사회에서 사람들은 커리어, 대인관계, 건강·의료, 육아, 금융, 법률 등 다양한 영역에서 복합적인 고민을 안고 있다. 이런 고민은 혼자 판단하기엔 리스크가 크고, 너무 개인적이거나 민감해서 주변에 털어놓기 애매하며, 전문가를 찾아가기엔 이르거나 비용이 부담되고, 검색해도 정보만 많을 뿐 내 상황에 맞는 기준이 안 잡힌다. 일본에서도 AI에게 고민을 묻는 사람이 늘었지만 AI 답변 신뢰에 회의적인 사람도 적지 않다. 단일 AI 답 하나로는 신뢰를 주기 어렵다. 특히 일본 시장은 정서적 교감과 신중한 의사결정을 중시하는 문화 특성이 있다.

### 해결 방안과 차별점
고민에 따라 'Quick', 'Deep' 두 답변 모드를 제공(단순 질의응답 ~ 다수 AI 모델·전문가 에이전트의 심층 다각 분석). 추가 질문/단순 응대가 필요하면 'Chat'이 자동 개입. Gemini·GPT·Claude 등 복수 최신 모델 + 질문 최적화 에이전트로 다각 답변을 실시간 제공하고, 핵심 의견을 종합·시각화. 일본 정서·문화에 맞는 섬세·공감 답변으로 차별화. 정답을 대신 내리기보다 사용자가 스스로 납득하는 판단에 이르도록 돕는다.

### 타겟 사용자
일상(커리어·대인관계·건강·의료·육아·금융·법률)에서 복합 고민을 갖고 다양한 관점으로 신중히 의사결정하고 싶은 일본 사용자. 특히 **너무 개인적/민감해 주변에 털어놓긴 애매하지만 혼자 안고 스트레스받는 고민을 스스로 해결하고 싶은 사용자**가 핵심 타겟. (AI 수용도 높고 새 상담 경험 원함.)

### 사용자 시나리오
일본 거주 30대 직장인 김하나. 투자 고민 → 서비스 추천받아 접속 → 기본 Quick에서 Gemini·GPT·Claude가 서로 다른 관점을 200자 내외로 빠르게 제시 → 더 깊은 분석 원해 Quick 하단 "ㅇㅇ 전문가의 의견도 확인해볼까요?" 클릭 → Deep 전환 → 고성능 모델 + 투자 전문 에이전트 매칭 상세 분석 + 종합 요약·시각화 선택지 → 자신에 맞는 방향에 확신, 신중히 결정.

## 2. 주요 기능 (사용자 흐름 순)

### 2.1 멀티 AI 상담 시스템과 공통 원칙

**구성 요소 — 모드**
- **Quick:** 여러 AI(Gemini·GPT·Claude)가 모델별 말풍선으로 빠르게 답 + 'AI들의 의견 요약' + (가설형이면) 선택지·가중치 시각화 (→2.4·2.5).
- **Deep:** 3개 모델 + 도메인 전문 에이전트(최대 7명) 매칭, 심층 답변 + 상세 비교(공통/고유 의견) (→2.8·2.9).
- **Chat:** 별도 모드 아님. 모더레이터(단일 모델)가 응답하는 자동 트리거 — ① 답변 가능한 '질문'이 아닌 입력, ② 사실확인형(`factual`, 웹서치 출처 링크). Quick/Deep과 무관하게 흐름 전·중·후 등장 (→2.3).

**구성 요소 — 응답 주체**
- **AI 모델(Gemini·GPT·Claude):** 멀티 의견(모델별 답변 1개씩).
- **AI 에이전트(롤 에이전트):** 질문 도메인 전문 의견(Deep, 최대 7명 → 2.6).
- **모더레이터(단일 모델 = Gemini):** 특정 모델이 아니라 **대화 전체를 진행하는 역할**. 정답을 대신 내리지 않고 판단 기준을 찾도록 돕는 진행자.
  - 트리거: ① Chat 응답(질문 아닌 입력/`factual`, 2.3) / ② AI들의 의견 요약 생성(Quick/Deep 답변 모인 뒤, 2.5·2.9) / ③ 후속 질문 제안(맥락 부족).
  - 출력: AI들의 의견 요약 / 핵심 쟁점·판단 기준 / 다음 행동 제안 / `simple` 직접 응답 / `factual` 사실 답변(웹서치 출처).
  - 시각 표현(아바타/심볼/이름)·말투 범위는 디자인·[Open Issues]에서 결정.

**구성 요소 — 답변 구성 요소(의견 템플릿)**
- **모델·에이전트 개별 의견:** 각 AI가 낸 서로 다른 관점의 답변. 다양한 시각의 원천.
- **AI들의 의견 요약:** 여러 답변 핵심을 한두 문장으로 종합.
- **선택지·가중치:** 질문에 대한 직접 답 후보(선택지) + 각 후보를 AI들이 얼마나 지지하는지(가중치).
  - 설계 의도: 한 선택지를 '정답'으로 단정하면 사용자 대신 결정하는 셈. 각 선택지의 **지지 정도(합의)와 남는 이견**을 함께 드러내 사용자가 스스로 무게를 달게 함. 소수 의견도 0%가 아닌 한 사라지지 않음. (제품 목표 '정답 대신 방향'과 일치.)
  - 산출: **개별 지지도** = 각 모델·에이전트 답변 내용을 분석해 0~100%(자기보고 숫자 아님, Deep은 '지지율 칩'으로 노출 2.9). **종합 가중치** = 모든 모델·에이전트의 해당 선택지 지지도 평균(도착한 답변만). 근거 추적 = 그 주체의 답변 자체(Quick=말풍선, Deep=전문 바텀시트).
- **공통·고유 의견:** 한 선택지에 대해 공통 동의 근거 vs 일부가 추가로 짚은 관점.
- **추가 질문:** 상황을 좁혀 더 정확한 답으로 가게 모더레이터가 던지는 후속 질문.

> **'리포트' 정의:** 개별 말풍선을 종합한 결과물 = AI들의 의견 요약 + 선택지·가중치(+ Deep의 공통·고유·지지율). 개별 말풍선과 구분되는 '정리·종합' 영역. **추가 질문·전문가 후킹은 리포트에 미포함.**

**공통 원칙**
- **답변 형태 분류 → 구성:** 핵심 갈림 = '여러 AI로 분석할 고민(의사결정 질문)이냐'.
  - `simple`(Chat): 인사·잡담·단순 사실 + 위기 신호(자해·타해). 모더레이터 응답(2.3).
  - `factual`(Chat 단일 모델 + 웹서치 출처 인라인, 멀티·그래프 없음, 2.3).
  - `hypothesis_binary`(택일 예/아니오·A/B): 2개 선택지 + 가중치 그래프.
  - `hypothesis_nonbinary`(여러 갈래): 2~5개 선택지 + 가중치 그래프.
- **입력:** 텍스트 기본 + 파일 첨부(이미지·문서, '+'). 형식·용량은 [Open Issues].
- **맥락 활용:** 세션 내 누적 대화 맥락만. 세션 넘는 기억·프로필 개인화 없음. 비로그인은 세션 미저장.
- **비로그인 접근:** Quick 1회 체험 가능(무료 여부·횟수 [Open Issues]). 그 이상 질문·모든 Deep은 로그인. 비로그인엔 후킹 강조(2.7)로 가입 유도. 비로그인 세션 미저장.
- **생성 중 입력창:** 유지하되 전송만 비활성(끝나면 재활성). 숨기거나 입력 차단 안 함.
- **플랫폼:** 모바일 퍼스트(결과 화면 모바일 기준, 웹 확장 대응).
- **언어:** 안내·UI 카피는 자연스러운 일본어, 모델/브랜드/모드명('Quick'/'Deep')·기술 용어·URL·숫자는 원표기. **AI 답변 본문 출력 언어는 사용자 입력 언어를 따름**(답변정책 §1).

**수용 기준(2.1):** 입력 분류 라우팅(simple/factual→Chat, 가설형→Quick/Deep) · Quick=3모델 각 200자 내외(답변 자체) · Deep=고성능 모델+에이전트 매칭 · 종합 후 모더레이터 의견 요약(한두 문장) · 모더레이터는 쟁점·판단 기준/다음 행동 포함 · 맥락 부족 시 후속 질문 · 생성 중 로딩 인디케이터 · 생성 중 입력창 유지+전송만 비활성 · 일본어 UI(고유명사 원표기). (답변 생성 시간 기준 미정 → [Open Issues].)

### 2.2 진입 및 모드 설정
- 최초 진입 시에만 기본 모드 Quick.
- 이후 Deep 전환하면 그 값 유지. 새 세션·재시작해도 Quick 초기화 안 함, 마지막 선택 모드 따름.
- 세션 내 Quick↔Deep 전환 시 이후 응답은 선택 모드로.
- 모드 전환 버튼은 상단 또는 입력창 주변, 현재 모드 라벨 표시. 전환 시 토글 애니메이션 피드백. **별도 토스트 없음**(현재 모드가 토글·라벨로 상시 보이므로 중복).

### 2.3 Chat 답변 생성
Chat = 단일 모델(Gemini) 하나로 구성, '모더레이터' 역할의 단독 목소리.
- **등장 시점:** Quick/Deep 무관, 흐름 전·중·후 언제든.
- **트리거:** ① 인사·무의미 ② 의도 불명 ③ 감정 토로만 ④ `simple`(단순·저위험 사실, 단 최신값·출처 중요하면 `factual`) ⑤ 위기 신호(→안전 안내, 답변정책) ⑥ `factual`(웹서치 출처 인라인, 멀티·그래프 없음).
- **대화 안 끊음:** 항상 다음 대화로 이어지게(위기 신호 포함). 끝맺음 질문형 어조는 답변정책.
- 역할 ① 단순 응답(짧게 직접) / ② 질문 유도(유도 질문이 본체, Quick/Deep로 연결) / ③ `factual` 사실 답변(웹서치 출처, 실패 시 출처 없이 답+불확실성 밝힘, 답변 자체 불가면 전체 실패 3.1).
- **우선순위:** Chat 케이스(①~⑥) > 사용자 선택 모드(Quick/Deep).
- **렌더링:** 메시지 타입별 카드 구분(사용자 입력/일반 답변/요약/선택지 시각화/Chat 유도 질문).

### 2.4 Quick 답변 생성 (멀티 모델 동시)
- Gemini·ChatGPT·Claude 3개(모델별 1개씩), 각 **200자 내외**(요약 아님, 답변 자체).
- **도착 순서대로 노출.** 미도착 = '생각 중', 실패분은 한도 내 자동 재시도(재시도 비노출).
- **의견 요약·시각화는 모아서:** 개별 답변 다 모인 뒤 한 번에 구성. 한도 내 도착분만(3중 2면 2개로), 0건이면 전체 실패(3.1).
- 재시도·타임아웃 값 [Open Issues]. 공통 포맷(핵심 조언 1~2문장 + 주의점 1문장 등).

### 2.5 Quick 답변 종합 및 시각화
Quick은 가설형 질문(사실확인형은 Chat, 2.3).
- **공통 요소:** AI들의 의견 요약(상단, 한두 문장) · 각 말풍선 200자 그대로 모두 표시('더 보기' 접기 없음) · 추가 질문 영역 · 전문가 후킹(하단, 2.7).
- **선택지·가중치:**
  - 선택지 = 답변 3개 클러스터링 → 2~5개. '행동 대안' 아니라 **질문에 대한 직접 답변**(예: '할까요 말까요'→'한다/안 한다', '어디로 놀러갈까'→오사카/홋카이도/오키나와).
  - 가중치 = 모든 모델 해당 선택지 지지 % 평균(도착분만). **누적 막대(합계 100%) + 숫자(%)** 함께. 그래프 형태(막대/도넛)는 UI 단계 결정.
  - **Quick 범위:** 종합 가중치 + 간단 공통/차이까지. **개별 지지도 칩·전문 에이전트·공통/고유 풀 전개·전문 바텀시트·에이전트 프로필은 Deep 전용.**
- **수용 기준(2.5):** 시각화 선택지 제공 · 선택지 위 한두 문장 요약 · 가중치는 답변 분석 산출(자기보고 아님) · 가중치=숫자%+그래프 · 간단 공통/차이 · 추가 질문.

### 2.6 에이전트 목록 및 추천 로직
- 속성: 이름·전문분야·목표·기본 톤·말투 가이드·금칙 표현·사용 모델·출력 포맷·보유 정보(RAG 도메인)·프로필 소개. (프로필은 Deep 전문 바텀시트 노출.)
- 영역: 커리어/대인관계/건강·의료/육아/금융/법률 등.
- 추천: 질문의 주제·감정 톤·의사결정 유형을 LLM 분류로 선정. Deep 최대 7명, Quick 후킹은 1명. 현재는 질문 분류 결과만(모델 답변 보조 신호 미활용).
- **자동 매칭**(사용자 선택 아님).

### 2.7 Deep 전환 유도 (Quick 하단 후킹)
- 질문과 가장 맞는 에이전트 1명(2.6)으로 하단 후킹. Quick 결과와 함께 한 번에 노출.
- 템플릿 'ㅇㅇ 전문가의 의견도 확인해볼까요?'(압박 없이 완곡 변형 허용).
- 클릭 시 **직전 Quick 질문 그대로** Deep 생성 즉시 시작(새 질문 안 받음, 2.8 경로①).
- 비로그인엔 강조 애니메이션 + 적합 에이전트 추천으로 가입 동기↑. 클릭 시 로그인·가입 후 Deep(2.1).

### 2.8 Deep 답변 생성 (에이전트 매칭)
- 경로 ①(후킹 클릭): 입력했던 질문 그대로 Deep 생성. 경로 ②(토글 직접 전환): 추가 질문 없이 모드만 바뀌고 이후 입력부터 Deep.
- 두 경로 모두 고성능 모델 + 전문 에이전트(최대 7명) 매칭(2.6) 심층 답변.
- **진행 단계 표시(실제 진행 기반):** ① 질문 분석 중 → ② 답변할 전문가 지정 중(하나씩 등장) → ③ 전문가들이 의견 생각 중. 실패·재시도 비노출.

### 2.9 Deep 답변 종합 및 선택지 상세 비교
Deep은 가설형 질문. 공통 요소 + 선택지·가중치 + 선택지별 공통/고유.
- **공통 요소:**
  - AI들의 의견 요약(상단).
  - **공통 vs 고유 기준:** 전원 만장일치 언급만 공통. 그 외는 고유(1명=그 AI 고유, 2명↑ 비슷=공동 고유). 고유=반대 아님, 같은 답 지지하며 공통에 없는 추가 관점(다른 근거·리스크·대안).
  - 빈 영역: 고유 없으면 고유 영역 미표시(공통만). 공통 없으면 공통 비우고 고유만 가능.
  - **답변 전문 접근:** 모델·에이전트 이름(지지율 칩·고유 카드) 클릭 → 그 주체 답변 전문 **바텀시트(모달)**. (전체 한 번에 펼치기 없음 — 필요한 주체만.)
  - **에이전트 프로필(바텀시트 내):** 전문 분야·보유 정보(RAG)·능력·한 줄 소개. (개별 모델은 프로필 없이 모델명만.)
  - 추가 질문 영역(2.5와 동일).
- **선택지·가중치 시각화:**
  - 선택지 = Deep 답변 클러스터링 2~5개, 직접 답변 형태.
  - 가중치 = 모든 모델·에이전트 지지 % 평균(도착분만).
  - **모델·에이전트별 지지율:** 각 선택지 안에 모든 주체의 지지율을 **칩**으로(예: '대기업 선택'→노무 90%, GPT 70%, Claude 50%). 종합(칩 평균) + (주체×선택지) 함께. 칩 의미 안내 문구 동반(카피는 디자인 확정).
  - **공통/고유 표시:** 각 선택지마다 공통·고유를 **처음부터 모두 펼쳐(앙케이트 결과지처럼)**. 클릭 펼침 아님.
  - **고유 의견 2단:** 한 줄 요약 + 상세 근거(전문 바텀시트와 별개 인라인).
  - **레이아웃:** 선택지별 공통 요약 →(구분선)→ 고유 카드(이름 + 글머리 근거) 순, 모든 선택지를 한 화면 스크롤에 순서대로 펼침.
- **수용 기준(2.9):** 의견 요약+시각화 선택지 · 선택지별 공통 요약+고유(없으면 미표시) · 모델·에이전트별 지지율 · 이름 클릭 답변 전문 · 바텀시트에 에이전트 프로필.

### 2.10 세션 저장 및 재열람
- **계정 단위 저장.** 비로그인은 창 닫으면 사라짐(저장·재열람 불가).
- 세션 목록 + 선택 시 시간순 재열람, 화면은 **가장 끝(최신)** 에서 열림.
- 정렬 = **마지막 질문 시각 최신순**(다른 정렬·뷰 없음, 검색 MVP 제외).
- 각 세션 = 첫 질문 요약 한 줄(넘치면 …) + 마지막 질문 시각.
- **소프트 삭제:** 목록에서 제거되나 내부엔 '삭제됨' 보관(영구 삭제 아님, 보관 기간·고지 [Open Issues]).
- 자동 저장(송·수신 시). 저장 실패 재시도→지속 실패 시 안내. 데이터 암호화.

### 2.11 피드백 및 품질 개선
- 답변 전체 단위 도움 됨/안 됨(Quick/Deep/Chat). 개별 모델·에이전트 단위도(Quick=말풍선, Deep=전문 바텀시트, 선택).
- '도움 안 됨' 후 사유 선택(선택): 사실 틀림/상황 안 맞음/뻔하고 얕음/한쪽 치우침/어조 불편/기타.
- 저장: 세션ID·메시지ID·대상(전체/개별)·응답 유형·모델·에이전트·타임스탬프·언어톤 버전. 개선 루프로 금칙·톤 업데이트.

## 3. 예외·에러·빈 상태 처리

**3.1 답변 생성** — 실패 유형: 일부 실패 / 리포트 생성 실패 / 전부 실패(0건).
- **전부 실패(Quick·Deep 공통):** 자동 재시도→한도 초과 시 '다시 시도' 버튼(질문 그대로 재생성, 입력 보존).
- **Quick 일부 실패:** 자동 재시도('생각 중'만)→안 오면 그 모델 빼고 도착분으로 구성(2개면 2개). 요약·가중치는 도착분 기준.
- **Quick 리포트 실패:** 자동 재시도→안 되면 오류 문구 대신 **거슬리지 않는 '다시 불러오기'** 버튼(말풍선 유지).
- **Deep 일부 실패:** 자동 재시도→안 오면 빼고 구성. 단 **도착분 너무 적으면(예:3개 이하) 부분 구성 안 하고 전부 실패로 '다시 시도'**(Deep은 여럿 모여야 의미).
- **Deep 리포트 실패:** 종합이 본체라 재시도 후 실패면 전체 실패 준해 '다시 시도'(종합만 재생성).
- **에이전트 매칭 실패:** 모델 3개 답변만으로 진행, **사용자에 안 알림.**

**3.2 저장·불러오기:** 재열람/목록 로드 실패 시 에러 + '다시 시도'.
**3.3 네트워크·입력:** 오프라인=안내+입력 보존(재전송). 과부하='잠시 후 다시'. 빈 입력=전송 비활성, 과도 길이=안내.
**3.4 빈 상태:** 세션 목록 비면 안내 + '질문 시작하기'.

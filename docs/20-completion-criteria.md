# 완료 기준 — 1차 / 공유 가능 / 픽스

> 에이전트가 말하는 "완료"와 디자이너가 말하는 "완료"가 다르다.
> 에이전트는 기획이 그려지면 끝이라 보고, 디자이너 기준으로는 시각 품질과 UX 검토가 남아 있다.
> 이 간극은 남은 작업을 어디에도 기록되지 않은 채 사람 머릿속에만 쌓는다.
> 완료를 3단계로 쪼개고 각 단계의 기준을 명시한다.
> 작성일: 2026-08-19

## 3단계

| 단계 | 뜻 | 누가 선언 | 공유 |
| --- | --- | --- | --- |
| `1차` | 기획·구조가 그려짐 | 에이전트 | 공유하지 않음 |
| `공유 가능` | 구조·방향이 섬. 디테일은 미픽스 | 에이전트 자가 검사 → 디자이너 확인 | 팀 공유 OK |
| `픽스` | 품질·UX 검토 끝 | 디자이너만 | 변경 시 공지 |

기존 Figma 화면 상태와 같은 사다리다. `공유 가능` ≈ `candidate`, `픽스` ≈ `approved screen`.

## 에이전트 보고 규칙

- **"완료"를 단독으로 쓰지 않는다.** 항상 단계명으로 보고한다.
- `1차 완료 — 남은 것: 시각 품질, UX 흐름`처럼 **남은 단계를 문장으로 남긴다.** 남은 일이 사람 머릿속이 아니라 기록에 있어야 한다.
- `공유 가능`은 아래 기준을 자가 검사하고 결과를 보고에 첨부했을 때만 선언한다.
- `픽스`는 에이전트가 선언할 수 없다. 준비만 한다.

## 공유 가능 기준

하나라도 미충족이면 `공유 가능`으로 부르지 않는다.

1. **목적 한 문장** — 이 화면/컴포넌트가 해결하는 사용자 목적
2. **핵심 흐름·분기** — IA와 사용자 분기가 정의됨
3. **DS 준수** — 승인된 컴포넌트/인스턴스만 사용. 손코딩 0
4. **핵심 상태** — 그 화면에 필요한 상태가 있음 (empty/loading/error/disabled 전체 강제는 아님)
5. **출처 근거** — Figma node id·variables 또는 `riiid/prism` 계약. 없으면 `pending`으로 두고 추측하지 않는다
6. **미결 질문 분리** — 디자이너 판단이 필요한 항목이 목록으로 뽑혀 있음
7. **공유 라벨** — `구조·플로우 픽스 / 비주얼·디테일 미픽스`처럼 무엇이 픽스인지 명시

문구는 lorem만 아니면 된다. 확정 문구는 `픽스` 몫이다.

## 픽스 기준

디자이너 판단이다. 에이전트는 선언하지 않는다.

1. **UX 흐름** — 사용자가 주요 행동을 바로 찾는가
2. **시각 품질** — 위계·밸런스·브랜드 톤
3. **토큰 준수** — spacing·typography·color 임의값 0
4. **QA 축** — 전 축이 아니라 그 컴포넌트의 **리스크 우선 축만**. 축 정의는 `socra-ai-workflow-wiki`의 `wiki/playbooks/33-storybook-qa-harness.md`가 소유한다
5. **실제 도는 표면에서 확인** — 컴포넌트 안은 Storybook, 화면 밖은 앱
6. **승인 기록** — 승인 대기와 승인 완료를 구분해 기록

## 왜 3단계인가

- **팀 병목이 풀린다.** 디자이너 품질 검토가 끝날 때까지 아무도 못 움직이던 구조에서, `공유 가능` 시점에 FE 착수와 리뷰가 시작된다. 폴리시는 그 뒤로 병렬 진행한다.
- **일정을 두 날짜로 말할 수 있다.** `공유 가능일`은 예측 가능하니 팀에 약속하고, `픽스일`은 AI 품질 편차와 진행 중 발견되는 범위 때문에 구간으로만 말한다.
- **공유 라벨이 디자이너를 지킨다.** 라벨 없이 공유하면 미픽스 디테일에 피드백이 쏟아져 부하가 오히려 늘어난다.

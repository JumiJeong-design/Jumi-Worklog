# 08. 다크에서 「선이 연해 보인다」는 대비비로 안 잡힌다

상태: ✅ 완료 · 기간: 2026-08 ~ 09

## 문제 정의 / 도입 배경

다크 모드에서 구분선이 연해 보인다는 지적이 왔다. 대비비를 재니 다크가 라이트보다 오히려 높게 나왔다. 수치로는 문제가 없는데 눈에는 문제가 있었다.

## 목표

- [x] 왜 수치와 눈이 어긋나는지 가른다
- [x] 눈에 맞는 척도를 찾는다
- [x] 모드별 토큰으로 가른다

## 사용한 툴

- Claude Code · 헤드리스 렌더 · CIELAB 계산

## 작업 과정

### 1단계. 대비비가 왜 거짓말하나

- WCAG 대비비의 0.05 오프셋이 어두운 쪽을 부풀린다. 다크에서 같은 차이가 더 큰 비율로 나온다.
- 원인은 선 색이 아니라 표면 단차였다. 라이트는 surface와 raised가 둘 다 흰색이라 단차가 없고, 다크는 단차가 있어 선이 묻힌다.

### 2단계. ΔL*로 다시 쟀다

- 밝기 차(ΔL*)로 재니 눈과 맞았다. 값을 올려도 눈엔 안 들어올 수 있어 렌더로 먼저 봤다.
- 얹힌 판(fill-subtle)과 파인 홈(inset)은 다크에서 반대로 움직이고, 어느 쪽이 잘 보이는지는 배경에 따라 뒤집힌다.

### 3단계. 선뿐 아니라 얹힌 판도 무너졌다

- `neutral/100` 직결은 다크에서 카드 표면과 같은 색(ΔL* 0.0)이었다. 라이트만 보면 안 드러난다.
- 한 값으로 통일하면 한쪽이 손해라 모드별 토큰(`bg.fill-subtle`)으로 갈랐다.

## 트러블슈팅

**문제 1**: 화면 지적을 이름 비슷한 컴포넌트에서 찾았다
- 원인: 실제 쓰인 컴포넌트가 아니었다.
- 해결: 화면 지적은 실제 쓰인 것으로 확인한다.

**문제 2**: 명암비 감사가 그라디언트 위 글자를 통째로 오탐했다
- 원인: SOLID만 훑었다. 31건.
- 해결: 그라디언트 뒷면까지 넣고 라이트 대조군과 규모를 맞춰 잰다. 다크 3.1% < 라이트 7.8%로 회귀가 갈렸다.

## 결과

- 척도가 대비비에서 ΔL*로 바뀌었다. 선과 얹힌 판 둘 다 모드별 토큰으로 갈렸다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 대비비 오프셋이 왜 부풀리는지 찾고 ΔL*로 재계산한 것.
- 디자이너: 「이상하다」를 먼저 본 것. 수치가 괜찮다고 해도 눈을 믿은 것.

## 아쉬운 점 · 리스크

- ΔL*도 만능은 아니다. 배경에 따라 뒤집히는 경우는 렌더로 봐야 한다.

## 공유할 만한 사항

- 다크 선 문제는 대비비 말고 ΔL*로 잰다. 값을 올려도 렌더로 먼저 본다.

## 한 줄 평

수치가 괜찮다고 할 때 눈이 이상하면 척도를 의심한다.

# 09. 공유 워킹트리 사고 셋 → 워크트리 격리와 훅

상태: ✅ 완료 · 기간: 2026-08-11 ~ 09-08

## 문제 정의 / 도입 배경

Claude 세션 여럿이 한 폴더를 썼다. 커밋 소유가 흐려졌다. 내용은 안 잃지만 커밋 메시지와 실제 내용이 어긋나고, 나중에 이력에서 그 판단을 찾을 수 없다.

## 목표

- [x] 사고 패턴을 가른다
- [x] 규칙으로 막아 본다
- [x] 규칙이 안 지켜지면 훅으로 옮긴다

## 사용한 툴

- git worktree · Claude Code 훅(PreToolUse · SessionStart) · `scripts/new-desk.sh`

## 작업 과정

### 사고 1 (8/11). `git add -A`

- 옆 세션의 미커밋 작업이 내 커밋에 딸려 갔다. 규칙이 생겼다.

### 사고 2 (8/24). 브랜치 공유

- 내 커밋이 옆 세션 브랜치에 얹혔다. 옮긴 뒤엔 반대로 옆 세션 커밋이 내 브랜치에 쌓였다. 두 세션의 커밋 저자가 똑같아서 `git log`로는 못 가린다. 시각과 내용으로 본다.

### 사고 3 (8/27). 파일 지정 add도 섞였다

- 파일을 지정해 add했는데 옆 세션이 방금 고친 내용이 함께 잡혔다. 두 번 났다. 한 문서를 여러 세션이 순차 수정하면 커밋을 갈라낼 수 없다. 22개를 통째로 한 PR에 담아야 했고 남의 커밋 넷이 딸려갔다.

### 결론. 규칙만으로는 안 된다

- 커밋할 일이 있으면 세션 시작 때 `new-desk.sh`로 워크트리를 나눈다. 충돌 보고를 받으면 늦다.
- 9/8에 훅 셋을 넣었다. 공유 폴더에서 `add -A`·`reset --hard`·`checkout main`·`rebase`를 실행 직전에 막는다. 격리 워크트리는 git-dir 비교로 안 막는다.

## 트러블슈팅

**문제**: 스택 PR의 아래쪽이 squash되면 위쪽이 add/add 충돌
- 원인: base가 갈린다.
- 해결: 리베이스 말고 위쪽 고유 커밋만 새 main 위로 cherry-pick.

## 결과

- 세션 시작 브리핑에 「공유 트리 여부 · 뒤처진 커밋 수」가 뜬다. 위험 명령은 막힌다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 사고 패턴 셋을 갈라 적고 훅을 쓴 것.
- 디자이너: 「규칙이 있는데 왜 또 났나」를 물은 것.

## 아쉬운 점 · 리스크

- 훅은 메인 폴더에서만 산다. 격리 워크트리에 훅 파일을 복사해야 하는 일이 남았다.

## 공유할 만한 사항

```
커밋할 일이 생길 작업이면 시작 전에 scripts/new-desk.sh <브랜치이름>으로 책상부터 나누고 거기서 해줘.
```

## 한 줄 평

같은 사고가 두 번 나면 규칙을 더 적지 말고 실행 자리에서 막는다.

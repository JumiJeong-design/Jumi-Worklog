# 05. 모션을 효과적으로 고치고 git과 정합하는 법

상태: ✅ 1차 완료 · 기간: 2026-08 ~ 2026-09

## 문제 정의 / 도입 배경

피그마에는 정지 컷만 있다. 답변 대기 인디케이터, 딥 에이전트 무대의 버블 흡수, 캡슐의 실패 모션 같은 것은 피그마로 정할 수 없었다. 처음엔 정지 컷을 나란히 놓고 골랐는데, 그렇게 내린 첫 판단 셋이 셋 다 틀렸다. 움직이는 걸 보고서야 골랐다.

그리고 모션 값을 어디에 두고 어떻게 고치는지가 없었다. 값이 코드 여기저기에 상수로 박혀 있으면 후보를 바꿔 볼 수가 없다.

## 목표

- [x] 모션 정본을 정한다
- [x] 후보를 나란히 보고 고를 수 있게 한다
- [x] 확정된 값이 코드로 내려가는 경로를 만든다
- [ ] reduced-motion을 치환으로 굴리기 (지금은 제거로 굴러간다, 제품이 올릴 때)

## 사용한 툴

- Claude Code · 스토리북(컨트롤·흐름 스토리) · CDP 헤드리스 측정 · 피그마(프로토타입 배선은 지정할 때만)

## 작업 과정

### 1단계. 정본은 피그마가 아니라 스토리북

```
모션은 피그마 말고 스토리북으로 봐. 피그마를 지정하면 그때만 프로토타입 배선.
```

- 모션 수치가 컴포넌트 이름으로 검색되는 자리에 없을 수 있다. 그 문법을 빌려 간 화면 주석에 있기도 했다.

### 2단계. 후보는 한 화면에 나란히, 값은 컨트롤로

- 답변 대기 인디케이터: 3닷은 정지 프레임만 정의돼 있었다. 시머 텍스트로 가면서 폭을 문장 폭의 55%(mask-size 220% 환산), 2400ms 호흡 계열로 잡았다. 새 색 대신 gradient.brand-fill을 마스크로 썼다.
- 딥 에이전트 무대: 버블 하나는 최다 지지 선택지 한 곳으로만 흡수한다. 모든 지지처로 흡수하면 참여자 수가 어긋난다. 무대에 수 표기는 하지 않는다. 8/3에 정했던 「찍고 줄에 서기」는 폐기했다.
- 캡슐 실패 모션: morph에 한 번 튕김을 얹었다. 완성 박자와 실패 튕김이 왜 다른지를 스토리에 적었다.

값은 추측으로 고치지 않고 스토리 컨트롤로 넘긴 뒤, 확정되면 상수로 올렸다.

### 3단계. 재서 확인

- 호버·전환은 CDP로 잰다. 계약 수치는 렌더에서 다시 잰다.
- 위치를 쥔 요소에 CSS `scale`을 같이 걸면 translate까지 배율이 걸린다. scale은 자식으로. jsdom 게이트는 이걸 못 잡고 렌더만 잡는다.
- 흐름 스토리는 고정 폭이라 리사이즈 경로를 안 탄다. 폭 반응은 폭이 실제로 바뀌는 스토리로 잰다.

## 트러블슈팅

**문제 1**: 정지 컷으로 고른 모션이 틀렸다
- 원인: 모션 선택지는 스틸로 못 고른다. 세 번 다 틀렸다.
- 해결: 움직이는 후보를 한 화면에 나란히. 고르는 건 사람.

**문제 2**: reduced-motion이 치환이 아니라 제거로 굴러간다
- 원인: 모션을 끄면 정보까지 사라진다.
- 해결(보류): 급하지 않아 접었다. 다시 열 조건은 「제품이 올릴 때」.

**문제 3**: 「됐다」가 눈으로만 판정됐다
- 원인: 모션은 스크린샷으로 안 잡힌다.
- 해결: CDP로 전환 타이밍과 위치를 재고, 수치 표가 다 통과해도 컷을 한 장 본다.

## 결과

- 모션 정본이 스토리북으로 정해졌고, 흐름 데모 스토리(답변 대기 · 딥 에이전트 무대 · 캡슐 여덟 상태 전환)가 프리즘에 올라갔다.
- 값이 스토리 컨트롤에서 상수로 내려가는 경로가 생겼다. git에 남는 건 확정값과 「왜 이 값인가」다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 후보를 컨트롤로 바꿔 나란히 띄운 것. CDP로 전환을 잰 것. scale과 translate가 곱해지는 원인을 찾은 것.
- 디자이너: 어느 것이 맞는지 고른 것. 「버블은 한 곳으로만」처럼 정보가 어긋나는 모션을 걸러낸 것.

## 아쉬운 점 · 리스크

- 피그마에 모션이 없으니 피그마만 보는 사람은 모션을 모른다. 프로토타입 배선을 안 하기로 한 대가다.
- reduced-motion이 제거로 굴러가는 건 접근성 리스크로 남아 있다.

## 공유할 만한 사항

```
모션 정본은 피그마가 아니라 스토리북이야. 값은 추측으로 고치지 말고 스토리 컨트롤로 넘기고, 확정되면 상수로 올려줘. 후보는 한 화면에 나란히 놔줘.
```

## 한 줄 평

모션은 정지 컷으로 못 고른다. 고를 수 있는 자리(스토리북)를 정본으로 삼으면 git 정합은 따라온다.

# 21. 안 고치기로 한 결정들 — 결함처럼 보이는 다섯 자리

상태: ✅ 완료 · 기간: 2026-08-24 ~ 2026-09-09

## 문제 정의 / 도입 배경

에이전트에게 감사를 시키면 「이상한 자리」를 잘 찾아온다. 그런데 그중 상당수가 내가 일부러 그렇게 둔 자리였다. 면책 문구가 안 뜨는 화면, 안 보이는 막대, 「페이지 제목」이라고 적힌 헤더 156곳. 전부 결함으로 보고됐고 전부 의도였다.

문제는 한 번 설명해도 안 끝난다는 것이다. 에러 화면 면책 건은 세 번 다시 올라왔다. 의도가 코드에도 피그마에도 안 적혀 있으니, 다음 세션의 에이전트는 같은 자리를 또 결함으로 읽는다.

## 목표

- [x] 「의도인데 결함으로 읽히는」 자리를 모은다
- [x] 각 자리의 의도를 판정 가능한 문장으로 적는다
- [x] 다시 올라오지 않게 메모리에 남긴다
- [ ] 의도를 피그마 description이나 계약 문서에도 적는다

## 사용한 툴

- Claude Code · Figma MCP 전 페이지 실측 · 프로젝트 메모리

## 작업 과정

### 자리 1. 에러 화면의 면책 문구가 opacity 0이다

`chat/report`의 실패 계열 화면에서 「AI는 실수를 할 수 있습니다」 면책 줄이 꺼져 있고 socra 마크만 남는다. 전 페이지를 실측하니 면책 줄 37곳 중 19곳이 이 상태였다.

이유는 간단하다. **답이 안 나왔는데 면책 문구가 뜨는 게 이상해서 가려 둔 것**이다. 답변 자리는 남기고 내용이 없으니 면책만 끈다. 마크는 답변 블록의 화자 표시이지 면책 줄의 잔여물이 아니다.

「텍스트는 opacity 0인데 같은 줄 아이콘은 1」이라는 모양이 감사 스크립트에 잘 걸린다. 세 번 올라왔다.

### 자리 2. 헤더 「페이지 제목」 156곳

제품 파일 헤더 제목 자리 193개 중 156개가 더미 문구다. 누가 잘못 넣은 게 아니라 **override를 안 해서 마스터 기본값이 드러난 것**이다. 입력바 199개 중 22개도 같은 이유로 홈 문구를 달고 있다.

결정은 「그냥 더미로 두자」였다. 헤더 제목은 컷마다 대화 내용이 달라야 하는데, 채우려면 문구를 지어내야 한다. 제품 카피는 기획서가 정본이라 내가 못 채운다.

이 건은 처음에 「3곳」으로 올라왔다가 다시 재니 156곳이었다. 대표 자리 하나만 재면 규모를 못 잡는다.

### 자리 3. 소수 의견 막대가 안 보인다

의견 막대의 소수 대역(라임)은 **일부러 덜 보이게 둔 것**이다. 다크에서 흐릿해 보여도 「가라앉음이 깨졌다」로 읽고 밝기를 올리면 안 된다.

PR #604가 이걸 반대로 갔다. 램프 안에서 라임이 넷 중 가장 밝다는 `ΔL*` 판정으로 다크 값을 올렸는데, 방향이 틀렸다. **대역 색은 램프 안 상대 밝기가 아니라 막대가 얹히는 트랙과의 대비로 고른다.** 라이트에서 라임은 넷 중 가장 밝지만 트랙과 대비가 1.22라 실제로는 거의 안 보인다. 배경 대비가 「보이는 정도」를 정하기 때문이다. #619로 되돌렸다.

### 자리 4. 첨부 칩 hover가 진하다

hover 강조가 진해 보인다는 지적이 나왔다. 선 색이 원인인 줄 알았는데 재 보니 배경 틴트 10% 쪽이었다. 대안 컷 셋(틴트 낮춤 · 선만 · 둘 다)을 나란히 놓고 봤고, **진해 보여도 유지**로 정했다. hover가 눈에 띄는 게 첨부 칩의 역할이다.

값을 안 바꿨으니 피그마도 코드도 안 건드렸다. 대신 원인과 대안 컷을 결정 옆에 남겼다.

### 자리 5. 비활성 입력창의 안내 문구가 흐리다

이건 반대 방향의 사고다. 비활성 필드의 안내 문구만 유독 흐린 게 눈에 띄어서 봤더니, **원래 손으로 맞춰 둔 값을 감사가 결함으로 읽고 지운 것**이었다. 누가 `text-tertiary`를 50% 불투명도로 박아 뒀는데, 원시값 감사가 「마스터가 이미 쓰던 값」이라며 100%로 되돌렸다. 제품 파일 168곳이 그렇게 바뀌었다.

코드는 원래 맞았고 피그마 쪽이 어긋나 있었다. 정리하면 `semantic/disabled/fg`를 쓰는 게 맞다.

## 트러블슈팅

**문제**: 같은 자리가 세션이 바뀔 때마다 결함으로 다시 올라온다

- 원인: 의도가 사람 머릿속에만 있다. 코드와 피그마에는 「값」만 있고 「왜 이 값인가」가 없다. 감사 스크립트는 값만 본다.
- 해결: 판정 가능한 문장으로 메모리에 적었다. 「덜 보이는 게 맞다」가 아니라 「판정은 램프 안 밝기가 아니라 트랙 대비로 한다」처럼, 다음 사람이 같은 결론에 도달할 방법까지 적는다.

**문제**: 손보정을 결함으로 읽는다

- 원인: 마스터와 값이 다르다는 것 자체를 어긋남의 증거로 본다.
- 해결: 원시값이나 손으로 맞춘 불투명도를 토큰으로 묶기 전에, 그 값이 무엇을 보정하고 있었는지 먼저 본다.

## 결과

- 다섯 자리 모두 현행 유지. 값을 바꾼 것은 되돌린 #619 하나뿐이다.
- 각 자리의 의도를 메모리에 남겼다. 이후 같은 자리가 결함으로 올라온 일은 없다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 전 페이지 실측으로 규모를 정확히 잰 것(면책 37곳 중 19, 헤더 193곳 중 156). 진한 원인이 선이 아니라 틴트임을 픽셀로 가른 것.
- 디자이너: 다섯 자리 전부 「이대로 둔다」를 고른 것. 그리고 소수 의견 건에서 판정 기준 자체가 틀렸다는 걸 잡은 것. 수치는 맞는데 재는 대상이 틀린 경우다.

## 아쉬운 점 · 리스크

- 의도가 메모리에만 있다. 메모리는 이 에이전트만 읽는다. 피그마 컴포넌트 description이나 계약 문서에 옮겨야 다른 사람도 본다.
- 첨부 칩 틴트 10%가 토큰이 아니라 Tailwind 클래스 문자열로 박혀 있다. 브랜드 값이 바뀌어도 안 따라온다.
- 입력바 홈 문구 22곳은 아직 안 정했다.

## 한 줄 평

감사가 찾아오는 「이상한 자리」의 절반은 의도다. 고치기 전에 왜 그렇게 됐는지부터 묻는다.

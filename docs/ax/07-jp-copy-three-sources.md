# 07. JP 문구 검수 — 정본이 세 군데로 갈려 있었다

상태: ✅ 1차 완료 · 기간: 2026-09-02 ~ 09-08

## 문제 정의 / 도입 배경

일본 출시가 확정이고 한국어는 개발 편의다. JP 문구를 검수하려고 화면을 열었더니 같은 문구가 화면 텍스트, Figma 변수, 기획 시트 세 군데에서 서로 달랐다. 어느 것이 맞는지 디자인이 정할 수 없는데, 화면은 그중 하나를 이미 보여 주고 있었다.

## 목표

- [x] 세 군데가 어떻게 다른지 전수로 센다
- [x] 언어 스위치가 걸리는 컬렉션을 정리한다
- [x] 어느 것이 정본인지는 기획이 정하게 넘긴다
- [ ] 남은 구조적 컬렉션 넷(주미님 판단 대기)

## 사용한 툴

- Claude Code · Figma MCP · Figma 변수 컬렉션(strings · strings-demo · typography)

## 작업 과정

### 1단계. 「넘침 0건」이 오판이었다

- 처음 감사에서 JP 넘침이 0건으로 나왔다. KR 렌더로 폭을 판정한 것이었다. 줄바꿈 문구를 뺀 집계이기도 했다.
- 페이지에 언어 모드를 상시로 걸고 다시 재니 Deep CTA 다섯이 두 줄로 넘쳤다.

### 2단계. 언어 컬렉션이 일곱이었다

- 언어 스위치가 걸리는 컬렉션을 세니 일곱이었다. 잔재 셋(로컬 typography · 옛 키 typography · 로컬 strings)에 물린 120곳을 되묶어 0으로 만들었다.
- 남은 넷은 구조라 디자인이 임의로 합칠 수 없다. 주미님 판단으로 넘겼다.
- 세그먼트를 되묶으면 노드 배열에 옛 alias가 남는다. 되읽어야 보인다.

### 3단계. DS에 문구가 다 있는데 컴포넌트가 덜 물고 있었다

- DS에 strings 75개가 JP까지 다 차 있었는데 컴포넌트는 60개만 물고 있었다.
- 디자인 문구 변수는 DS `strings-demo`에 둔다. 제품 파일에 로컬 문구 컬렉션을 만들지 않는다. 「항상 그렇게 해 줘」로 굳었다.

### 4단계. 정본은 기획이 정한다

```
strings는 기획이 관리하니까 신설·정정 제안은 하지 마.
```

- 디자인은 세 군데가 다르다는 사실과 수치만 보여 줬다. 어느 것이 정본인지는 기획이 정한다.

## 트러블슈팅

**문제 1**: 언어를 `characters`로 판정했더니 KR로 나왔다
- 원인: `characters`는 모드 해석 전 저장값이다. 원격 컬렉션 모드는 프레임에 명시해야 한다.
- 해결: 페이지에 언어 모드를 걸고 렌더로 판정한다.

**문제 2**: DS에서 변수를 걸어도 화면 문구가 안 바뀐다
- 원인: 인스턴스가 override한 문구에는 라이브러리 변수가 안 내려간다. 게시·수락 문제가 아니다.
- 해결: 진척은 화면에 남은 한국어 개수로 센다. override 자리는 제품 파일에서 직접 건다.

## 결과

- 잔재 컬렉션 셋 120곳 되묶음 → 0. 남은 넷은 판단 대기.
- Deep CTA 다섯의 두 줄 넘침을 실측으로 잡았다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 일곱 컬렉션을 세고 120곳을 되묶은 것. 화면 남은 한국어를 진척 지표로 바꾼 것.
- 디자이너: 「어느 것이 정본인지는 기획이 정한다」 선을 그은 것. 컬렉션 구조 넷은 합치지 않고 판단으로 남긴 것.

## 아쉬운 점 · 리스크

- 정본이 세 군데인 채로 출시가 가까워진다. 디자인이 정할 수 없는 자리라 대기 시간이 리스크다.

## 공유할 만한 사항

```
JP 문구는 페이지에 언어 모드를 걸고 재줘. KR 렌더로 폭을 판정하면 뒤집혀.
```

## 한 줄 평

「0건」은 없는 게 아니라 안 본 것이었다. 언어를 걸고 다시 재야 보인다.

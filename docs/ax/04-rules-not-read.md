# 04. rule 문서를 안 읽던 이유와 색인표

상태: ✅ 완료 · 기간: 2026-08-25 ~ 2026-09-08

## 문제 정의 / 도입 배경

사고가 날 때마다 규칙을 한 줄씩 적었다. 두 달 만에 51개 879줄이 됐다. 그런데 규칙이 있는데도 같은 실수가 반복됐다. 게시와 수락을 가르는 43번은 본문이 있었는데도 열흘간 같은 오판이 났다.

「규칙을 왜 안 읽나」가 아니라 「규칙이 왜 안 읽히나」가 문제였다.

## 목표

- [x] 안 읽히는 원인을 가른다
- [x] 규칙 본문과 별도로 걸리는 장치를 만든다
- [x] 규칙이 늘어도 감당되는 구조를 잡는다

## 사용한 툴

- Claude Code · 프리즘 레포 `AGENTS.md` · `design-system/rules.md` · Claude Code 훅

## 작업 과정

### 1단계. 통독도 검색도 안 된다

- 879줄은 세션마다 통독시킬 수 없다.
- grep은 찾을 단어를 이미 알 때만 걸린다. 문제를 「새 레이아웃 설계」로 잡으면 「컴포넌트 재사용」 규칙을 찾을 이유가 없다.
- 43번은 제목과 무관한 규칙의 하위 불릿에 묻혀 있었다. 제목으로는 절대 안 걸린다.

### 2단계. 색인표 (8/25)

`AGENTS.md`에 「이럴 때 → 볼 것」 표를 넣었다. 규칙 본문이 아니라 색인이다.

| 이럴 때 | 볼 것 |
| --- | --- |
| 뭔가 새로 만들려 할 때 | 41 이미 있나 |
| variant를 갈거나 스왑할 때 | 42 override가 흘러나간다 |
| 게시·전파를 판정할 때 | 43 |
| 수락했는데도 안 바뀔 때 | 43-2 프록시 세트 |
| 감사 결과가 「0개」로 나올 때 | 44-5-2 0은 검산할 대상이 없다 |
| 인스턴스 크기를 바꾸려 할 때 | 36 크기 override는 무시된다 |

「규칙을 새로 추가할 때는 번호부터 다시 잰다」도 같이 적었다. 뽑아 주는 스크립트가 없고 겹쳐도 git이 안 잡아 준다.

### 3단계. 규칙이 두 번 안 지켜지면 훅으로 (9/8)

- `git add -A` 금지는 규칙으로 두 번 어겼다. 실행 직전에 막는 훅으로 옮겼다.
- 「0건이면 범위를 적어라」는 훅이 상기시킨다.
- 커밋 전 문서 형식과 체인지셋 검사는 pre-commit이 한다.

### 4단계. 열린 항목 정리

- 같은 항목이 여러 문서에 열려 있었다. 라임 재퍼블리시가 두 문서에 세 번, 「패널 EdgeBand 부재」가 두 문서에 두 번.
- 8/27에 여섯 문서를 재측해 열린 항목을 260에서 224로 줄였다. 실측으로 닫은 15건이 전부 「A 때문에 대기」였고 A는 이미 사라져 있었다.
- 체크박스 규칙을 세웠다. `- [ ]`는 「누가 손대면 닫히는 일」에만. 발견·결론·교훈·조건부는 평문. 하루에 세 문서 54건을 이 기준으로 정리했다.

## 트러블슈팅

**문제 1**: 규칙 본문이 있는데 안 걸린다
- 원인: 제목·검색·통독 셋 다 안 된다.
- 해결: 상황별 색인. 규칙 번호만 알아두고 필요할 때 연다.

**문제 2**: 규칙이 있는데 어긴다
- 원인: 규칙은 읽는 사람이 지킨다. 안 읽으면 없는 것과 같다.
- 해결: 실행 자리에 훅. 규칙이 두 번 안 지켜지면 훅으로 옮긴다.

**문제 3**: 열린 항목이 부풀어 무엇이 남았는지 안 보인다
- 원인: 발견까지 체크박스로 적고, 「A 때문에 대기」를 A가 사라져도 아무도 안 닫는다.
- 해결: 체크박스 규칙 + 주기적 재측 + 대기 사유엔 「무엇이 어떻게 되면 풀리는지」를 같이 적는다.

## 결과

- 규칙 51개는 그대로인데, 세션이 규칙을 찾는 경로가 「제목」에서 「상황」으로 바뀌었다.
- 훅 넷이 규칙 넷을 대신한다. 세션 브리핑 · 공유 폴더 보호 · 0건 규칙 · 커밋 전 검사.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 열린 항목 260건을 사유별로 재측한 것. 훅을 쓴 것.
- 디자이너: 「규칙이 있는데 왜 또 났나」를 계속 물은 것. 「검수 부담은 줄지 않고 새로 생긴다」고 반박한 것.

## 아쉬운 점 · 리스크

- 규칙은 사고마다 늘고 스스로 줄지 않는다. 색인표도 자란다. 정리 비용이 계속 붙는다.
- 규칙과 훅은 재발만 막는다. 신종 오류의 첫 발견은 매번 사람이 한다.

## 공유할 만한 사항

- 규칙 문서에는 처음부터 번호와 「이럴 때 본다」 한 줄을 붙인다.
- 규칙이 두 번 안 지켜지면 규칙을 더 적지 말고 훅으로 옮긴다.
- `- [ ]`는 누가 손대면 닫히는 일에만.

## 한 줄 평

규칙은 적는 것보다 걸리게 하는 게 일이다. 안 걸리면 없는 것과 같다.

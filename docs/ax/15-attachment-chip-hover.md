# 15. 첨부 칩 hover — 진해 보여도 유지하기로 한 결정

상태: ✅ 완료 · 기간: 2026-09-08

## 문제 정의 / 도입 배경

채팅 입력바의 첨부 칩이 hover에서 너무 진해 보인다는 지적이 있었다. 선 색이 문제인 것 같았는데, 재 보니 선이 아니었다.

## 목표

- [x] 진해 보이는 원인을 가른다
- [x] 대안을 나란히 놓고 고른다
- [x] 결정을 기록한다

## 사용한 툴

- Claude Code · 스토리북 · CDP 렌더 대조

## 작업 과정

- 원인은 선 색보다 배경 틴트 10%였다. 토큰이 아니라 클래스에 박혀 있었다.
- 두께 1px은 배율 스냅이지 결함이 아니다. 축소한 렌더로 색을 판정하면 안티에일리어싱이 밝은 쪽으로 밀어 오판한다. 원본 해상도로 받아 픽셀을 셌다.
- 대안 컷(틴트 낮춤 · 선만 · 둘 다)을 나란히 놓고 봤다. 결정은 「진해 보여도 유지」. hover가 눈에 띄는 게 첨부 칩의 역할이라서다.
- 다시 열면 다크부터 본다.

## 트러블슈팅

**문제**: 선을 inset box-shadow로 그린 컴포넌트는 borderColor가 거짓말한다
- 원인: border-0이라 color가 상속돼 잡힌다. 투명 요소는 backgroundColor에 rgba(0,0,0,0.1)로 섞인다.
- 해결: 선은 boxShadow로 읽는다. 측정 코드가 무엇을 읽는지 먼저 본다.

## 결과

- 유지. 원인(틴트 10%, 클래스에 박힘)과 대안 컷을 결정 옆에 남겼다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 선 색이 아니라 틴트가 원인임을 픽셀로 잰 것. 대안 셋을 나란히 띄운 것.
- 디자이너: 「진해 보여도 유지」를 고른 것. 첨부 칩이 눈에 띄어야 하는 이유를 안 것.

## 아쉬운 점 · 리스크

- 틴트가 토큰이 아니라 클래스에 박혀 있어서 브랜드 값이 바뀌어도 안 따라온다.

## 한 줄 평

「진하다」는 지적이 왔을 때 선부터 의심하면 틀린다. 무엇이 진한지 픽셀로 먼저 잰다.

# 03. 발행이 빠져서 몇 번을 돌려도 같은 결과가 안 나오던 구조

상태: ✅ 완료 · 기간: 2026-08

## 문제 정의 / 도입 배경

디자인 시스템 파일에서 마스터를 고치고, 제품 파일에서 감사를 돌리면 값이 옛것이었다. 다시 돌려도 같았다. 에이전트는 「반영됐다」고 하고, 화면은 안 바뀌어 있었다. 열흘 가까이 같은 오판이 반복됐다.

## 목표

- [x] 왜 안 내려오는지 원인을 가른다
- [x] 게시 여부를 상태값이 아니라 실물로 재는 방법을 만든다
- [x] 루프에 「게시」를 명시한다

## 사용한 툴

- Claude Code · Figma MCP(use_figma) · Figma REST

## 작업 과정

### 1단계. 게시와 수락이 다르다는 것

- 변수는 게시하면 수락 없이 자동 전파된다.
- 컴포넌트 구조는 제품 파일에서 수락해야 내려온다.
- 「퍼블리시 필요」를 컴포넌트 기준으로 읽으면 변수 쪽을 오판하고, 반대로 읽으면 구조 쪽을 오판한다.

### 2단계. 게시 대기 목록은 대부분 허수였다

```
주미님이 「게시할 게 없다는데?」
```

- 라이브러리 상태값(`getPublishStatusAsync`)이 `CHANGED`여도 이미 내려와 있는 경우가 많았다. 14개가 떠 있어도 실제 차이는 둘이었다.
- 세트 안 variant는 게시해도 늘 `UNPUBLISHED`로 나온다. 세트 키로만 잰다.
- boundVariables 배열 순서는 파일마다 달라 이름으로 정규화해야 오탐이 안 난다.
- 게시가 실제로 나갔는지는 REST `updated_at`으로 본다. 같은 항목만 계속 남으면 게시 창의 체크가 꺼진 것이다.

### 3단계. 수락도 만능이 아니었다

- 수락했는데도 안 바뀌는 경우가 있었다. 제품 파일에 프록시 세트가 여러 벌 살아 있어서다. 이때만 `swapComponent`가 정공법이다. 중첩 인스턴스는 층마다 세대가 다르다.
- 그래서 규칙이 「게시·수락을 부탁하지 말고 직접 넣는다」가 됐다. 값 변경이면 이미 놓인 인스턴스에 직접 넣는다. 구조 변경이라 게시가 꼭 필요하면 「이 게시가 막아 주는 것」 한 줄과 소비 파일에서 키를 임포트해 본 결과를 같이 올린다.

## 트러블슈팅

**문제 1**: 규칙 43번이 있었는데 열흘간 같은 오판
- 원인: 본문이 제목과 무관한 규칙의 하위 불릿에 묻혀 있었다. 검색은 찾을 단어를 이미 알 때만 걸린다.
- 해결: 색인표에 「게시·전파를 판정할 때 → 43」, 「수락했는데도 안 바뀔 때 → 43-2」, 「게시할 게 없다는데 → 43-1」로 상황별 줄을 넣었다.

**문제 2**: DS에서 변수를 걸었는데 제품 화면 문구가 안 바뀐다
- 원인: 게시 문제가 아니었다. 인스턴스가 override한 문구엔 라이브러리 변수가 안 내려간다. 값이 같아 보여도 타이핑한 자리는 override다.
- 해결: 진척은 「DS에서 몇 개 걸었나」가 아니라 화면에 남은 미바인딩 개수로 센다. override된 자리는 제품 파일에서 변수를 임포트해 직접 건다.

## 결과

- 루프 그림이 「Figma 승인 → 게시 → Git 언어화 → Package → Storybook → Worklog」가 됐다. 「게시」가 따로 그려졌다.
- 게시 판정은 제품 파일 인스턴스가 무엇을 물고 있는지로 한다. 상태값은 안 믿는다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 게시본 지문과 소비 파일 인스턴스를 대조해 허수를 걸러낸 것. REST로 실제 게시 시각을 잰 것.
- 디자이너: 「게시할 게 없다는데?」라고 되물어 상태값을 못 믿게 만든 것. 「게시를 부탁하지 말고 직접 넣어라」로 흐름을 바꾼 것.

## 아쉬운 점 · 리스크

- 프록시 세트가 여러 벌인 파일은 `swapComponent`가 답인데, 이건 우회다. 파일이 왜 그렇게 됐는지는 못 고쳤다.
- 「어느 변수를 무는지」를 바꾼 것은 자동 전파가 아니다. 마스터만 새 변수를 물고 인스턴스는 옛 변수를 문다. 이 경우는 여전히 손이 간다.

## 공유할 만한 사항

```
마스터를 고친 뒤 게시·수락을 나한테 부탁하지 마. 값 변경이면 이미 놓인 인스턴스에 직접 넣어줘.
게시가 됐는지는 상태값 말고 제품 파일 인스턴스가 무엇을 물고 있는지로 재줘.
```

## 한 줄 평

같은 작업을 몇 번 돌려도 결과가 다르면 코드가 아니라 사이에 빠진 단계를 의심한다. 여기서는 게시였다.

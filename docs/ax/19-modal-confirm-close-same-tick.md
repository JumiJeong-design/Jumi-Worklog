# 19. ModalDialog는 확인 뒤 onClose를 같은 틱에 부른다

상태: ✅ 완료 · 기간: 2026-09

## 문제 정의 / 도입 배경

확인 버튼을 누르면 「처리 중」 상태가 떠야 하는데 통째로 사라졌다. 타입체크도 테스트도 통과했다.

## 목표

- [x] 왜 「처리 중」이 안 보이는지 원인을 찾는다
- [x] 어느 게이트가 못 잡는지 확인한다

## 사용한 툴

- Claude Code · 렌더 검산 · jsdom 테스트

## 작업 과정

- onConfirm에서 올린 state를 같은 틱에 불리는 onClose가 못 본다. 스테일 클로저다.
- 대기 여부는 오버레이 값에 담는다. 부모 state에 의존하지 않는다.
- 타입체크와 테스트는 못 잡고 렌더만 잡는다. 비슷한 경우가 하나 더 있다. 위치를 쥔 요소에 CSS `scale`을 같이 걸면 개별 변환 속성이라 translate까지 배율이 걸리는데, jsdom 게이트는 못 잡는다. scale은 자식으로.

## 트러블슈팅

**문제**: 게이트를 다 통과한 결함
- 원인: 게이트가 보는 것(타입·단위 동작)과 결함이 있는 자리(틱 순서·렌더)가 다르다.
- 해결: 「됐다」는 렌더로 잰 뒤에만. 계약 수치는 렌더에서 다시 잰다.

## 결과

- 오버레이 값으로 대기 여부를 담았다. 「렌더만 잡는 결함」 유형을 메모리에 남겼다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 틱 순서를 재현해 원인을 찾은 것.
- 디자이너: 「처리 중이 안 보인다」를 화면에서 본 것.

## 한 줄 평

게이트가 통과했다는 건 게이트가 본 것만 통과했다는 뜻이다. 렌더는 따로 본다.

# 11. 피그마 감사 함정 — 「0개」는 없는 게 아니라 안 본 것

상태: ✅ 1차 완료 · 기간: 2026-08 ~ 09

## 문제 정의 / 도입 배경

피그마 전수 감사를 에이전트에게 시키면 「0건」이 자주 나왔다. 그중 상당수가 실제로 없는 게 아니라 범위를 잘못 잡았거나 판정 코드가 틀린 것이었다. 78건을 통째로 빠뜨린 사고가 있었다.

## 목표

- [x] 0건이 나오는 원인을 유형별로 가른다
- [x] 감사 보고 형식을 고정한다
- [x] 규칙과 훅으로 상기시킨다

## 사용한 툴

- Claude Code · Figma MCP(use_figma) · Figma REST

## 작업 과정

### 원인 유형

- **범위**: 페이지를 범위 경계로 삼으면 옆 페이지가 빠진다. 같은 컴포넌트는 여러 페이지에 놓인다. SECTION은 보드가 아닌데 폭으로 거르면 섹션 안 화면이 통째로 사라진다.
- **판정 코드**: `boundVariables.fills`는 페인트 인덱스가 아니라 압축 인덱스다. `figma.getVariableByIdAsync`는 없는 API라 try/catch로 감싸면 전수가 미바인딩으로 나온다. `skipInvisibleInstanceChildren` 기본값이 틀렸다고 가정한다.
- **이름으로 세기**: 인스턴스 이름으로 세면 개명된 67개가 빠진다(48 vs 115). 반대로 이름으로 대상을 세면 안 그려지는 노드가 딸려 온다(track 89곳이 숨은 원). `/icon/i`가 `Icon=false`에 걸려 134건 오탐.
- **동명 슬롯**: 같은 이름 노드가 둘이면 `findAll[0]`이 숨은 쪽을 잡는다. 「안 내려왔다」 224건 오판.
- **strokeWeight**: 네 변 키로 쪼개지고 mixed 심볼이라 `??` 체인이 밑줄형 2.0을 놓친다. 선 페인트가 없어도 값은 남아 있어 335건이 대상으로 보이지만 실제 0건.

### 보고 형식

- 표 위에 스캔 방법 한 줄. 어디를 봤는지, 뺀 것과 개수, `skipInvisibleInstanceChildren` 값.
- 대조군을 먼저. 바인딩된 걸 확실히 아는 노드 몇 개가 「바인딩됨」으로 잡히는지.
- 전부 0이거나 전부 같은 값이면 결과가 아니라 코드 오류로 보고 멈춘다.

## 트러블슈팅

**문제**: 데이터가 멀쩡해도 화면이 틀렸다
- 원인: 인스턴스 복제나 variant 전환 뒤 렌더가 옛 값이다.
- 해결: 렌더를 한 장 더. 직접 쓴 노드를 대조군으로 함께 찍는다.

## 결과

- 「0건이면 범위를 적어라」가 규칙 44-5-2와 훅(zero-result-rule)이 됐다. 문구에도 박혔다.

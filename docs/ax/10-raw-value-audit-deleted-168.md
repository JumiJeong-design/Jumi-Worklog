# 10. 원시값 감사가 손보정을 결함으로 읽고 168곳을 지웠다

상태: ✅ 완료 · 기간: 2026-09

## 문제 정의 / 도입 배경

비활성 입력창 안내문구 색이 피그마와 코드에서 달랐다. 코드는 `disabled/fg`, 피그마는 `text-tertiary`. 감사는 피그마 쪽을 정답으로 잡고 코드가 틀렸다고 했다. 실제로는 코드가 원래 맞았고 피그마가 어긋나 있었다.

## 목표

- [x] 어느 쪽이 맞는지 실물로 가른다
- [x] 왜 피그마가 어긋났는지 원인을 찾는다
- [x] 되돌린다

## 사용한 툴

- Claude Code · Figma MCP · 렌더 대조

## 작업 과정

### 1단계. 값이 아니라 결과를 봤다

- `text-tertiary`를 쓰면 비활성 필드에서 안내문구만 가장 진해진다. 비활성인데 안내문구가 튄다. 이건 틀린 것이다.
- 코드의 `disabled/fg`가 맞았다.

### 2단계. 왜 피그마가 어긋났나

- 앞선 원시값 감사가 손보정을 결함으로 읽고 지웠다. 168곳. 「토큰 안 쓴 자리」를 전부 결함으로 세면 의도된 예외까지 지워진다.

### 3단계. 되돌리고 규칙을 세웠다

- opacity가 1보다 작거나 마스터와 일부러 다르게 둔 자리는 「의도 확인」 표로 따로 뺀다. 고치지 않는다.
- 안 쓴 케이스가 컴포넌트면 같은 variant를 쓰는 마스터 전체 분포를 재서 어느 쪽이 표준인지 본다. 마스터 쪽이 소수파면 마스터를 고친다.

## 트러블슈팅

**문제**: 감사 결과 count만 보고 일괄 수정했다
- 원인: false positive를 먼저 안 걸렀다.
- 해결: count만 보고 일괄 수정하지 않는다. Button·icon strokeWeight·Text Field처럼 민감 항목은 승인 범위를 다시 확인한다.

## 결과

- 168곳 복구. 「마스터가 늘 맞출 대상은 아니다」가 규칙이 됐다.

## AI가 잘한 것 / 디자이너가 보정한 것

- AI: 168곳을 세고 되돌린 것. 분포로 표준을 가른 것.
- 디자이너: 「비활성인데 안내문구가 튄다」를 화면에서 본 것.

## 아쉬운 점 · 리스크

- 감사는 현상을 재지 의도를 못 잰다. 의도는 사람이 표시해 둬야 한다.

## 공유할 만한 사항

```
opacity가 1보다 작거나 마스터와 일부러 다르게 둔 것 같은 자리는 고치지 말고 「의도 확인」 표로 따로 빼줘.
```
